# v0.9 — what is not done

Web search landed: the `SearchProvider` trait with Brave behind it, the
DPAPI-wrapped key and its Settings page, parallel page reads over WinHTTP,
Readability-style extraction, synthesis through whichever Agent `!c` would have
asked, the answer streaming inline with a numbered source list, Enter opening the
query in the default browser, and the warm outbound state. What follows is
outstanding, with the phase that owns each.

---

## 1. No verification against a real key — **v0.9, before the phase is claimed**

Every layer below the network is tested and green, and
`cargo test --test web_search -- --ignored` proves WinHTTP reaches the live
internet, reads real pages and survives a host that does not resolve. What has
never run is a search: this machine holds no Brave key, so
`v0_9_a_real_search_returns_coherent_hits` skips itself and prints why.

Until a key is pasted into Settings → Web search and `docs/verify/v0.9.md` is run,
the claim "`!s` answers a question" rests on fixtures. The exit criterion is not
met and the phase is not finished — this is the one item that blocks it.

## 2. There is no debounce, because there is nothing to debounce — **v1.0**

The plan's trap ("typing `!s ferrari` must not fire six queries") was answered by
never firing on a keystroke at all: the request happens on Enter. That is
stronger than a debounce and it is why no timer exists.

It stops being enough the day `!s` gains a preview — an inline first result, or
suggestions — because both mean requests while typing. Whoever builds that owns
the debounce, and the free tier's per-second limit is the number to design to.

## 3. A JavaScript-only page yields nothing, and says so only in the prompt — **post-v1**

`extract::readable` returns `None` below 200 characters of prose, which is what a
page that draws itself in JavaScript looks like. The source stays in the prompt
with its provider snippet and a note that the page could not be read, so the
answer is thinner rather than wrong, and the source list still shows the row.

What the user does not see is *which* sources were readable. The headless
fallback is deferred (`docs/plans/post-v1.md`); marking an unread source in the
list is smaller and would fit v1.0.

## 4. The answer's citations are numbers, not links — **v1.0**

The prompt asks for `[1]`, `[2]` and the numbers match the source list, which is
what makes them checkable. They are still plain text: clicking `[1]` inside the
answer does nothing, and only the list below opens anything.

Turning them into links means parsing the Agent's prose, which is exactly what
numbering was chosen to avoid doing on the Rust side. A renderer that linkifies
`\[(\d+)\]` against the known source count is contained and safe, and belongs
with whatever else makes the answer richer.

## 5. Cancelling does not stop a fetch in flight — **v1.0**

`web_cancel` sets a flag checked between steps, so a search stops before it reads
pages and before it starts a Turn. A `WinHttpSendRequest` already waiting runs to
its own six-second timeout, because cancelling one means keeping every handle
addressable from another thread and closing it underneath the reader.

The cost is bounded and invisible: the Palette has already moved on, and the
thread ends by itself. It matters the day the timeout is raised.

## 6. One provider, and the second one is a preference — **post-v1**

`SearchProvider` exists, `provider()` returns Brave by name, and TBC-0004 owns
which alternative comes next. A second provider needs a Settings choice, a second
key in `creds\`, and a decision about what happens when the chosen one has no
key. None of that is built and none of it is needed yet.

## 7. A version bump slips under the screenshot budget — **v1.0**

`maxDiffPixels: 150` is what v0.8 tightened to after a ratio let two whole
sidebar rows through. A version number changing from `0.8.0` to `0.9.0` is about
thirty pixels, which is under it by design — the guard for that is the About
test's exact assertion against `package.json`, added at the same time, and it
does its job.

The consequence is that `settings-about.png` has to be regenerated by hand on
every bump or it drifts silently again. `bun run bump` should do it: one
`playwright test -g "About names the version" --update-snapshots=all` at the end
of the script, which is three lines and was out of scope here.

## 8. `!s` is not in the `!` picker, because there is no picker — **v1.0**

Four Bangs now exist and the registry is still parked
(`docs/plans/bang-registry.md`). `!s` was added the way `!c` was: a constant in
`bang.rs` and a match arm. The picker, user-defined Bangs and the four open
questions at the end of that file are unchanged by this phase.

## 9. Page content reaches an Agent, and that is prompt injection by design — **v1.0**

`!s` reads pages off the open web and puts their text in a prompt. Anything on
one of those pages is free to address the Agent directly, and the honest
statement is that nothing prevents it.

What bounds it is the Turn, not the text. The synthesis Turn runs with **tools
off** in the **Scratch directory**, which is empty, so an instruction the Agent
obeys has nothing to act on: no file to write, no command to run, no session to
carry it into. The worst case is a wrong or manipulated answer, shown with the
sources it came from, which the user can open.

Three smaller edges are closed rather than accepted. Titles and snippets are
stripped of control and bidirectional characters, so a row cannot draw itself
reversed and name a site it did not come from. Source URLs are re-checked in
Rust and only http(s) is opened, so a result cannot hand the shell a `file:` or
a custom scheme. And a query that could read as a browser flag is never passed
as a command-line argument (Chromium's `--gpu-launcher` starts a process); it
goes through a URL instead.

What is left for v1.0 is telling the user *which* claim came from where, beyond
the numbered list: an answer sentence that cites nothing is currently
indistinguishable from one that cites source 3.
