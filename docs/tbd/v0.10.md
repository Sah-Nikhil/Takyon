# v0.10 — what is not done

What the Appearance phase left undone, and which phase owns it. See
[`README.md`](./README.md) for what this directory is: `adr/` says why it is
built this way, `tbc/` says which of those calls we expect to revisit, this says
what is not done.

---

## 1. There is no theme editor, and no theme import — **post-v1**

The ask was a set of good themes, not a colour picker, and ADR-0023 shaped
`ThemeHalf` as seven roles so that an import stays cheap: a
`.takyon-theme.json` carrying seven values per half, validated in the renderer,
stored by id like any built-in.

What it needs beyond that is the part nobody sees: a reserved-id set so an
import cannot shadow a built-in, and a decision about what happens to a stored
id whose file has been deleted. t3code's `RESERVED_THEME_IDS` is the shape of the
first; the second is why this is not a Saturday afternoon.

---

## 2. The foreground opacity ladder is still ad hoc — **v0.11**

v0.10 lifted the whole ladder to clear 4.5:1 on a light plate (nothing text-
bearing now sits below `text-fg/46`, and the remap was order-preserving so no
hierarchy inverted). It did **not** fix the underlying problem: there are
seventeen distinct alpha steps across the app, chosen one call site at a time.

The right shape is four named steps as tokens — primary, secondary, muted,
faint — and about a hundred class changes. Deferred because it is a large
mechanical diff with real regression surface, and it was not what made light mode
unusable.

---

## 3. The Windows-key hook has never been driven by hand — **v0.10, blocking its own exit**

`docs/verify/v0.10.md` §6 is written and unrun. Everything about ADR-0024's
mechanism is reasoned rather than observed:

- that injecting `0xE8` on the down-stroke actually suppresses Start on this
  build of Windows;
- that `Win+R`, `Win+E` and `Win+L` still work with the hook armed;
- that turning the switch off restores Start on the **first** tap, not the second;
- that the hook is re-armed after a restart rather than reporting success against
  nothing.

There is no automated substitute. A low-level keyboard hook cannot be driven by
Playwright, and `MockRuntime` has no message queue to install one on.

---

## 4. The hook does not survive an elevated foreground window — **v1.0**

Same limitation `Alt+Space` already has, and the same cause: the UIAccess
helper's certificate is v0.1's outstanding item and a v1.0 blocker
(`docs/plans/uiaccess-signing.md`). The switch's description says so. It is
listed here because the Windows key is the binding people will most expect to
work everywhere, so it will be reported as a v0.10 bug rather than as a v0.1 one.

---

## 5. Nothing reports a hook that Windows dropped mid-session — **v0.11**

`LowLevelHooksTimeout` unhooks a slow callback silently. `superkey::armed()`
reports what this process last did, not what Windows currently holds, so a
dropped hook reads as armed until something re-checks.

The honest fix is cheap and was not built: keep the hook thread alive after
`UnhookWindowsHookEx` returns unexpectedly and re-install once, then surface a
warning on the Keyboard page if that also fails. What is built instead is a
callback small enough that it should never happen — which is a reason to expect
it not to, not a reason to be unable to see it.

---

## 6. File Search: five switches in the reference that Takyon does not have

The page was rebuilt to the reference's shape and only the controls that map to
real behaviour ship. Each of these is a feature, not a setting, and a disabled
row for an unbuilt one would be a dead control in the one window whose whole
point is that none of them are:

- **Content search** — reading file contents. An index format change. **post-v1**.
- **Glob ignore patterns and `.gitignore` awareness** — today `files.excludes`
  matches one whole folder name (`index::roots::is_excluded`). Globs are a walker
  change plus a stored-format migration. **v0.11**.
- **Include hidden files** — walker behaviour. **v0.11**.
- **Keep files from removed volumes** — store behaviour, and the interesting half
  is deciding what a stale entry for an unplugged drive should *do* when
  activated. **v0.11**.
- **Enforce low disk space block** — needs an index size estimate, which nothing
  currently computes. **post-v1**.

---

## 7. Expanded mode has no keyboard affordance for its groups — **v0.11**

Arrow keys walk every Entry in order and skip the headings, which is correct.
There is no way to jump *between* groups, which is the thing a grouped list makes
you want. Raycast has none either, so this is a gap rather than a regression.

---

## 8. The suggestions list is Frecency only — **v0.11**

Expanded's first view is `Frecency::top`, resolved back through the Sources.
Two things it is not:

- **Not pinnable.** Raycast has favourites; Takyon has nothing that says "this
  one, always". Frecency answers it eventually, which is not the same as
  answering it now.
- **Not seeded.** A fresh install has an empty `usage` table, so the first view is
  empty until something has been launched — the one moment a suggestions list
  would help most. First-run experience is a v1.0 item and this belongs with it.

---

## 9. `window_mode` is not in the bench harness — **v0.11**

`bun run bench` measures the four budgets against a Compact Palette, which is the
default and therefore the right thing to measure. Expanded paints a 520px window
on every summon instead of a 68px one, and nobody has measured what that does to
"hotkey → first pixel". It should be a second bench row, not an assumption.
