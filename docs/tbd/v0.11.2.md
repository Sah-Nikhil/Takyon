# v0.11.2 — to be done

What the Agent fallback and the faster `!s` left behind, and who owns each item.
The decisions themselves are in ADR-0041.

## 1. opencode before v2 is no longer driven — **nothing, unless reported**

v0.11.2 moved opencode off `--dir` and `--variant`, because v2.4.1 refuses both
with `Unrecognized flag`. It now runs in the process cwd and puts the variant on
`-m provider/model#variant`. A pre-v2 opencode would ignore the `#variant`
suffix, or reject it. Nobody here runs one, so it stays unhandled until someone
reports it. An effort locked with no model is not sent at all, because a variant
has nothing to attach to without a model.

## 2. No real usage limit has been hit — **v0.11.2, before the phase is claimed**

The handover was proven live with a refused model. Claude Code reported it as a
`<synthetic>` assistant message followed by an error `result`, and Codex
answered after it. A real five-hour limit should take the same path, because
t3code reads the same synthetic line for limits. That is still reasoning, not a
run. `docs/verify/v0.11.2.md` §A is the script.

## 3. Codex has no reset time — **post-v1**

`codex exec --json` reports a limit as prose in an `error` event, with no
structured reset field. Codex is benched for the flat ten minutes. t3code gets
its reset from Codex's app-server protocol, which is v0.15's live two-way
process, not `exec`.

## 4. A follow-up never falls back — **v0.15**

A resumed session belongs to one Agent, so a follow-up to an Agent that has
since run out of usage fails with that Agent's reason. Handing the transcript to
the next Agent as a fresh prompt is possible, but it belongs with v0.15's
conversation model, not here.

## 5. A fast `!s` default is not checked before use — **nothing**

`haiku`, `gpt-6-luna` and `opencode/big-pickle` all answered here. A CLI that
lacks its default fails the `!s` Turn, the fallback walks on, and that Agent is
benched. Settings → Agents lets the user pick a model it does have. Checking
first would cost a model listing on every `!s`.

## 6. opencode's own default model fails here — **nothing in Takyon**

Found driving the release build. With no `!c` model locked, opencode uses its
own default, which on this machine is a Google model whose key returns
`401 API key not valid`. Takyon passes no model in that case, so the fix is
outside it: lock a working model for opencode in Settings → Agents, or repair
the key in opencode. The fallback already covers it, by handing over to the next
Agent.
