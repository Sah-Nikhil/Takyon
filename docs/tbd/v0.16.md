# v0.16 — to be done

What Focus left behind, and who owns it. The build is complete against the
plan's task list; this is everything a careful reader would otherwise assume
was done.

## 1. The verify script has never been run — **v0.16**

`docs/verify/v0.16.md` was written before the build and has not been driven
against a release build. Everything below that names a section of it is a
claim from code and tests, not from a run. The shutdown hurdle (§D.6), the
idle-sleep hold (§D.7), sleep and wake (§D.9), the bar's focus behaviour (§E)
and the bar's RSS (§E.5) have no automated coverage at all: each needs a real
window, a real power event or a real shutdown.

## 2. The live browser test needs an idle desktop — **CI**

`cargo test --test focus_browser -- --ignored` launches real browsers and sends
keystrokes. On a machine in use, the foreground lock stops the test raising its
own window and the run fails without proving anything about the driver. It
passed here for Chrome, Edge and Helium on a quiet run, and it was deliberately
not re-run while the desktop was in use. CI's daily `web-search` job runs it on
an idle runner; that job has not run with it yet.

Gecko is skipped there: a fresh Firefox or Zen profile opens a modal (terms,
welcome) that hides the address bar, and accepting Mozilla's terms is the
user's act, never the test's. Gecko is proven by the spike (ADR-0035) and by
`docs/verify/v0.16.md` §B on a real profile.

## 3. The enforcer polls; the plan said hook — **nothing**

The plan named `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` plus a 2 s process
poll. The build polls the foreground every 250 ms and the process table every
2 s, from one thread that also owns the power and shutdown window. A blocked app
brought to the front is quit within 250 ms instead of at once. Worth changing
only if §A of the verify script shows the gap.

## 4. Early Complete restores tabs on the next visit — **nothing**

The plan walked every browser's tab strip at session end. Takyon may not raise a
window it does not own, and switching tabs needs the browser in front, so the
walk now runs lazily: for 30 minutes after a session ends, the first time each
browser comes to the front, its `Blocked · Takyon` tabs are restored. A session
that simply expires does not need the walk at all: each block page returns
itself when its `end` passes.

## 5. Zen restores to the host, not the page — **nothing**

Zen's address bar shows the host only (`example.com`), so a page blocked in Zen
comes back to the site's home page, path lost. Chromium and Firefox show the
path and restore exactly.

## 6. The start form names fewer refusals than the plan — **v0.16 follow-up**

The plan's form listed "Can't block X: runs as administrator" and "Can't block
sites in <browser>" before the session started. The build lists only keys that
would hit Windows or Takyon itself (`protected.rs`). An elevated app is
discovered when its quit is denied, recorded as a `refused` event, and never
retried; an unsupported browser is simply never read. Both need a running-process
check at preview time.

## 7. Tray mode does not flash — **post-v1**

With the bar collapsed to the tray, a block updates nothing visible: the tray
tooltip carries the goal, not the block line, and the icon does not flash.

## 8. Edges accepted as they are — **nothing**

- `until 4:30pm` across a daylight-saving change is an hour off: the parser has
  no timezone rules by design (`duration.rs`).
- A host shown in Unicode (an IDN) never matches a `site:` key; keys are ASCII.
- A session running through a shutdown counts the powered-off time as focused;
  only sleep pauses the clock.
- Two built-in package family names (Telegram, Netflix) were written from
  memory and are unverified; their `exe:` siblings cover the same apps.
