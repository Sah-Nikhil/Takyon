# v0.16 — to be done

What Focus left behind, and who owns it. The build is complete against the
plan's task list; this is everything a careful reader would otherwise assume
was done.

## 1. The verify script has never been run — **v0.16**

`docs/verify/v0.16.md` has not been driven against a release build. It has been
driven against a dev build, on 2026-10-07, by `apps/desktop/tests/drive/focus.ts`:
50 checks pass, none fail, and 7 are skipped as unrunnable here (reboot,
Windows' shutdown screen, sleep, idle timeout, UAC, Steam, private window). It found the
early-Complete bug in §4 and the `www.` loss in §5.

Since d0.11.31 the Win32 halves are tested on real windows:
`tests/focus_power.rs` sends the hidden window `WM_POWERBROADCAST` and
`WM_QUERYENDSESSION` and reads back the shutdown reason and this thread's
execution state, and `tests/focus_bar.rs` shows a window through the bar's own
`float_quietly` and checks it neither activates nor sits in Alt+Tab. What only a
hand run proves is narrower, and none of it can be automated:

- Windows' own "preventing shutdown" screen and its Shut down anyway (§D.6).
- A real suspend and resume (§D.9), and a real idle timeout (§D.7).
- A click on the bar's WebView2 not taking focus (§E.3). Windows enforces
  `WS_EX_NOACTIVATE` below any message, and the click lands in WebView2's
  own child window, in another process.
- The bar's RSS (§E.5).

## ~~2. The live browser test needs an idle desktop~~ — closed

Closed in d0.11.31. The test now guards itself. It waits up to a minute for
20 s with no input before launching anything. It checks the input tick before
every step that types and stops if anyone else has touched the machine. It
never forces the foreground; a refused raise counts as a person being about.
It sends no key but navigate's own Enter, so the Alt tap and Ctrl+T are gone,
and the second tab comes from handing the URL to the running browser. A panic
still closes the throwaway profile (`Cleanup`). Off CI, a busy desktop is a
skip; on CI it fails. Run here on an idle desktop: Chrome, Helium and Edge
pass. It also found a real flake, a tab strip read mid-switch showing no tabs,
and the runtime's lazy restore now retries up to three walks a second apart.

Gecko is skipped there: a fresh Firefox or Zen profile opens a modal (terms,
welcome) that hides the address bar, and accepting Mozilla's terms is the
user's act, never the test's. Gecko is proven by the spike (ADR-0035) and by
`docs/verify/v0.16.md` §B on a real profile.

## 3. The enforcer polls; the plan said hook — **nothing**

The plan named `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` plus a 2 s process
poll. The build polls the foreground every 250 ms and the process table every
2 s, from one thread that also owns the power and shutdown window. A blocked app
brought to the front is quit within 250 ms instead of at once. Worth changing
only if §A of the verify script shows the gap.

## 4. Early Complete restores tabs on the next visit — **nothing**

The plan walked every browser's tab strip at session end. Takyon may not raise a
window it does not own, and switching tabs needs the browser in front, so the
walk now runs lazily: for 30 minutes after a session ends, the first time each
browser comes to the front, its `Blocked · Takyon` tabs are restored. A session
that simply expires does not need the walk at all: each block page returns
itself when its `end` passes.

Until d0.11.32 an early Complete never reached this at all. The runtime ran its
end-of-session work (lazy restore, Restore Terminated Apps) only when its own
tick saw the clock expire, and a Complete from IPC ends the session between
ticks. Found by the dev-build drive (`apps/desktop/tests/drive/focus.ts`, A.7
and B.3); the runtime now runs it on any transition from running to not.

## 5. Zen's restore is unproven on a real profile — **v0.16 follow-up**

The block page's `u` comes from the page's own document now (`Uia::page_url`),
not the address bar, so Chrome's hidden `www.` comes back exactly (d0.11.33,
found by the dev-build drive's B.3; the live test now opens a `www.` URL and
demands it back in Chrome, Helium and Edge). Firefox was probed by hand once its
terms were accepted on a throwaway profile (d0.11.34): its bar shows
`www.example.com/sub?y=2`, its documents give `https://www.example.com/sub?y=2`,
and a background tab's document is offscreen while the window is in front, so it
is ordered last. Zen is the same engine, so its host-only bar should be covered
the same way, but no Zen profile past its welcome screen has been probed.
`docs/verify/v0.16.md` §B, run in Zen, settles it.

## ~~6. The start form names fewer refusals than the plan~~ — closed

Closed in d0.11.29. `Focus::preview` now walks the process table and the
registered browsers (`HKLM` and `HKCU` `SOFTWARE\Clients\StartMenuInternet`)
and names three more refusals before the session starts: a blocked app running
as administrator, a running browser Focus cannot read, and a supported browser
running as administrator. "Elevated" is tested as "cannot be opened to
terminate" (`procs::can_quit`), which is the same integrity line UIPI draws for
UI Automation. A portable browser that never registered is still invisible to
the check. The form re-asks every 5 s while open.

## ~~7. Tray mode does not flash~~ — closed

Closed in d0.11.31. The tray tooltip reads "Focus: <goal> · <n> min left ·
blocked <app>", refreshed each whole minute, and with the bar collapsed to the
tray a block blinks the glyph three times (`tray::flash`). The line's text and
the dimmed frame are unit tested; the blink itself is §E.4.

## 8. Edges accepted as they are — **nothing**

- `until 4:30pm` across a daylight-saving change is an hour off: the parser has
  no timezone rules by design (`duration.rs`).
- A host shown in Unicode (an IDN) never matches a `site:` key; keys are ASCII.
- A session running through a shutdown counts the powered-off time as focused;
  only sleep pauses the clock.
- Netflix's built-in package family name was written from memory and is
  unverified; its site covers the same service. Telegram's matched the
  installed Store app on the dev-build drive.
