# v0.12 — to be done

What the macOS port has left behind so far, and who owns it. The phase is open,
so this file grows as rows land rather than being written at the end.

## 1. Nothing in the port has run on a Mac — **v0.12, unit 0**

Unchanged from the plan's own statement, and repeated here because it now covers
more code than it did: `tauri.macos.conf.json`, the `Info.plist`, the activation
policy call and both macOS arms of `takyon-bench` compile under
`bun run check:macos` and have never executed. `LSUIElement` in particular only
takes effect on a clean launch, so a hot-reloaded dev build cannot confirm it
either way.

## 2. The bench harness's macOS arm is unverified — **v0.12, unit 1**

The Windows arm is done and measured. `takyon-bench mem` returned byte-for-byte
what `scripts/bench-mem.ps1` returned against the same live tree — 5 processes,
93421568 bytes working set, 144232448 bytes committed. `takyon-bench input`
drove a full `bun run bench --alt-hotkey` on 2026-09-07, release build, 30 shows,
and all four budgets passed: first pixel p95 **21.9 ms** / 50, keystroke to first
Entry p95 **24.3 ms** / 30, start to hotkey **263.9 ms** / 500, idle RSS
**25.8 MB** / 150 across 7 processes, 231.9 MB committed. The first-pixel figure
sits on top of v0.1's PowerShell-measured 22.6 ms, which is the corroboration
worth having: the Rust input path measures the same span the PowerShell did.

**Read the percentile before calling a miss a regression.** `stats` takes
`s[floor(0.95 * n)]`, so at `--runs 20` the p95 *is* the maximum sample and one
outlier fails a budget on its own. A 20-run pass of the same binary reported
first Entry at p95 38.9 ms, over the 30 ms budget, purely from that. Run 30 or
more, which is the default.

The macOS arm has run nowhere. `CGEventPost` reaching a Carbon hotkey at all is
the one genuinely new mechanism in the file, and the first Mac bench answers it.

## 3. `bun run bench` cannot run while Takyon is installed and running — **fixed, but read this**

Not deferred — fixed during unit 1 — but recorded because the failure was
misleading enough to cost time. `tauri-plugin-single-instance` makes a second
Takyon hand off to the first and exit immediately, writing nothing at all to
`TAKYON_BENCH_LOG`. The harness then waited out its full 15 s deadline and
reported `timed out waiting for the hotkey to be registered`, which reads as a
hotkey bug and is not one.

`bench.ts` now checks first, via `takyon-bench pids --name takyon`, and says what
is actually wrong. `--kill-running` ends the running copy; without it the harness
refuses rather than killing a launcher the user is using.
`scripts/bench-idle.ps1` always had this guard, which is why the gap was invisible.

## 4. macOS RSS may be under-reported, and the harness will say so — **v0.12, unit 1**

On Windows the WebView2 browser, renderer and GPU processes are all descendants
of ours, so a tree walk finds them. On macOS the WKWebView helpers are XPC
services, and an XPC service is reparented to launchd — so the same walk may find
none of them and report roughly the Rust binary's footprint.

Rather than guess, `takyon-bench mem` reports `untrackedWebKitHelpers`: the count
of `com.apple.WebKit` processes on the machine that the walk did not reach. **If
that number is non-zero on the first Mac run, the macOS RSS figure is wrong** and
the walk needs a responsible-pid lookup before ADR-0003 can be amended with a
macOS number. This is the first thing to read in the first bench output.

`privateBytes` is reported as 0 on macOS with `privateBytesAvailable: false`
alongside it. `ps` gives RSS and nothing else, and `phys_footprint` needs a task
port. ADR-0028 removed the trim on macOS, so the committed-versus-resident gap
that number exists to show is a Windows-only question anyway.

## 5. The detached idle runner is Windows-only — **v0.12, unit 1**

`scripts/bench-idle.ps1` now drives `takyon-bench` for both input and memory, so
its duplicated `keybd_event` block and tree walk are gone and there is one
implementation of each mechanism. It is still PowerShell, and still the only way
to run the 35-minute measurement detached from the shell that started it.

`bun run bench --idle 35` is cross-platform and does the same measurement; it
just dies with its parent shell. The macOS equivalent of the detached wrapper is
`nohup` or `caffeinate`, and it is a few lines rather than a port. Worth writing
when someone actually needs a 35-minute run on the Mac, not before.

## 6. `bench-input.ps1` and `bench-mem.ps1` are now dead — **awaiting a decision**

Nothing calls either one: `bench.ts` and `bench-idle.ps1` both go through
`takyon-bench`. §2's Windows half is now closed, so the reason to keep them as a
reference implementation has expired and they can go. Left on disk pending an
explicit decision, because deleting files is not the agent's call to make.

## 7. ~~`hotkey.rs` has no macOS default~~ — **closed**

`DEFAULT_ACCELERATOR` is now `Command+Space` on macOS, with its own `CHOICES`
list led by that chord. See §15 for the half of unit 12 that is still open, and
§16 for the second copy of the default this exposed in the frontend.

## 8. `set_activation_policy` is a Tauri call, not an `objc2` one — **note on ADR-0028**

ADR-0028 says `LSUIElement` and the activation policy "are `objc2` calls against
the `NSWindow` handle after Tauri creates it". The policy half is not:
`tauri::App::set_activation_policy(ActivationPolicy::Accessory)` is a supported
Tauri 2 API and is what `lib.rs` uses, which keeps one fewer `objc2` call in the
startup path. The panel configuration in row 8 is still `objc2` exactly as the
ADR describes. Not a decision reversal, so no ADR amendment — a correction to one
sentence, left here rather than silently diverging.

## 9. The Palette is not actually an `NSPanel`, and making it one is not free — **v0.12, row 8, decide on hardware**

`panel.rs` sets everything ADR-0028 asks for that a plain `NSWindow` can carry:
`NSFloatingWindowLevel`, `CanJoinAllSpaces | FullScreenAuxiliary`,
`hidesOnDeactivate(false)`, and the `NonactivatingPanel` style-mask bit. It does
**not** turn the window into an `NSPanel`, so `becomesKeyOnlyIfNeeded` is unset
and the `NonactivatingPanel` bit may be inert — that bit is only fully honoured
by a panel.

This is a deliberate stop, not an oversight. The usual trick is
`object_setClass(window, NSPanel)`, and objc2's `set_class` states its
requirements plainly: the new class must be a **subclass of the object's current
class**, and must not change the instance size. Tauri's window is tao's own
`NSWindow` subclass, and `NSPanel` is that subclass's *sibling* — so the swap
breaks requirement 1, probably breaks requirement 2, and objc2's own
`debug_assert` on instance size is there because getting it wrong is undefined
behaviour rather than a bad layout. `tauri-plugin-nspanel` solves this by
building a dynamic class that inherits from `NSPanel` and re-adds tao's
overrides; that is a new crate, which ADR-0026 rules out, or a hand-rolled
subclass, which is real work to write blind.

**The question to answer on hardware, before writing any of it:** are the four
behaviours actually wanted already there without a panel? Namely — the Palette
draws over a full-screen app, survives a Space switch, does not vanish when the
app underneath takes focus back, and does not yank activation away from it. If
all four hold, no panel is needed and ADR-0028 should be amended to say so. If
one fails, the dynamic `NSPanel` subclass is the work, and it is bigger than the
ADR's five-line flag table implies.

Test it in that order: it is cheap to check and it decides whether a hard piece
of work exists at all.

## 10. `working_dir` is dropped on macOS — **v0.12, row 7**

`LaunchTarget::Exe` carries a `working_dir`, and `NSWorkspace` has nowhere to put
it: a launched application inherits launchd's environment rather than ours, and
setting a current directory for it is not something macOS offers. `run_open`
takes the argument and discards it with a comment rather than pretending.

Nothing populates it on macOS today — the field is filled from a Windows `.lnk`'s
working-directory property, and the `.app` walk has no equivalent. So this is a
gap in the type rather than in behaviour. It becomes real only if a macOS Source
ever wants to start something in a particular directory, and the answer then is
`NSTask`, not `NSWorkspace`.

## 11. The launched-image path is still nobody's — **TBC-0010**

Row 7 exists partly to restore launched-image identity, and it does:
`openApplicationAtURL:`'s completion handler hands back the
`NSRunningApplication`, and `open_application` waits up to two seconds for it.
But `query.rs` binds the result to `let _image` and drops it — nothing consumes
it on either platform yet.

Worth knowing before the two-second wait is read as load-bearing. It costs
nothing today (the Palette is already hidden, and a launch that reports
immediately returns immediately), and it is there so that the day TBC-0010's
recents list arrives, the data is already flowing. `bundleIdentifier` is the
better key and is deliberately *not* plumbed yet, for the same reason: there is
no consumer to shape it for.

## 12. ~~Settings' Files page has no macOS shape~~ — **closed**

Closed in the same session it was written. `settings::ConfiguredIndex` is a type
alias resolving to `WalkIndex` on Windows and `SpotlightIndex` on macOS, so the
Files page's commands are typed on whichever index this platform actually runs,
and the roots it writes reach the Spotlight query. Nothing rebuilds there: scope
is a `MDQuery` predicate, not a walk boundary.

`FileIndexReport.entries` became `Option<u32>` for the same reason — Spotlight
reports no count, so the page reads "Searching through Spotlight" rather than a
fabricated number. That is ADR-0027's stated consequence, now built.

**Two contract tests caught the field additions**, which is exactly what they are
for: `settings.rs`'s own key list and `tests/ipc.rs`'s `SNAPSHOT_KEYS` both had
to learn `platform`. Worth knowing before adding a field to `Snapshot`.

## 13. `security-framework` is the one new crate — **note on ADR-0026**

ADR-0026's rule is zero new crates, and the rest of the port honours it: the
`objc2` family was already in `Cargo.lock` via Tauri, and both `MDQuery` and
`AXIsProcessTrusted` are hand-declared `extern "C"` rather than a CoreServices
wrapper crate.

`security-framework` 3.7 is the exception, and it is ADR-0030's own decision
rather than drift — the alternative is hand-rolling `SecItemAdd` and
`SecItemCopyMatching`, which need CFDictionary building rather than the flat C
calls the other two are. Recorded because "zero new crates" gets quoted, so the
exception should be findable.

## 14. A clipboard test is flaky under the full suite — **not caused by this port**

`clips::os::tests::v0_11_the_windows_clipboard_round_trips` failed roughly one
run in four under `cargo test --lib`, and passed every time run alone. It writes
to the *real* Windows clipboard while the suite runs tests in parallel, so it
races anything else touching it — including a Takyon already running in the
tray, whose watcher reads the same clipboard.

Untouched by v0.12: it is `#[cfg(windows)]` and predates this work. Recorded
because the plan makes `cargo test -p takyon` the gate on the Mac, and a gate
that fails a quarter of the time teaches people to re-run rather than read. The
fix is a retry around the round trip — matching what the Win32 clipboard code
already does internally — or pinning that one test to a single thread.

## 15. The Cmd+Space onboarding has no blocking first-run screen — **v0.12, unit 12**

The mechanism is built and reachable: `DEFAULT_ACCELERATOR` is `Command+Space` on
macOS with its own `CHOICES`, `contested_chord` names the chord and the pane that
frees it, `open_contested_chord_pane` deep-links there, and
`claim_contested_chord` re-attempts the registration every 700 ms so the step
advances the instant Spotlight's checkbox is unchecked — no "I've done it" button
to lie to. Settings → Keyboard shows the block whenever the chord is contested
and unregistered.

What is **not** built is the plan's § Onboarding proper: a first-run screen that
explains the trade in one screen and **does not complete until the chord
registers**. That is a surface Takyon does not have — there is no onboarding
window, only the Palette and Settings — and inventing one blind, for a flow whose
entire point is how it feels the first time somebody meets it, is the part worth
doing with a Mac in front of you.

The plan is also explicit that this is the last thing built, "because until the
Palette is worth summoning there is nothing to take Spotlight's shortcut *for*".
Everything the screen needs to call now exists behind `api.ts`.

## 16. `Keyboard.tsx` had a second copy of the default chord — **fixed**

`const DEFAULT = "Alt+Space"` sat in the page while Rust's own
`DEFAULT_ACCELERATOR` became platform-dependent, so the Reset button would have
offered Option+Space on a Mac and called it the default. It now reads
`choices[0]`, which Rust orders with the platform default first — one source of
truth rather than two that agree until they do not.

The same page now hides the Windows-key row on macOS. `superkey.rs` is dropped
there (ADR-0025), so the switch would have offered a hook that can never install.
