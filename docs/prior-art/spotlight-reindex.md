# Spotlight and app discovery on macOS

Research date: 2026-11-03. Scope: macOS 13+ Apple Silicon. Evidence below is source research, not a reproduction on the friend's Mac. “Inference” labels engineering conclusions.

## Finding

Takyon's Apps Source walks `.app` bundles at startup; only its `!e` file search calls `MDQuery`. **Spotlight reindex alone cannot remove an app already in Takyon's own cache.** If Takyon drops apps, investigate scan roots, depth, timing, and stale cache. Spotlight can make `!e` incomplete or slow. Apple distinguishes filesystem-change-driven indexing from querying the metadata store. [Apple Spotlight architecture](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/MetadataIntro/Concepts/HowDoesItWork.html).

## 1. Why Spotlight may lose apps

**Spotlight store and Launch Services are distinct.** Spotlight stores file metadata; `MDQuery`/`mdfind` query that store. Launch Services records known apps and file/URL claims. Apple says Spotlight uses Launch Services to determine a file's type/importer, so failures may intersect; neither database's failure proves the other's. LaunchBar says its current default app index reads Launch Services, while its disk-scan option bypasses it. [Apple Spotlight architecture](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/MetadataIntro/Concepts/HowDoesItWork.html), [Apple Launch Services concepts](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/LaunchServicesConcepts/LSCConcepts/LSCConcepts.html), [LaunchBar support](https://www.obdev.at/support/launchbar).

[Apple Developer Forums report](https://developer.apple.com/forums/thread/845516). Another developer reported `mds_stores` consuming 60 GB on Tahoe beta and speculated about developer directories; this neither establishes the friend's cause nor implicates Takyon. [Apple Developer Forums memory report](https://developer.apple.com/forums/thread/796555).

**Read-only diagnostic split:** verify the `.app` exists; run `mdls -name kMDItemCFBundleIdentifier "/Applications/Example.app"` and `mdfind 'kMDItemCFBundleIdentifier == "the.bundle.id"'`; compare Spotlight's Apps mode and `NSWorkspace.urlsForApplications(withBundleIdentifier:)` for that known ID. Disk present + metadata absent points toward Spotlight import/store. Metadata present + UI absent points toward category/ranking/UI behavior. LS lookup absent as well means both may be stale, without proving order of failure. Apple's `NSWorkspace` API is a per-bundle-ID lookup. [Apple MDQuery](https://developer.apple.com/documentation/coreservices/file_metadata/mdquery), [Apple Spotlight categories](https://support.apple.com/guide/mac-help/narrow-search-results-in-spotlight-mchl4d69efd3/mac), [Apple NSWorkspace bundle-ID lookup](https://developer.apple.com/documentation/appkit/nsworkspace/urlsforapplications%28withbundleidentifier%3A%29).

## 3. App locations and walker design

**No finite fixed list is complete.** Apple permits installation in `/Applications` *or another chosen directory*. User-added scopes are needed for complete user-specific coverage. [Apple managing apps](https://developer.apple.com/documentation/xcode/managing-apps-on-devices), [Raycast Applications](https://manual.raycast.com/applications).

| Location/case | Evidence and treatment |
|---|---|
| `/Applications`, `~/Applications`, `/System/Applications` | Ordinary roots. Recursion is required for subfolders; depth 1 misses nested apps. Apple documents global/user application locations. [Apple file-system domains](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPFileSystem/Articles/Domains.html), [Apple app environment](https://developer.apple.com/library/archive/documentation/General/Conceptual/MOSXAppProgrammingGuide/AppRuntime/AppRuntime.html) |
| `/System/Applications/Utilities`, `/Applications/Utilities` | System and third-party utility paths. Recurse from their parents. Apple documents Activity Monitor in Utilities; a Ventura developer discussion identifies Terminal under `/System/Applications/Utilities`. [Apple energy guide](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/MonitoringEnergyUsage.html), [Apple Developer Forums](https://developer.apple.com/forums/thread/718722) |
| `/System/Library/CoreServices/Applications` | Add this *narrow* root; Apple places Feedback Assistant here. Avoid blanket `/System/Library` scanning. [Apple Feedback Assistant help](https://support.apple.com/en-is/guide/feedback-assistant/fbab81460adb/mac) |
| `~/Applications/Chrome Apps.localized` | Chrome web apps can be nested here. Treat `.localized` as an ordinary directory. [Google Chrome community](https://support.google.com/chrome/thread/229177249/how-to-remove-icons-for-google-apps-documents-youtube-etc-from-launchpad-mac-os?hl=en) |
| `/Applications/Setapp`, `~/Applications/Setapp` | Setapp documents both. `/Users/Shared/Apps/Setapp` holds previews/shortcuts for *uninstalled* apps; do not blindly index as installed. [Setapp storage locations](https://support.setapp.com/hc/es/articles/360002037440--D%C3%B3nde-guarda-Setapp-sus-archivos) |
| Homebrew Cask | Normal app artifacts move to `/Applications`; `--appdir` can redirect them. Add custom scopes rather than scanning all staged Caskroom files as installed apps. [Homebrew Cask Cookbook](https://docs.brew.sh/Cask-Cookbook), [Homebrew common issues](https://docs.brew.sh/Common-Issues) |
| Safari cryptex | Apple DTS says Safari can appear both at `/Applications/Safari.app` and `/System/Volumes/Preboot/Cryptexes/App/System/Applications/Safari.app` because the cryptex is grafted into the expected path. These may be the **same inode**. Scanning the cryptex path is unnecessary if `/Applications` is covered; deduplicate aggregated paths with file identity (`.fileResourceIdentifierKey`). The prompt's `/System/Cryptexes/App/...` is not the path in this Apple example. [Apple DTS answer](https://developer.apple.com/forums/thread/745673) |
| iOS-on-Mac app | Apple confirms compatible iPhone/iPad apps run on Apple Silicon through Mac App Store. Scan the outer `.app` bundle, not nested implementation content; Apple's public docs do not guarantee one stable wrapper layout. [Apple iOS apps on Mac](https://developer.apple.com/documentation/apple-silicon/running-your-ios-apps-in-macos), [Apple App Store guide](https://support.apple.com/en-ca/guide/app-store/-fird2c7092da/mac) |
| Symlinks and Finder aliases | Raycast explicitly supports both. Follow resolved app targets with cycle detection and identity deduplication; Finder aliases need alias resolution, not symlink handling. [Raycast Search Bar](https://manual.raycast.com/search-bar), [LaunchBar support](https://www.obdev.at/support/launchbar) |

Stop descent at a discovered `.app` bundle, or helper apps inside `Contents/Applications` may appear as launcher entries; Apple has a developer report of Spotlight surfacing such helpers. Filter `LSUIElement`/background helpers according to Takyon's user-facing-app policy. [Apple Developer Forums helper report](https://developer.apple.com/forums/thread/806244). Raycast documents Deep Search for nested app folders and a fix for app discovery in subdirectories. [Raycast Applications](https://manual.raycast.com/applications), [Raycast changelog](https://www.raycast.com/changelog/macos/2).

## 4. Keeping the app list fresh

**Best: independent cached scan + FSEvents.** Start `FSEventStreamCreate` before the initial scan, watch configured app roots, debounce events, and rescan affected subtrees. Apple's guide says starting the watcher before scanning avoids a lost-change race. Its latency setting coalesces events. `kFSEventStreamEventFlagMustScanSubDirs`, dropped events, and root changes require rescan; use `kFSEventStreamCreateFlagWatchRoot` for moved/deleted roots. Reconcile at startup/resume. Cost is directory metadata I/O on scans and low idle watcher work; latency is stream latency + debounce + scan. [Apple FSEvents introduction](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/), [Apple FSEventStreamCreate](https://developer.apple.com/documentation/coreservices/1443980-fseventstreamcreate), [Apple FSEvents handling](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html).

**Supplement only:** `NSWorkspace.urlsForApplications(withBundleIdentifier:)` returns URLs for a *known* bundle ID; `LSCopyApplicationURLsForBundleIdentifier` is deprecated. Neither provides documented all-app enumeration. LaunchBar shows LS lookups are fast but can miss aliases/unregistered apps. `NSWorkspace.didLaunchApplicationNotification` reports app launches, not installs, and omits background/`LSUIElement` apps; mount notifications can supplement external-drive updates. [Apple NSWorkspace bundle-ID lookup](https://developer.apple.com/documentation/appkit/nsworkspace/urlsforapplications%28withbundleidentifier%3A%29), [Apple LS API](https://developer.apple.com/documentation/coreservices/1449290-lscopyapplicationurlsforbundleid), [Apple launch notification](https://developer.apple.com/documentation/appkit/nsworkspace/didlaunchapplicationnotification), [LaunchBar support](https://www.obdev.at/support/launchbar).

**Avoid private enumeration:** one Apple Developer Forums participant reports `_LSCopyAllApplicationURLs` works without Spotlight, with a supplemental filesystem scan. This is a user report about a private symbol, not a public API guarantee. No public all-app enumeration method was found in Apple's documented Launch Services/NSWorkspace API. [Apple Developer Forums enumeration thread](https://developer.apple.com/forums/thread/822349), [Apple Launch Services API](https://developer.apple.com/documentation/coreservices/launch_services).

## 5. `MDQuery` and reindexing

Apple says `kMDQuerySynchronous` blocks during **query initial gathering** and runs the current thread's default run loop. Without it, `MDQueryExecute` returns after starting an asynchronous query. Its `true` means *started*, not “the global index is healthy.” `MDQuery` progress/finish notifications concern that query's gathering, not Spotlight's global rebuild. `MDQuerySetDispatchQueue` does not affect synchronous queries. [Apple metadata query flags](https://developer.apple.com/documentation/coreservices/file_metadata), [Apple MDQueryExecute](https://developer.apple.com/documentation/coreservices/1413099-mdqueryexecute), [Apple MDQuery overview](https://developer.apple.com/documentation/coreservices/file_metadata/mdquery), [Apple dispatch queue](https://developer.apple.com/documentation/coreservices/1413019-mdquerysetdispatchqueue).

**Observed:** Apple/Alfred say results can be incomplete during reindex; a developer reports `mdfind` returns nothing when Spotlight is disabled. **Inference:** `MDQuery` may return empty/partial results against an unbuilt/stale store. No source found that promises a fixed upper bound on synchronous gathering or says it always blocks for the whole OS rebuild. An unbounded synchronous `!e` call is still a latency risk. [Apple indexing support](https://support.apple.com/en-us/102321), [Alfred troubleshooting](https://www.alfredapp.com/help/troubleshooting/indexing/), [Apple Developer Forums enumeration thread](https://developer.apple.com/forums/thread/822349).

**Timeout pattern:** use a fresh asynchronous `MDQuery` on a worker with a serviced run loop or dispatch queue; set a deadline on its owning executor; stop it with `MDQueryStop` on timeout or superseding input; ignore late callbacks via query generation. Return partial results or a nonblocking loading/error state to the Palette. Apple's `MDQueryStop` preserves results already gathered, but a query stopped before completion sends no finish notification and cannot restart, so Takyon must signal its own timeout completion. Serialize stop and result access with callbacks; do not assume an arbitrary-thread `MDQueryStop` safely interrupts a synchronous call. [Apple MDQueryStop](https://developer.apple.com/documentation/coreservices/1413077-mdquerystop), [Apple MDQuery overview](https://developer.apple.com/documentation/coreservices/file_metadata/mdquery).

`mdutil -s /` reports volume indexing enablement; `mdutil -E /` erases its store for rebuild. Neither is a global percentage or per-query completeness test. Apple documents a user-facing progress indicator in Spotlight. No documented public `MDQuery` property or `kMDQueryProgress` global index-state API was found; `kMDQueryProgressNotification` refers to query gathering. [mdutil man page](https://www.manpagez.com/man/1/mdutil/), [Apple indexing support](https://support.apple.com/en-us/102321), [Apple MDQuery overview](https://developer.apple.com/documentation/coreservices/file_metadata/mdquery).

## 6. Could Takyon cause `mds_stores` RAM/reindex?

**Inference from Apple's architecture:** a normal `MDQuery` reads the existing store; file creation/modification/deletion drives index updates. Takyon's read-only queries should not cause a full reindex or explain runaway `mds_stores` RAM. Rapid overlapping queries can still consume CPU/client memory, so cap concurrency and results. `MDQuerySetMaxCount` limits result count and must precede execution. [Apple Spotlight architecture](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/MetadataIntro/Concepts/HowDoesItWork.html), [Apple MDQuerySetMaxCount](https://developer.apple.com/documentation/coreservices/1413085-mdquerysetmaxcount).

Large, frequently rewritten app-owned trees in indexed locations add indexing work. Keep transient cache/scratch data in appropriate app data locations and avoid needless rewrite churn. Apple's Search Privacy is the documented way to exclude a folder. Do **not** assume `.metadata_never_index` is reliable on current macOS; sources conflict after Mojave. A recent analysis identifies `.noindex` folder suffix, but that is not an Apple API guarantee. Time Machine may continue indexing its backup disk despite Search Privacy. [Apple Spotlight architecture](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/MetadataIntro/Concepts/HowDoesItWork.html), [Apple Search Privacy](https://support.apple.com/en-hk/guide/mac-help/mchl1bb43b84/mac), [Eclectic Light exclusion analysis](https://eclecticlight.co/2026/01/06/exclude-or-include-items-in-backup-search-icloud-drive-and-quicklook-preview/).

## 7. Ranked recommendation

1. **Retain independent app discovery; expand coverage.** Recurse configured roots, add `/System/Library/CoreServices/Applications`, support custom scopes, handle symlinks/aliases, stop at app bundles, deduplicate file identity, and define helper-app filtering. This directly protects Bangless app results from Spotlight rebuild. [Apple app installation](https://developer.apple.com/documentation/xcode/managing-apps-on-devices), [Raycast Applications](https://manual.raycast.com/applications).
2. **Add FSEvents and reconciliation.** Watch before scan, debounce, recover from dropped/root-changed events, and reconcile at launch/resume. This closes the startup-only freshness gap. [Apple FSEvents handling](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html).
3. **Isolate `!e` latency.** Replace the unbounded synchronous `MDQuery` with asynchronous query, deadline, cancellation, capped results, and stale-response guard. Spotlight may still limit file completeness but must never stall the Palette. [Apple metadata query flags](https://developer.apple.com/documentation/coreservices/file_metadata), [Apple MDQueryStop](https://developer.apple.com/documentation/coreservices/1413077-mdquerystop).
4. **Diagnose rather than reset the OS.** Distinguish app outside configured scope, missing metadata, Spotlight UI filtering, and stale LS lookup. Do not automatically run `mdutil -E`, delete `.Spotlight-V100`, or rebuild LS state. Apple's supported guidance starts with settings and targeted reindex. [Apple indexing support](https://support.apple.com/en-us/102321), [Alfred troubleshooting](https://www.alfredapp.com/help/troubleshooting/indexing/).

For the friend's Mac, compare Takyon's cached Apps Source with the filesystem first. If Takyon retains all apps while Spotlight drops them, the report is an OS search issue. If Takyon misses nested or recently installed apps, its current depth-1, startup-only walk directly explains the gap without reference to App Store provenance.
