## Tasks, in order

1. **`SearchProvider` trait** (§2). Brave Search behind it. Trait exists from day
   one so every alternative in TBC-0004 is a 1 to 2 day change.
2. **Key handling.** User supplies the key. Store it the way clipboard keys are
   stored, DPAPI-wrapped. Never in plaintext settings.
3. **Retrieval.** Provider returns URLs. Fetch pages in parallel over plain HTTP.
   Extract text with a Readability-style algorithm. No browser engine.
4. **Synthesis.** Feed extracted text to the summariser. In V1 that is the same
   Claude CLI subprocess `!c` uses, behind a swappable seam.
5. **Rendering.** Answer inline in the Palette with its sources listed. Streaming,
   not a spinner then a wall of text.
6. **Enter opens the query** in default browser with default search engine.
   Selecting a source Entry opens that URL.
7. **Outbound state visible.** The Palette shows it left the machine, in colour
   and in words. See `docs/brand.md`.

## Traps

Extraction fails on JavaScript-only pages. That is expected and the headless
fallback is deferred (`post-v1.md`). Fail visibly per source, do not silently
drop it and present a thinner answer as complete.

Parallel fetch needs a per-request timeout and a total budget. One slow page must
not hold the whole answer.

Rate limits are per second on the free tier. Debounce so typing `!s ferrari` does
not fire six queries.

Never send anything from the Bangless path to make `!s` faster. No prefetch, no
suggestion API, no warming. That is ADR-0002 and it has no exceptions.

The key is a secret. It is also a bearer token for someone else's paid account.

## Exit criteria

A question like "Ferrari in F1" returns a readable synthesised answer with
working source links, no browser opened, and the Palette clearly shows data left
the machine.

## Manual verification

1. `!s` a current-events question, confirm the answer cites reachable sources.
2. Confirm streaming, not a long blank pause.
3. Kill the network mid-query, confirm a clear failure, not a hang.
4. Enter opens the browser with the right query in the right engine.
5. Network monitor during Bangless typing: zero requests.
6. Type `!s` fast, confirm debounce prevents a burst of provider calls.
