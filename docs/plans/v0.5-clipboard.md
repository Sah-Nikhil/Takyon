# v0.5 Clipboard history

Useful without ever becoming a liability. Highest-risk phase in V1.

## Read first

ADR-0006 (storage and safety), ADR-0008 (field-level encryption),
`IMPLEMENTATION_PLAN.md` §4.

This feature captures every password you copy. Treat it accordingly.

## Tasks, in order

1. **Clipboard watcher.** `AddClipboardFormatListener`. Text first. Images and
   file lists later, behind the same rules.
2. **Key material.** Generate a 32-byte key once. Wrap with Windows DPAPI, bound
   to the user account. Store at `creds\clip.key.dpapi`.
3. **`clips.db`.** Schema in §4. `PRAGMA secure_delete = ON` at open, every time.
   AES-256-GCM per row, fresh nonce per row.
4. **Exclusions, both mechanisms:**
   - Honour the `ExcludeClipboardContentFromMonitorProcessing` clipboard format.
     Password managers already set it.
   - User-editable foreground-exe blocklist, because not every app sets the
     format.
5. **Retention.** Fixed list: forever, 6 months, 1 month, 1 week, 1 day.
6. **Sweep.** Runs at startup and on a timer. `DELETE` older than cutoff, then
   `PRAGMA wal_checkpoint(TRUNCATE)`.
7. **`!v` Mode.** Clipboard search, its own view. Clip Entries never appear in
   Bangless results.
8. **Paste-back** preserving format where it makes sense.

## Traps

**`DELETE` does not destroy data.** SQLite leaves freed pages intact and WAL
keeps live content until checkpoint. Without `secure_delete` plus
`wal_checkpoint(TRUNCATE)`, a deleted password is recoverable with a hex editor.
"Row deleted" and "secret gone" are different claims. This feature needs the
second one.

**Clip Entries must never surface Bangless** (ADR-0006). Not "ranked low", never.
That removes the whole shoulder-surfing problem: a result list glanced at over
your shoulder cannot contain a secret.

Metadata stays plaintext by decision, not by oversight. `source_exe`,
`created_at`, and `len` are readable. ADR-0008 accepts that leak and explains
why SQLCipher was deferred.

Retention change is destructive. Confirm with the real number before running the
sweep.

## Exit criteria

Copy a password from a password manager. Nothing about it exists in
`clips.db`, verified by opening the file, not by trusting the UI.

## Manual verification

1. Copy from Bitwarden or 1Password. Confirm no row appears.
2. Add Notepad to the blocklist, copy from Notepad, confirm no row.
3. Copy ordinary text, confirm the row exists and the ciphertext is not readable
   in a hex editor.
4. Set retention to 1 day. Confirm the dialog names the exact count. Confirm rows
   are gone and the file does not contain the old plaintext afterward.
5. Bangless query matching a clip's content returns nothing.
6. `!v` finds it.
