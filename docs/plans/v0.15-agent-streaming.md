# v0.15 Agent streaming and permissions

Every Agent streams its answer token by token, and a follow-up Turn can ask the
user before it touches anything.

**Driver: two things `!c` cannot do today.** Codex and opencode answer a message
at a time, however long the message, because the commands Takyon drives them
through cannot stream. And every permission prompt is refused, because nothing in
Takyon can answer one (`docs/tbd/v0.8.md` §1). Both need the same missing piece:
a two-way channel to a live Agent process, instead of arguments in and stdout out.

This reverses one decision of v0.8's on purpose — a fresh process per Turn — and
keeps the rule [v0.11.1](./v0.11.1-agent-spawning.md) establishes: every process
`!c` or `!s` starts is gone the moment the Palette hides. A live process here
lives for **one summon**, never between them.

Builds on v0.11.1 and does not start before it ships: the Job Objects, the
visibility gate, `turn::spawn` and `TurnFailure` are all assumed.

## The problem, precisely

**`codex exec --json` cannot stream tokens.** `exec` is itself a client of Codex's
app-server protocol, and its JSONL printer drops the deltas:
`openai/codex`, `codex-rs/exec/src/event_processor_with_jsonl_output.rs:336-360`
maps an `AgentMessage` item to nothing when it starts and to a whole message only
when it completes. No flag changes that.

**`opencode run --format json` cannot stream tokens.** `run.ts:753` emits a `text`
event only when the part has finished (`part.time?.end`). `run` starts opencode's
own server internally and subscribes to its events; it prints only the finished
ones.

**Claude can stream on the v0.11.1 path** (`--include-partial-messages`), but
cannot take a permission answer: v0.11.1 closes stdin after writing the prompt,
and a prompt that arrives afterwards has nowhere to go.

**v0.8's reasoning is out of date in one respect.** It chose a fresh process per
Turn partly because "`--input-format stream-json` exists on only one of the
three". Codex's `app-server` and opencode's `serve` are both long-lived,
two-way, and are what t3code drives. The other half of v0.8's reasoning —
crash-safety — still holds, and the design keeps it by resuming by session id.

## What t3code does, read from the source

**Claude** — `apps/server/src/provider/Layers/ClaudeAdapter.ts`. The Agent SDK's
`query()` with `includePartialMessages: true`, `canUseTool` (line 4476 onward),
`resume` and `permissionMode` (lines 4720-4743). The SDK keeps one `claude`
process for the conversation, writes each user message to its stdin as
stream-json, and answers its permission requests over the same pipes.
`Drivers/ClaudeExecutable.ts` follows an npm `claude.cmd` to the real binary
because the SDK cannot spawn a shim; Takyon's own spawn can (v0.11.1).

**Codex** — `Layers/CodexSessionRuntime.ts`. A long-lived `codex app-server`
spawned through `resolveSpawnCommand`, JSON-RPC over stdio:

- `initialize`, then the `initialized` notification (lines 2367-2368)
- `thread/start`, or `thread/resume` with a fall-back to a fresh start when resume
  fails (lines 704-768)
- `turn/start`; `turn/interrupt` (line 2511)
- notifications `thread/started`, `turn/started`, `item/agentMessage/delta`,
  `turn/completed`
- server-initiated requests `item/commandExecution/requestApproval` and
  `item/fileChange/requestApproval` (lines 2052, 2108), answered with a decision

Its Sign-in probe (`Layers/CodexProvider.ts:407-426`) spawns a short-lived
app-server and calls `account/read`, which returns the account and
`requiresOpenaiAuth`.

**opencode** — `opencodeRuntime.ts`, `OpenCodeServerOwner.ts` and
`Layers/OpenCodeAdapter.ts`. `opencode serve --hostname=… --port=…`
(`opencodeRuntime.ts:671`) with `OPENCODE_SERVER_PASSWORD` set and
`OPENCODE_CONFIG_CONTENT` respected rather than overwritten — its comment records
that setting it unconditionally once hid users' own providers. A shared server
with a **30-second idle TTL** (`OpenCodeServerOwner.ts:11`). Prompts go through
`session.promptAsync`; events arrive over SSE from `event.subscribe`
(`message.part.delta`, `message.part.updated`, `session.status`,
`permission.asked`, `permission.replied`); a permission is answered with
`permission.reply({ requestID, reply: "once" })` (line 1770); cancel is
`session.abort`. Its Sign-in probe reads the provider list's explicit `connected`
set (`Layers/OpenCodeProvider.ts:258`, `:522`).

`OpenCodeAdapter.ts` is 3,942 lines, and a large share of them reconcile
`session.status` going idle against message events that have not arrived yet.
That is the warning in this plan, not a detail.

### What is taken, and what is not

| t3code | Taken? | Why |
|---|---|---|
| The three transports | **Yes** | They are the only way to stream Codex and opencode, and the only two-way channel for all three |
| Resume with fall-back to a fresh thread | **Yes** | Keeps v0.8's crash-safety |
| `account/read` and `connected` probes | **Yes** | Both are structured where ours parse prose (`codex login status`) or infer from model lines (`opencode models`). They cost nothing extra once the clients exist |
| Claude's SDK-based probe | **No** | `claude auth status --json` returns the same facts without starting a session |
| The 30-second idle TTL | **No** | Breaks v0.11.1's rule. A process ends when the Palette hides |
| The Agent SDK itself | **No** | TypeScript. Takyon speaks the CLI's stream-json protocol directly, which is what the SDK does |
| `OpenCodeServerOwner`'s shared server | **No** | One server per conversation, inside that conversation's job |

## Design

### Lifetime: per summon

A **live Agent process** belongs to one conversation. The first Turn starts it;
follow-ups in the Chat Surface reuse it while the Palette stays shown;
`window::hide` terminates it through v0.11.1's jobs and gate, exactly as a Turn is
terminated today. The conversation already dies with the Palette
(`docs/tbd/v0.8.md` §3), so nothing is lost that is not already lost.

A registry, `agents/session.rs`, owns live processes the way `Turns` owns running
ones. It notices a process that exited on its own, marks it dead, and on the next
Turn respawns and resumes by session id. That is where v0.8's crash-safety lives
now.

**Each Agent moves on its own.** Until its transport lands, an Agent stays on
v0.11.1's one-shot path. `!c` never has a release where one Agent is half-moved.

### Tools still belong to the Turn

ADR-0017: the first answer runs with tools off, follow-ups with them on. A
long-lived process has to honour that per Turn, and the three do not make it
equally easy:

- **Claude** fixes its tool set at launch (`--tools ""`). The first Turn runs a
  tools-off process; Promotion replaces it with a tools-on process started with
  `--resume`. Every follow-up after that is warm.
- **Codex** — check at build whether `turn/start` accepts sandbox and approval
  overrides in the generated schema. If it does, one process; if not, the same
  replace-and-resume as Claude.
- **opencode** takes the agent per prompt, so `plan` on the first Turn and the
  default afterwards, in one server.

### Claude

```
claude -p --input-format stream-json --output-format stream-json --verbose
       --include-partial-messages --permission-prompts host
       --append-system-prompt <ANSWER_STYLE>
       [--tools ""] [--model …] [--effort …] [--resume <id>]
```

Process cwd, as now. A Turn is one user message written to stdin as a stream-json
line; it ends at the `result` line. Deltas are v0.11.1's `stream_event` rule.

`--permission-prompts host` means the CLI sends permission requests to its host
over stdout and waits for the answer on stdin. That is the Agent SDK's control
protocol, which `canUseTool` sits on, and it is **not a published contract**. Read
the request and response shapes from `@anthropic-ai/claude-agent-sdk`'s source at
build time and pin them with captured fixtures. An unrecognised control request is
answered with a denial, never left waiting.

### Codex

`codex app-server` — never `daemon` or `proxy` — inside the conversation's job,
cwd the Scratch directory. A small JSON-RPC client, `agents/jsonrpc.rs`: request
ids correlated to responses, notifications and server-initiated requests
interleaved on the same stdout, one JSON object per line.

`initialize` → `initialized` → `thread/start` (or `thread/resume`, falling back to
`thread/start`) → `turn/start` per Turn. `item/agentMessage/delta` becomes
`TurnEvent::Text`; `turn/completed` ends the Turn; `turn/interrupt` cancels one;
the two `requestApproval` requests become permission prompts. The locked model and
effort go in `turn/start`'s parameters, no longer a `-c` override.

**`codex app-server --help` labels the protocol `[experimental]`.** Pin the subset
Takyon uses: `codex app-server generate-json-schema` emits the schema from the
installed CLI, and an ignored test compares every method and field Takyon sends or
reads against it. Some reassurance: `exec` itself consumes these notifications, so
a breaking change there breaks Codex's own CLI too.

### opencode

`opencode serve --hostname=127.0.0.1`, never `--mdns` (which binds `0.0.0.0`), with
a random `OPENCODE_SERVER_PASSWORD` generated per spawn and sent as HTTP Basic auth.
`OPENCODE_CONFIG_CONTENT` passes through only if the user already set it.

**The port.** Prefer `--port 0`, opencode's own default, and read the URL it prints
on startup; check the line's exact shape at build time. t3code picks a free port
first and passes it, which races with anything else binding in between. If the
printed line proves unstable, fall back to t3code's way and retry once on a bind
failure.

Create or resume the session, send each Turn with `promptAsync` (agent `plan` on
the first Turn), and read the `/event` SSE stream: `message.part.delta` becomes
`TurnEvent::Text`, `permission.asked` becomes a permission prompt, `session.abort`
cancels. **Route and body shapes come from `@opencode-ai/sdk`'s generated client,
read at build time**, not from this plan.

**When is a Turn done?** `session.status` going idle is not enough on its own: it
can arrive before the message events for the prompt just sent. Require a message
from this prompt to have been seen, then idle — t3code waits for two idle
confirmations after the message (`OpenCodeAdapter.ts:1434-1436`).

### Loopback HTTP: std, not WinHTTP

opencode's server is plaintext HTTP on `127.0.0.1`. ADR-0019 put all HTTP through
WinHTTP for three reasons — OS TLS, the user's proxy, nothing added to the
installer — and none of them applies here: there is no TLS, a proxy must **never**
see a loopback request, and `std::net::TcpStream` adds nothing. It is also
portable, where WinHTTP would need a second `URLSession` implementation for macOS
(ADR-0029).

So `agents/loopback.rs`: HTTP/1.1 requests with `Connection: close`, and an SSE
reader that buffers to the line exactly as `turn.rs` buffers stdout. Proposed as an
**ADR-0019 amendment**, written with the code: WinHTTP for the network, std for
loopback.

### Permission prompts

```rust
TurnEvent::PermissionRequested { request_id: String, tool: String, summary: String }
TurnEvent::PermissionResolved { request_id: String }
```

A new command, `agent_permission_reply(turn_id, request_id, allow)`. Allow means
**once**; there is no "always" in the first version. Each Agent's request is mapped
to the same shape:

| Agent | Request | Summary built from |
|---|---|---|
| Claude | control request from `--permission-prompts host` | tool name and input |
| Codex | `item/commandExecution/requestApproval`, `item/fileChange/requestApproval` | command and cwd, or the paths |
| opencode | `permission.asked` | permission type and patterns |

The Chat Surface renders an approve/deny row inline in the transcript, and the
Turn waits. A pending prompt does not survive a hide — the process is gone with
it, which is the rule. The first Turn is tools-off and never raises one.

`--permission-prompts none` on Claude becomes `host`; `docs/tbd/v0.8.md` §1 closes.

### Probes

- Claude — unchanged. `claude auth status --json` is already better than t3code's.
- Codex — a short-lived `codex app-server` in a job: `initialize`, `account/read`,
  exit. `requiresOpenaiAuth` with no account is signed out; the plan type becomes
  the label.
- opencode — a short-lived `serve`: the provider list's `connected` set replaces
  counting providers in `opencode models` output.

Both keep `PROBE_TIMEOUT` and stay off the keystroke path (ADR-0018).

## Traps

- **stdin stays open for the process's whole life.** The opposite of v0.11.1, and
  the reason a writer thread becomes a channel. Closing it ends a Claude session.
- **Never let a pending permission hang a Turn.** An unknown request shape is
  denied and logged.
- **opencode idle before message.** See § opencode. The reconciliation is where
  t3code's adapter spent its lines; budget for it.
- **The protocols are not all contracts.** `app-server` is `[experimental]`;
  Claude's control protocol is SDK-internal; opencode's HTTP API is generated from
  its source. Pin each with fixtures, and keep v0.11.1's one-shot path compiling
  until every Agent has moved, so any one can be rolled back.
- **Loopback only, password always.** Any local process can connect to a port on
  `127.0.0.1`; the password is what makes the server Takyon's alone.
- **Do not overwrite `OPENCODE_CONFIG_CONTENT`.**
- **Tools-off must survive the move.** A warm tools-on process answering the first
  Turn of the next conversation would break ADR-0017 silently. It cannot happen
  under per-summon lifetime; a test asserts it anyway.
- **macOS.** Process groups and std sockets are portable. The unix crash gap
  v0.11.1 records — no `KILL_ON_JOB_CLOSE` equivalent — matters more with
  longer-lived processes, and v0.12 owns it.

## Tests

**Unit, from captured fixtures.** Claude: partial-message deltas, a control
request, a `result`. Codex: every notification Takyon reads, both approval
requests, a response interleaved with notifications. opencode: SSE frames for
deltas, `permission.asked`, and idle arriving before the prompt's first message.

**Unit, framing.** JSON-RPC id correlation with out-of-order responses; SSE lines
split across reads; HTTP Basic auth on every request.

**Integration, not ignored.** Fake peers, t3code's
`codexCollabMockPeer.mjs` / `.cmd` / `.sh` shape: small scripts run with `bun`
(already required by `bun run test`, so already on CI) behind a `.cmd` on Windows,
speaking just enough stream-json, JSON-RPC or HTTP to drive a Turn, a delta, a
permission prompt and a crash. Each asserts the lifetime rule: after
`set_visible(false)`, the job reports no active processes.

**Live, `#[ignore]`d.** For each signed-in Agent: at least two text deltas; a warm
follow-up; a follow-up asked to create a file in a `TempDir`, approved once (the
file exists) and denied once (it does not); the Codex schema pin.

**Visual.** The permission row, pending and resolved.

Five units, each leaving `!c` working:

1. Session registry and Claude (tasks 1-2)
2. Loopback and opencode (tasks 3, 5)
3. JSON-RPC and Codex (task 4)
4. Permission prompts (task 6), after 1-3
5. Probes and measurement (tasks 7-8)

Units 2 and 3 can run in parallel once unit 1 has landed. Every unit's gate is
`bun run typecheck && bun run lint && bun run test`, plus `bun run check:macos`
and `bun run check:comments`, with its ignored live tests run by hand and pasted
into the PR.

## Exit criteria

In `!c` and `!s`, all three Agents stream token by token. A follow-up asking for a
file edit shows a permission prompt in the Chat Surface; Approve writes the file
and Deny does not. First-token latency for a first Turn and a follow-up is
measured and written down. Hiding the Palette at any moment — mid-answer, or with
a prompt pending — leaves no process Takyon started.
