# v0.1 manual verification

The third testing layer from `IMPLEMENTATION_PLAN.md` §11. Everything below is
here because automating it is expensive and the automation would be less
trustworthy than doing it by hand — global hotkeys, focus rules, the tray,
multi-monitor placement and the UIAccess overlay are all OS state, not app state.

Written as part of the phase rather than improvised at the end, and short enough
that it stays honest. Run it against a **release** build unless a step says
otherwise; a debug build deliberately behaves differently in three places.

Record the date, the machine and anything surprising. A step that "sort of worked"
is a failure.

---

## Setup

```powershell
bun run build
# The bundle lands in apps/desktop/src-tauri/target/release/
```

---

## A. The hotkey

| # | Step | Expected |
|---|---|---|
| A1 | Press `Alt+Space` with a maximised app focused | The Palette appears in front of it, focused, with an empty input and a blinking caret |
| A2 | Press `Alt+Space` with the desktop focused | Same |
| A3 | Press `Alt+Space` again while the Palette is open | It hides. The hotkey toggles, so there are three ways out: the hotkey, Escape, and clicking away. All three must work |
| A4 | Type `photoshop`, press Escape, press `Alt+Space` | The input is **empty**. The Palette remembers nothing (ADR-0001) |
| A5 | Start PowerToys Run (or anything else holding `Alt+Space`) first, then launch Takyon | A **dialog** appears naming the conflict. It does not fail silently. Takyon still starts and the tray icon works |

## B. Dismissal

| # | Step | Expected |
|---|---|---|
| B1 | Open the Palette, press Escape | It hides |
| B2 | Open the Palette, click any other window, or the desktop | It hides immediately. This and Escape are the only two ways out, so both must be reliable |
| B3 | Open the Palette, press `Alt+F4` | It **hides**, and Takyon is still running (check the tray). ADR-0003 — the window is never destroyed |

## C. Placement

| # | Step | Expected |
|---|---|---|
| C1 | With two monitors, put the cursor on monitor 1 and press `Alt+Space` | The Palette opens on monitor 1 |
| C2 | Move the cursor to monitor 2, dismiss, press `Alt+Space` | It opens on monitor 2 |
| C3 | With two monitors at **different scale factors** (e.g. 150% and 100%), repeat C1–C2 | It is horizontally centred on both, not offset by half the DPI difference |

## D. The tray

| # | Step | Expected |
|---|---|---|
| D1 | Find the tray icon | It exists. Windows hides new tray icons behind the `^` chevron by default, so look there first |
| D2 | Left-click it | The Palette opens |
| D3 | Right-click it | Menu: Open Takyon / Settings / — / Quit Takyon |
| D4 | Click Settings | A separate window opens with the autostart switch |
| D5 | Click Settings again while it is open | The **existing** window focuses. No second window |
| D6 | Click Quit | The process ends. Confirm with `Get-Process takyon -ErrorAction SilentlyContinue` returning nothing |
| D7 | Switch Windows to Light mode (Settings → Personalisation → Colours) while Takyon runs | The tray glyph **swaps polarity within a second or two** and stays legible. Switch back and confirm it swaps again |
| D8 | Set "Choose your mode" to **Custom**, with Windows mode dark and app mode light | The glyph follows the **Windows** (taskbar) mode, not the app mode |

## E. Autostart

| # | Step | Expected |
|---|---|---|
| E1 | First launch after a fresh install | A dialog asks whether to start at login. It is asked **once**; relaunch and confirm it does not ask again |
| E1b | Run `target\release\takyon.exe` directly, or `bun run bench` | The prompt does **not** appear and no `Run` value is written. A build output is not an installed app, and `bun run bench` injects thirty keystrokes that will otherwise answer the dialog for you — which is exactly how a `Run` entry pointing into `target\release\` got created once |
| E2 | With autostart on, check the registry | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` has a value named **`com.v3sper.launcher`** — the slug, not "Takyon" (ADR-0011) |
| E3 | Reboot | Takyon is running. `Alt+Space` answers within about half a second of the desktop appearing |
| E4 | Turn autostart off in Settings, reboot | It does not launch, and the `Run` value is gone |
| E5 | Disable it from Task Manager → Startup apps, then open Settings | The switch reads **off**. It reflects the OS, not a cached copy |
| E6 | Uninstall with autostart on | Neither `...\Run\com.v3sper.launcher` nor `...\StartupApproved\Run\com.v3sper.launcher` survives |
| E7 | Launch a second copy while one is running | The existing Palette opens. No second process |

## F. Development builds — the three deliberate differences

| # | Step | Expected |
|---|---|---|
| F1 | `bun run dev`, open Settings | The autostart switch is **disabled**, with a reason naming `target\debug\` |
| F2 | After F1, check `HKCU\...\Run` | **No** Takyon value was written. This is the trap: a debug registration survives uninstalling the real app |
| F3 | `bun run dev` on a machine that has never run Takyon | The first-run prompt does **not** appear. A dev build must not consume the one-time question |

## G. Inspecting the Palette

| # | Step | Expected |
|---|---|---|
| G1 | `$env:TAKYON_NO_FOCUS_STEAL=1; bun run dev`, then `Alt+Space`, then open devtools | The Palette **stays visible**. Without this flag, focus-loss dismissal destroys it the moment devtools takes focus |

## G2. The idle beat and the motion switch

Automated tests assert which elements carry the animation and that the two share
a beat, but nothing automated can tell you whether it looks alive or looks like a
twitch. That part is here.

| # | Step | Expected |
|---|---|---|
| G2a | Summon the Palette and watch the mark without typing | Particle breathes, cone tip sweeps ±8° about the back edge, both on one beat. Alive, not busy — if it reads as a spinner the timing is wrong |
| G2b | Type one character | All motion stops immediately, mark level. Delete it: motion resumes |
| G2c | Dismiss with Escape, then summon again | Motion is running again and starts from the level frame, not mid-sweep |
| G2d | Settings → **Turn off animations**, then summon the Palette | Mark is completely still and level. The switch is read on every summon, so no restart is needed |
| G2e | Windows Settings → Accessibility → Visual effects → Animation effects **off**, our switch left on | Mark is still. The OS setting alone is enough; neither switch needs the other |
| G2f | Quit Takyon, relaunch, open Settings | The switch is where you left it |

## H. UIAccess over an elevated window

Needs `scripts/dev-sign-uiaccess.ps1` to have been run — see
`docs/plans/uiaccess-signing.md`. **This is the step most likely to be skipped and
the one most worth doing**, because its failure mode is silence.

| # | Step | Expected |
|---|---|---|
| H1 | Without the helper installed: focus an elevated terminal, press `Alt+Space` | The Palette does **not** come to the front. This is UIPI, and confirming it is what makes H2 meaningful |
| H2 | With the signed helper installed and `TAKYON_UIACCESS_HELPER` set: repeat H1 | The Palette appears **in front of** the elevated terminal and accepts typing |
| H3 | Quit Takyon, then check for the helper | `Get-Process takyon-uiaccess-helper` returns nothing. A privileged listener must not outlive the app |

## I. Benchmarks

| # | Step | Expected |
|---|---|---|
| I1 | `bun run bench` | Completes, prints p50/p95/max for show latency, startup, and idle RSS across **all** WebView2 processes |
| I2 | Check the process count it reports | More than one. If it says 1, it is measuring the Rust host alone and the memory number is meaningless |
| I3 | `bun run bench --idle 35` | Produces the post-idle first-show number. **This is the one that decides ADR-0003** — a tight loop never sees Windows reclaim the trimmed working set |
| I4 | Write all four into `docs/tbc/0002` | With the date, the machine, and how far each is from budget |

### I5 — the calibration capture (once, not per run)

`bun run bench` measures *hotkey handler entry → the IPC call after the painted
frame*. It includes one IPC hop and excludes DWM's final composition, so it is a
regression gate rather than a claim about what the eye sees.

Once, record the screen at 240fps, press `Alt+Space`, and count frames from the
keypress to visible pixels. The difference between that and the instrumented
number is the constant offset. Record it in TBC-0002 so every later number can be
read honestly without repeating this.
