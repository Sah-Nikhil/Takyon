# v0.6 Settings

Every decision so far becomes the user's. Also the first phase needing a real
theme, so the colour question in `docs/brand.md` must close before this ships.

## Read first

`docs/brand.md` (mark locked, colour open). ROADMAP v0.6 checklist. Raycast's
settings navigation is the reference for structure.

## Tasks, in order

1. **Separate settings window.** `Ctrl+,` from Palette and from tray. Its own
   lifecycle, never inside the Palette.
2. **`settings.db`.** Schema in `IMPLEMENTATION_PLAN.md` §4. UI is the only
   editor. No hand-edited config file.
3. **Two-tier navigation.** Short fixed set above a divider (General, Launcher,
   Keyboard, Advanced, About), then one alphabetical page per feature
   (Applications, Calculator, Clipboard History, File Search, AI). Every future
   Source or Mode adds a tier-two page without touching navigation.
4. **Settings search box.** Tier two is unbrowsable past ~15 entries.
5. **Controls, all pinned options.** Chips not free text, not sliders, where the
   option set is small. Hotkey control offers named choices plus reset, never a
   raw capture field.
6. **Apply on change**, ~1 s debounce, brief "Applied" confirmation. No save
   buttons.
7. **Destructive settings get a confirmation naming the consequence.** "Setting
   retention to 1 day will permanently delete 4,312 clipboard items."
8. **Pages content:** hotkey rebind, autostart, tray visibility, monitor
   placement, recents toggle, Bangless file-search toggle (default off), aliases,
   clipboard retention and blocklist, index roots and exclusions with a live
   entry count, appearance (follow system plus manual light/dark override, pinned
   interface sizes, and the motion switch inherited from v0.1), local crash-log
   folder button.
8b. **Migrate the motion switch.** v0.1 shipped "Turn off animations" in
   `localStorage` because no `settings.db` existed. `src/prefs.ts` is the only
   thing that reads that key: move it onto Appearance, read one existing value
   across so nobody's setting silently flips back on, and delete the fallback.
9. **Resolve the colour question.** Pick the palette, write it into
   `docs/brand.md`, and generate tokens from one source.

## Traps

Autostart reads from the OS via `isEnabled()` on mount, never from `settings.db`.
Mirroring it produces two sources of truth that disagree.

Apply-on-change plus a destructive setting is a data-loss bug waiting to happen.
Retention and the index-roots list both need the confirmation, and the
confirmation needs the real count, not a generic warning.

The live entry count is not decoration. It is the fastest way to notice a bad
exclusion rule just added 300,000 junk entries to the index.

Crash logs are written locally and never sent (ADR-0010). The settings button
opens the folder. It does not upload.

## Exit criteria

Nothing in the app requires editing a file or a registry key.

## Manual verification

1. `Ctrl+,` from Palette and from tray, both open the same window.
2. Rebind the hotkey, confirm old binding releases and new one works after
   restart.
3. Set retention to 1 day, confirm dialog names the exact item count.
4. Add an exclusion, watch the entry count drop.
5. Toggle appearance override, confirm it beats the OS setting both directions.
6. Kill the app mid-edit, restart, confirm settings persisted.
