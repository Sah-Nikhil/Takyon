# v0.6 Settings

Every decision so far becomes the user's. Also the first phase needing a real
theme, so the colour question in `docs/brand.md` must close before this ships.

## Read first

`docs/brand.md` (mark locked, colour open). ROADMAP v0.6 checklist. Raycast's
settings navigation is the reference for structure. [ADR-0015](../adr/0015-os-state-lives-in-the-os.md) before touching the autostart
switch, and `tesseract/docs/plans/launch-at-startup.md` for the longer argument
behind it.

## Tasks, in order

1. **Separate settings window.** `Ctrl+,` from Palette and from tray. Its own
   lifecycle, never inside the Palette.
2. **`settings.db`.** Schema in `IMPLEMENTATION_PLAN.md` §4. UI is the only
   editor. No hand-edited config file.
3. **Two-tier navigation.** Short fixed set above a divider (General, Launcher,
   Keyboard, Advanced, About), then one alphabetical page per feature
   (Applications, Calculator, Clipboard History, File Search, AI). Every future
   Source or Mode adds a tier-two page without touching navigation.
4. **Settings search box.** Tier two is unbrowsable past ~15 entries.
5. **Controls, all pinned options.** Chips not free text, not sliders, where the
   option set is small. Hotkey control offers named choices plus reset, never a
   raw capture field.
6. **Apply on change**, ~1 s debounce, brief "Applied" confirmation. No save
   buttons.
7. **Destructive settings get a confirmation naming the consequence.** "Setting
   retention to 1 day will permanently delete 4,312 clipboard items."
8. **Pages content:** hotkey rebind, autostart, tray visibility, monitor
   placement, recents toggle, Bangless file-search toggle (default off), aliases,
   clipboard retention and blocklist, index roots and exclusions with a live
   entry count, appearance (follow system plus manual light/dark override, pinned
   interface sizes, and the motion switch inherited from v0.1), local crash-log
   folder button.
8b. **Migrate the motion switch.** v0.1 shipped "Turn off animations" in
   `localStorage` because no `settings.db` existed. `src/prefs.ts` is the only
   thing that reads that key: move it onto Appearance, read one existing value
   across so nobody's setting silently flips back on, and delete the fallback.
8c. **Autostart: read the OS, report the failure, add nothing.** The registration
   itself shipped in v0.1 and is not being rebuilt — `tauri-plugin-autostart`, the
   `com.v3sper.launcher` `Run` value, the first-run prompt, the dev-build guards,
   `tray::self_heal_autostart` and the NSIS uninstall hook all exist and work.
   What v0.6 owes it is a real home and one fix:

   - Move the switch onto **General**, worded as it is now ("Start Takyon when I
     log in"). It stays a two-state switch with no sub-options.
   - Keep reading `isEnabled()` **on every mount**, never from `settings.db`
     ([ADR-0015](../adr/0015-os-state-lives-in-the-os.md)). No caching layer, no
     query client with a stale time, no optimistic update.
   - **Report a refused write.** This is the one behavioural fix
     ([`../tbd/v0.1.md`](../tbd/v0.1.md) §3): the current code awaits the write with
     no `try`/`catch`, so a rejection from group policy or a locked hive skips the
     re-read and vanishes into a floating promise, leaving a switch that silently
     refuses to move. Wrap it, show the error string beside the control, refetch in
     a `finally`.
   - Keep the dev-build disable, with its reason naming `target\debug\`. It is the
     only control in the whole window that is disabled by build profile, so it needs
     to survive a rewrite that standardises every other control.
   - **Do not add "close to tray" or "start hidden".** Tesseract has both; neither
     has an analogue here, and ADR-0015 records why. The Palette has no ✕ and always
     starts hidden.
   - Closing the Settings window must not end the process. The Palette is hidden
     rather than destroyed (ADR-0003), which is what keeps the app alive with no
     visible window — an easy thing to break while rebuilding window lifecycles, and
     the failure is a launcher that quits the moment you finish configuring it.

9. **Resolve the colour question.** Pick the palette, write it into
   `docs/brand.md`, and generate tokens from one source.

## Traps

Autostart reads from the OS via `isEnabled()` on mount, never from `settings.db`
(ADR-0015). Mirroring it produces two sources of truth that disagree, and the one
that disagrees is ours: Task Manager flips the registration with no event to
observe. A settings window built around a single cached config object will pull
this control into it by default. It has to stay outside.

Apply-on-change plus a `settings.db` write is the wrong shape for autostart
specifically. There is no row to write and no debounce to apply: the switch calls
the plugin, then re-reads. Whatever generic control component the rest of the
window uses must allow that.

Closing the Settings window must not exit the process. Nothing else in the app has
a close button, so this is the only place the behaviour can regress, and it will
look like a crash rather than a lifecycle bug.

Apply-on-change plus a destructive setting is a data-loss bug waiting to happen.
Retention and the index-roots list both need the confirmation, and the
confirmation needs the real count, not a generic warning.

The live entry count is not decoration. It is the fastest way to notice a bad
exclusion rule just added 300,000 junk entries to the index.

Crash logs are written locally and never sent (ADR-0010). The settings button
opens the folder. It does not upload.

## Exit criteria

Nothing in the app requires editing a file or a registry key.

## Manual verification

1. `Ctrl+,` from Palette and from tray, both open the same window.
2. Rebind the hotkey, confirm old binding releases and new one works after
   restart.
3. Set retention to 1 day, confirm dialog names the exact item count.
4. Add an exclusion, watch the entry count drop.
5. Toggle appearance override, confirm it beats the OS setting both directions.
6. Kill the app mid-edit, restart, confirm settings persisted.
7. Close the Settings window with its ✕. Takyon is **still running** — the tray
   icon is there and `Alt+Space` still opens the Palette.
8. Disable autostart from Task Manager → Startup apps, then open Settings. The
   switch reads off. Re-run `docs/verify/v0.1.md` section E in full; it is the
   regression suite for this control and none of it is superseded by v0.6.
9. Force the write to fail — a `Run` key denied by policy, or the value made
   read-only — and toggle. An error appears beside the control and the switch
   settles on what the registry says, not on what was clicked.
