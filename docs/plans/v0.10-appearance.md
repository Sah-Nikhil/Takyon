# v0.10 Appearance

The phase that finally closes the colour question `docs/brand.md` left open "until
v0.6", and that gives the Palette two shapes instead of one.

Four things ship together because they are one change wearing four hats: a theme
is only meaningful once every surface reads from tokens, the Expanded window is
only worth having once there is something to put in it, the Windows-key binding
is the first hotkey that is not an accelerator, and File Search is the page whose
current shape most obviously predates the settings vocabulary.

## Read first

`docs/brand.md` §"Colour — deliberately not locked" — this phase is what closes
it, and ADR-0023 is where it closes. [ADR-0022](../adr/0022-the-answer-surface-is-arc-shaped.md)
for the icon families already in play. [TBC-0006](../tbc/0006-content-sized-window.md),
because Expanded is the case that decision did not consider. `hotkey.rs` before
touching the binding, and [ADR-0015](../adr/0015-os-state-lives-in-the-os.md) for
why a low-level hook is not a stored preference the way an accelerator is.

Two references, both named by the user:

- **Raycast for Windows** — Compact and Expanded window modes, the category
  headings on the Expanded first view, the Follow System Appearance / Dark Theme /
  Light Theme triple on the Appearance page, and the Windows-key binding.
- **[t3code](https://github.com/pingdotgg/t3code)** — `packages/shared/src/themePalettes.ts`
  and `apps/web/src/components/settings/ThemeSettings.tsx`. The theme *model* is
  taken from here wholesale, and so is the selection mechanism. t3code was
  already the source of Takyon's surface construction at v0.6, so this is the
  same borrowing continued rather than a new dependency of taste.

## The problem this phase actually solves

Light mode does not look bad because the light palette is bad. It looks bad
because **the Palette was never tokenised.** v0.6 converted the Settings window
and stopped there. Everything in `palette/` still names raw colours:

```
border-white/10   panel edge          31 occurrences of white/N or black/N
border-white/5    inner seams         across Palette.tsx, Footer.tsx,
bg-white/10       row selection       EntryRow.tsx, ActionMenu.tsx,
bg-white/5        keycaps             AskView.tsx, SearchView.tsx and
bg-black/40       action-menu scrim   ClipboardHistory.tsx
text-amber-*      the outbound state
```

On a near-black plate white-at-10% is a hairline. On a near-white plate it is
nothing at all — the panel loses its edge, the selected row loses its highlight,
and the keycaps disappear. The light theme has been shipping with an invisible
selection since v0.6. No amount of palette work fixes that, and every one of
these has to become a token before a theme registry means anything.

The `amber-*` values are a second, quieter version of the same bug.
`docs/brand.md` states a semantic — **cool means contained, warm means it left** —
and then the code spells the warm half as Tailwind's amber, which no theme can
move. It becomes `--color-outbound`, carried by the theme like every other role.

## Tasks, in order

### 1. Tokens before themes

Extend `styles.css`'s token set to cover what the Palette needs, keeping v0.6's
two rules intact: **surfaces are raised, never grey**, and **every separation is
an alpha of the foreground**.

New roles, all derived except where noted:

| Token | Value | Replaces |
|---|---|---|
| `--color-edge` | `fg` at 12% | `border-white/10` — the outer panel border, which has to read against an arbitrary desktop |
| `--color-seam` | `fg` at 6% | `border-white/5` — the inner divisions |
| `--color-key` | `fg` at 7% | `bg-white/5` on keycaps |
| `--color-scrim` | **stated** | `bg-black/40`. The one role that cannot be an alpha of the foreground: on a light theme that is a *black* wash, and on a dark one a *white* one, so the two would behave oppositely |
| `--color-outbound` | **stated** | every `amber-*`. The warm counterpoint from `docs/brand.md`, which the theme now owns |
| `--shadow-panel` | **stated** | `shadow-2xl`. A near-white panel over a light wallpaper needs a tighter, denser shadow than a near-black one does |

Then convert every occurrence in the table above. This task is mechanical and it
is also the whole point: **nothing in `apps/desktop/src` may name a colour after
it**, the same promise v0.6 made for Settings.

`bg-plate/95` stays as-is. The Palette is deliberately translucent over its
backdrop blur, and the slash-alpha is applied to a token, not to a literal.

### 2. The theme model, taken from t3code

A theme is a **family carrying both appearances**, not a single palette:

```ts
interface ThemeHalf {
  plate: string;   // the window canvas
  fg: string;      // text
  accent: string;  // the cool signal: selection ring, tick, "Applied"
  outbound: string; // the warm signal: !s, the network-left state
  card: string;    // stated, because the surface order inverts
  sidebar: string; // likewise
}

interface ThemeFamily {
  id: string;
  label: string;
  dark: ThemeHalf;
  light: ThemeHalf;
}
```

Both halves are always present. That is what makes the Raycast Appearance page
coherent: **Dark Theme** and **Light Theme** are two independent choices over the
same list, and **Follow System Appearance** decides which of the two is live.
A family that only had one half would appear in one list and not the other, which
reads as a bug rather than as a constraint.

Colours are authored in **oklch**, following t3code. Not decoration: the
discipline this phase needs is *the same lightness across families* — every dark
plate at L ≈ 0.19, every dark accent at L ≈ 0.79, every light plate at L ≈ 0.975 —
and that is a property oklch states and hex hides. WebView2 Evergreen is
Chromium 120+, which has supported it since 2023.

The derived surfaces move from `color-mix(in srgb, …)` to `in oklab` for the same
reason: mixing a tinted near-black toward a near-white in sRGB desaturates through
the middle, which is exactly the "milky" failure v0.6's rules exist to prevent.

### 3. Five families

Five, not three and not twelve. Three is not a library; twelve is a page nobody
reads, and each one is hand-tuned rather than generated.

| id | label | Character | Why it is in the set |
|---|---|---|---|
| `graphite` | Graphite | Neutral cool near-black, vermillion accent | **The default, both halves.** A launcher opens over whatever the user's wallpaper is; a neutral plate is the only one that never fights it. The accent is warm and confident rather than another blue, which is what Raycast's own default does |
| `vela` | Vela | Indigo plate, violet accent | The Midnight analogue, and the one the reference screenshots are actually running |
| `cherenkov` | Cherenkov | `#0b0e12`, cyan accent | **What shipped through v0.9.** It stays in the set because it is the mark's own hue and because demoting it silently would be a worse change than demoting it deliberately |
| `aurora` | Aurora | Green-tinted plate, green accent | |
| `halide` | Halide | Amber-tinted plate, amber accent | The one family whose accent and outbound roles are near neighbours, so it is the test case for whether the warm semantic still reads |

The names are Takyon's own register — light and particle physics — rather than
Raycast's times of day or t3code's places. Borrowing the model is deliberate;
borrowing the labels would be careless.

**Cherenkov is no longer the default.** The mark keeps its hue: `--mark-particle`
still resolves to `--color-accent`, so the in-app mark adopts the live theme,
while everything `brand/` generates — the installer icon, both tray polarities —
stays locked at Cherenkov cyan. Those are identity, not interface.

### 4. Theme selection, taken from t3code

A **card grid**, not a dropdown, and the card is a *preview*, not a swatch.

t3code paints each theme as a sphere: a radial gradient whose base is the theme's
canvas and whose highlight is its accent, interpolated in oklab so the falloff has
no grey mid-tones. Two spheres per card, sun and moon. Reimplement it — it is
pure CSS, needs no asset, and it is the one preview that survives being 40px wide.

The page is Raycast's:

```
Appearance
  Follow system appearance          [switch]
  Dark theme      [card grid, moon halves]
  Light theme     [card grid, sun halves]
  Interface size  [small · default · large]
  Window mode     [two preview cards]
  Turn off animations               [switch]
```

Appearance leaves General and becomes its own tier-one page. General keeps
autostart and gains nothing; six controls is a page, and appearance is now the
largest group in the window.

**No theme editor and no imported themes in this phase.** The user asked for a
set of good themes, not for a colour picker. `ThemeHalf` is deliberately six
roles so that a `.takyon-theme.json` import stays cheap to add later; that is
`docs/tbd/v0.10.md`, owned by post-v1.

### 5. Compact and Expanded

Two window modes, stored as `ui.window-mode`, **Compact by default.**

- **Compact** is exactly today's behaviour and TBC-0006's content-sized window:
  68px empty, growing by `ROW_HEIGHT` per Entry to a cap of eight. Nothing about
  the 30 ms budget or the window arithmetic changes.
- **Expanded** is a fixed `EXPANDED_HEIGHT` window that never resizes on a
  keystroke. The list scrolls inside it.

Expanded is not "Compact but taller". It is the mode that has room for structure,
so it gets two things Compact cannot afford:

- **Category headings** over the Entry list, grouping by Kind — Applications,
  Files, Folders, Commands, Clipboard, Settings — in the ranked order the groups
  first appear, so the ranking still decides and the grouping only labels.
- **A first view.** An empty query in Compact shows nothing (ADR-0001), and that
  is right for a 68px bar. A 520px window showing nothing is a hole. Expanded's
  empty query shows **Suggestions**: the top Frecency entries, which is the one
  list that is genuinely about this user and needs no network and no walk.

The Rust half is small. `Shape` gains `expanded: bool`, `content_height` returns
`EXPANDED_HEIGHT` when it is set and no View is open, and the flag is cached in an
atomic beside `UI_SCALE` for the same reason that one is — `apply` runs on every
keystroke and must not read SQLite.

The suggestions path is new: `Frecency::top(limit)` over the existing table, then
`AppSource::find` to resolve each id. **It runs only for an empty query in
Expanded mode**, so it is off the hot path for every other keystroke, and it
touches nothing outside the machine (ADR-0002 is not even reached).

### 6. The Windows key

The default binding stays `Alt+Space`. The Windows key is a **switch, off by
default**, on the Keyboard page.

It cannot be an accelerator. `Alt+Space` is registered with
`RegisterHotKey` through `tauri-plugin-global-shortcut`; the Windows key is a
*modifier*, and Windows opens the Start menu on its **release** when no other key
was pressed in between. Replacing it needs a `WH_KEYBOARD_LL` hook:

- On `LWIN`/`RWIN` **down**, inject a benign undefined virtual key (`VK_F24`, or
  `0xE8`, which Windows assigns to nothing). The OS now sees the tap as a chord
  and will not open Start on the release. The down-stroke itself is **never
  swallowed**, which is what keeps `Win+R`, `Win+E`, `Win+L` and every other
  system chord working.
- On `LWIN`/`RWIN` **up**, if no real key was pressed between down and up, this
  was a tap: toggle the Palette and swallow the release.
- Anything else falls through untouched.

Three costs, all of which have to be in the code as comments and in
`docs/tbd/v0.10.md` as gaps:

1. **The hook is on every keystroke in the system.** It must do nothing but
   compare a virtual-key code and set a bool — no allocation, no lock, no logging.
   Windows silently unhooks a callback that exceeds `LowLevelHooksTimeout`
   (300 ms by default), and the failure mode is the binding quietly dying mid-
   session with nothing in the log.
2. **It does not survive an elevated foreground window** without the UIAccess
   helper, whose certificate is still the outstanding v0.1 item. Same limitation
   `Alt+Space` already has, so this is not a regression — but the switch's
   description has to say it.
3. **It must be released on quit and on hook failure**, and re-armed if Windows
   drops it. A hook left installed by a dead process is not a thing Windows
   leaves lying around, but a hook the app *thinks* is installed and is not is,
   and the Keyboard page has to be able to say which.

The Keyboard page changes shape with it. Six chords as chips was reasonable when
the chord was the whole setting; now there is a switch above it, so the chord
becomes a **dropdown** (`Select`, which already exists and is already keyboard-
complete) and the chips go. macOS is documented in `docs/plans/post-v1.md` as the
`Alt+Space` replacement, not built.

### 7. File Search

The page is rebuilt to the shape in the reference: **Search Scopes** as a list
with an add control, **Ignore Patterns** as a list with an add field and the
hierarchical explanation, then the switches, then **Reset to defaults**.

What genuinely ships, because it maps to behaviour that exists: the scopes list,
the exclusions list, `files.bangless`, `files.fallback`, the live entry count,
the opened-files history, and Reset to defaults (which clears both stored keys and
lets `index::roots::defaults()` be recomputed — the probe-don't-store rule from
TBC-0005's amendment already makes that the correct reset).

What is **named in `docs/tbd/v0.10.md` and not built**, because each is a feature
rather than a setting and pretending otherwise puts dead controls in the one
window whose whole point is that none of them are:

- **Content search.** Reading file contents is an index format change, not a
  toggle. Owned by post-v1.
- **Glob ignore patterns and `.gitignore` awareness.** Today `files.excludes`
  matches one whole folder name (`index::roots::is_excluded`). Moving to globs is
  a walker change and a stored-format migration. Owned by v0.11.
- **Include hidden files**, **keep files from removed volumes**, **low disk space
  block.** All three are real, all three are walker and store behaviour.

## Traps

**The Palette's tokens are not the Settings window's tokens, and the difference is
the desktop behind them.** The Settings window is opaque; every separation in it
only has to work against `--color-plate`. The Palette is `transparent: true` with
a backdrop blur, so its *outer* edge is read against an arbitrary wallpaper. That
is why `--color-edge` exists as a role separate from `--color-hairline` rather
than being the same 8%. Collapsing the two is the obvious simplification and it
loses the panel's silhouette on light themes over light wallpaper.

**`--color-scrim` is the one token that must not be derived.** Every other
separation is an alpha of the foreground, which inverts correctly because the
foreground inverts. A scrim does not: its job is to push the surface behind it
back, and that is a *darkening* in both appearances. Deriving it produces a white
wash over a light theme, which brightens the thing it was supposed to dim.

**Expanded mode breaks the shape/height test both ways.** `paletteHeight` in
`packages/shared` and `window::content_height` in Rust mirror each other and a
test asserts the constants agree. Expanded adds a branch to both, and the branch
that is easy to forget is the interaction with `View`: a full-window View already
overrides every row-based measurement, so **`View` must still win over Expanded**,
or opening the Chat Surface from Expanded mode leaves it at the wrong height.

**Expanded mode plus the first view is the one path that can violate ADR-0001.**
"The Palette always opens empty" is about *state*, not about pixels: nothing typed
is remembered. Frecency suggestions are not remembered state, they are a Source's
answer to the empty query — the same status a Recents Entry has. Ranking them is
fine. Restoring the last query into the input is not, and the temptation to do
that arrives with the tall window.

**The idle mark's animation is gated on `value === ""`, and Expanded's first view
is an empty value with a full list.** The particle would breathe under eight rows
of suggestions, which reads as "working" while the shell is idle. Gate it on
Compact as well, or on there being no Entries.

**The low-level hook must not be installed on the setup thread.** `SetWindowsHookExW`
binds the hook to the thread that installs it and that thread must run a message
loop for the callback to fire. The main thread has one; a `std::thread::spawn`d
worker does not, and the hook will install successfully, report success, and never
call back. This is the same class of failure as the "never create a window from
the main thread" gotcha in reverse, and it fails just as silently.

**Every existing visual screenshot is invalidated by task 1.** That is correct and
expected — the selection highlight changes value on dark as well, because
`--color-row-selected` is 10% and `bg-white/10` was 10% of pure white rather than
10% of `--color-fg`. Regenerate the baselines in one commit, separately from the
change that caused it, so the diff is reviewable.

**`ui.theme` already exists and holds `system | light | dark`.** It becomes
`ui.appearance` unchanged in meaning, and two new keys carry the family per half.
Read the old key once and write the new one, the way `prefs.ts` already migrates
the v0.1 `localStorage` keys — a rename with no migration silently resets
everyone's appearance override to "system".

## Exit criteria

The light themes are usable — panel edge, selected row and keycaps all visible on
every one of the five families — the Expanded window opens on a categorised list
of suggestions, and no file under `apps/desktop/src` names a colour.

## Manual verification

Full script in [`docs/verify/v0.10.md`](../verify/v0.10.md). The short form:

1. Every one of the ten halves, in both windows, checking the panel edge, the
   selected row, the keycaps and the `!s` outbound header.
2. Follow System Appearance on, then flip Windows between light and dark with the
   Palette open. The live half changes; neither stored choice does.
3. Compact → Expanded with the Palette open. The window grows once and stays.
4. Expanded, empty query: suggestions appear under category headings, and the
   mark is **not** breathing.
5. Expanded, then `!c` with a question. The Chat Surface is `VIEW_HEIGHT`, not
   `EXPANDED_HEIGHT`.
6. Turn the Windows key switch on. Tap Win — the Palette opens and the Start menu
   does not. Hold Win and press `R` — the Run dialog opens and the Palette does
   not. Hold Win and press `L` — the machine locks.
7. Turn it off. Tap Win — the Start menu opens, and it opens on the first tap
   rather than the second.
8. With the switch on, restart the app and confirm the hook is re-armed rather
   than reporting success against nothing.
9. File Search → Reset to defaults, with a custom root added first. The root
   list returns to the probed defaults, and the entry count moves.
