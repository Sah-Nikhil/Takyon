# v0.3 Ranking that learns, and the Sources it ranks

Palette starts guessing right before you finish typing — and knows about the
things v0.2 could not see.

Tasks 1–7 are the ranker. Tasks 8–10 add Sources. They are one phase on purpose:
each new Source adds Entries that are individually worth less than an application,
and dropping ~200 of those into an unranked Palette makes it worse. Frecency and
kind ordering are what make them safe to add.

## Read first

v0.2 done. `IMPLEMENTATION_PLAN.md` §3 (Frecency, Stability). `CONTEXT.md` for
both terms. `docs/tbd/v0.2.md` §7 for the evidence behind tasks 8–10 — including
a first diagnosis that was wrong, and how it was caught — and **§9 and §10 before
task 0**, which carry the measurements the fix is sized against.

## Tasks, in order

0. **Fix `EntryId` before anything writes Frecency against it.** Two v0.2 defects,
   both found on 2026-08-27 and both recorded with measurements in
   `docs/tbd/v0.2.md` §9 and §10.

   *The identity collision (§9).* `EntryId::for_launch` ignores launch arguments,
   so every Start Menu shortcut that runs through a host binary collapses onto one
   id: nine onto `cmd.exe`, three onto `javacpl.exe`, three onto the x86
   `powershell.exe`. **15 distinctly-named applications** on this machine are
   dropped by `seen.insert`, then reappear through `AppsFolder` as AUMIDs — wrongly
   subtitled `Store app`, with their action menu truncated to Open, and past the
   `is_noise` filter that only runs in `lnk.rs`. Fold arguments into the id where
   they exist, leaving the argument-free case byte-identical so nothing already
   learned is invalidated. This contradicts
   `v0_2_launch_arguments_do_not_change_identity` and one row of ADR-0014; amend
   both in the same change rather than deleting the test.

   Detect `Store app` rather than asserting it, and move `is_noise` somewhere both
   discovery paths reach. Six more shortcuts have no target path at all — File
   Explorer, Control Panel, Run among them — and need a separate decision, not this
   fix.

   *The icon cache (§10).* `icons.bin` is 12 bytes and always has been: `flush()`
   runs once per launch, immediately after the walk, at the one moment nothing has
   been extracted yet. Flush on a debounce after extraction, or at exit. `flush()`
   itself is correct.

   **This is task 0 because task 1 keys Frecency on `EntryId`.** Land it first and
   the collision is a bug that was fixed; land it second and it is a corrupted
   usage database that has to be thrown away.

1. **`frecency.db`.** Schema in `IMPLEMENTATION_PLAN.md` §4. Written on every
   activation, keyed by `EntryId`.
2. **Decay.** `weight = Σ 0.5^(age_days / 30)`. Store decayed value plus
   `decayed_at`, re-decay lazily on read. No background job, no clock-skew bug.
3. **Score composition.** Match tier from v0.2, multiplied by Frecency weight.
4. **Kind ordering, applied after scoring.** Apps always above documents. Never
   interleaved by raw score. This is a product rule, not a tuning knob.
5. **Stability lock:**
   ```rust
   struct StabilityLock { query: String, top: EntryId, locked_at: Instant }
   ```
   100 ms after last keystroke, current top `EntryId` locks for that exact query
   string. Later results append below, never displace. New keystroke clears lock.
6. **Aliases.** Resolved before matching, from `settings.db`. Alias exact match
   outranks everything.
7. **Recents Source.** Shell recent-items list, no index, cheap. Always below
   apps.

8. **System entries Source** (`sources/system.rs`). Two halves, one Source.

   *Control panel tasks.* The All Tasks shell folder,
   `shell:::{ED7BA470-8E54-465E-825C-99712043E01C}`. Verified on the dev machine:
   198 items with human-readable names ("Change how your keyboard works", "Use
   screen reader"). Enumerated with `IEnumShellItems`, the same COM path
   `appsfolder.rs` already walks, so this adds no new Windows API surface.
   Activation invokes the item's default verb.

   *Settings pages.* `ms-settings:` URIs. There is no public enumeration API —
   Raycast reports reading 947 entries from "the Windows settings catalog", which
   is almost certainly a table it ships rather than something it discovers. Start
   with a curated table of the pages people actually reach for (bluetooth,
   display, sound, network, apps, storage, updates) and grow it from use. **Open
   question:** whether a fuller catalog can be derived rather than hand-written.
   Do not block the control-panel half on answering it.

   Both halves produce a **new `EntryKind`, ranked below applications and never
   interleaved** — the same product rule as task 4. `EntryId` is
   `system:<canonical name>` or `ms-settings:<page>`, stable across reinstalls.

   If any of this reaches UI copy, `CONTEXT.md` needs a term for it first. Do not
   invent one in code and backfill the glossary.

9. **Game launcher Sources**, Epic first.

   Manifests live at
   `C:\ProgramData\Epic\EpicGamesLauncher\Data\Manifests\*.item` — one JSON file
   per game, **UTF-8 with BOM**, carrying `DisplayName`, `InstallLocation`,
   `LaunchExecutable` and `AppName`. No new dependency; `serde_json` is already in.

   Two things the real files teach that a spec would not:

   - **Separators are mixed.** `C:\GG\EpicLibrary/DyingLight` is a verbatim
     `InstallLocation` from this machine. Normalise before joining.
   - **Manifests go stale and Epic does not clean them up.** All seven on the dev
     machine point at directories that exist but are empty, and one
     (`NBA2K21`) at a directory that is gone. Raycast lists all seven as
     launchable. Takyon must apply ADR-0013's rule instead: resolve the
     executable, check it exists, drop the Entry if it does not.

   **Consequence, and it is the important one: this Source returns zero Entries on
   the dev machine.** Like Steam (`docs/tbd/v0.2.md` §3) its launch path cannot be
   verified here. The parser gets fixture tests taken verbatim from the seven real
   manifests; the round trip needs an installed game or another machine. Build it
   for correctness, not for a demo.

   `EntryId` is `epic:<AppName>` — the catalog GUID, never the path. This mirrors
   the `steam:` prefix already in `EntryId::for_launch` and survives a library
   move, which a path-keyed id would not.

   **EA is deferred, with the finding recorded so it is not re-investigated.**
   `C:\ProgramData\EA Desktop\InstallData\<name>\` yields the display name, but no
   structured record of the install path could be found: `machine.ini` carries
   `machine.downloadinplacedir`, which is the download directory and not where the
   game landed, and the actual path appears only in `EABackgroundService.log`. A
   log is not a manifest and must not be parsed as one. Revisit only if a
   structured source turns up. This matters because EA is the one launcher with a
   live game on the dev machine.

   The remaining launchers Raycast queries — GOG, Ubisoft, Blizzard, Riot,
   Battlestate, Rockstar, Roblox, itch — take the same shape and get added on
   demand, not speculatively.

10. **winget Source — measure before building.** Raycast collects 4 winget apps on
    the dev machine against 156 Start Menu shortcuts. Before writing anything,
    count how many of those 4 an existing Source already finds. If the answer is
    4, do not build it and record that here. Same discipline as
    `docs/tbd/v0.2.md` §4.

11. **Desktop shortcuts, gated on collision.** Add the user and public Desktop to
    the `.lnk` walk. Everything in `lnk.rs` is reused unchanged — `com::read`,
    `is_noise`, `collapse_by_name` — so this is a roots change, not a new Source.

    **The gate is the feature.** A Desktop shortcut is nearly always a second
    pointer to something the Start Menu already has. Measured on the dev machine:
    9 Desktop shortcuts, **8 already discovered, 1 new**. Ungated it adds nine
    rows to buy one app. So a Desktop Entry survives only when neither its name
    nor its resolved target matches an Entry another Source already produced.
    Name-only and name-plus-target dedupe give the same answer here; implement
    both, because they will diverge on a machine where a shortcut was renamed.

    The one survivor is `Adobe After Effects 2022` at
    `C:\ADOBE\Adobe After Effects 2022\Support Files\AfterFX.exe` — a root no
    other Source reaches.

    **Desktop is walked last and always loses a collision.** Order is not
    cosmetic: `EntryId` is the launch path, people delete desktop icons casually,
    and if the Desktop copy won, deleting the icon would change the id and reset
    that app's Frecency. The Start Menu copy is the stable one.

    **Resolve the Desktop path with `SHGetKnownFolderPath`
    (`FOLDERID_Desktop`, `FOLDERID_PublicDesktop`), never by joining
    `%USERPROFILE%\Desktop`.** A OneDrive-backed Desktop is redirected, and the
    hardcoded join silently walks an empty directory. Cap the walk at depth 2 —
    the Desktop is flat in practice but users do make folders on it.

## Traps

**Stability lock is the phase.** Without it a late Source inserts above your
selection in the 20 ms between eye and finger, and you launch the wrong thing.
Unit test it the day it exists. Test case: lock top, deliver a higher-scoring
Entry 50 ms later, assert top unchanged and new Entry appended.

Frecency keyed on an unstable `EntryId` silently resets on every app update. If
`vsc` stops finding VS Code after an update, this is why.

**Frecency keyed on a *colliding* `EntryId` is worse than unstable — it is wrong
and it never looks wrong.** Nine Command Prompt variants share one id today
(§9). Launch any of them and all nine get the credit, so the ranker becomes
confident about an application nobody chose. Task 0 exists for this and is not
optional sequencing.

Decay half-life of 30 days is a guess. Tune from real use, not from theory.

Recents come from the shell, so they include files opened by any app. Do not
assume they are yours.

**Task 4 lands before task 8, not after.** The system entries Source adds roughly
200 Entries whose individual value is far lower than an application's. Dropped
into an unordered ranker they push apps down and the Palette gets worse, not
better. Kind ordering is what makes them safe to add at all — which is the whole
reason these Sources belong in the ranking phase rather than in v0.2.

Epic manifests are stale by design; see task 9. A launcher Source that trusts its
manifest ships dead rows. Resolve and check, every time.

Do not parse `EABackgroundService.log`. It is a log, its format is not a contract,
and the entry that looks like an install path is an installer argument.

An ungated Desktop Source is worse than no Desktop Source. On the dev machine it
would add nine rows for one app's worth of coverage, and eight of them would be a
second row for something already on screen — the exact failure v0.2 spent
§3a and §4a fixing.

## Exit criteria

After a week of real use, your ten most-used apps each reachable in one or two
keystrokes — and adding the new Sources has not pushed a single one of them down.
That second half is the guard on this phase: a Source that improves coverage and
degrades the top row has failed.

`bluetooth` reaches the Bluetooth settings page without touching the Start menu.

## Manual verification

Script goes in `docs/verify/v0.3.md`, written as part of the phase.

1. Pick Slack from `s` five days running. `s` puts Slack first.
2. Alias `ps` → Photoshop. `ps` returns Photoshop above everything.
3. Type a query, stop, wait 200 ms. Top row does not move. Confirmed with a
   deliberately slowed Source.
4. Recents appear, always below apps, never above.
5. `bluetooth` and `display` each reach a settings page, below any application
   that matches the same letters.
6. A control panel task launches from the Palette.
7. Desktop shortcuts add exactly one Entry on the dev machine (After Effects)
   and no duplicate row appears for Discord, Spotify, Chrome, Steam, Epic Games
   Launcher, NVIDIA App, R or Helium.
8. **Epic, if a game is installed** — blocked on the dev machine, see task 9.
   Name appears, Enter launches it, and the Entry survives moving the library
   folder because the id is the catalog GUID rather than the path.
