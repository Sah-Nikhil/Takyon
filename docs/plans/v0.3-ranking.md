# v0.3 Ranking that learns

Palette starts guessing right before you finish typing.

## Read first

v0.2 done. `IMPLEMENTATION_PLAN.md` §3 (Frecency, Stability). `CONTEXT.md` for
both terms.

## Tasks, in order

1. **`frecency.db`.** Schema in `IMPLEMENTATION_PLAN.md` §4. Written on every
   activation, keyed by `EntryId`.
2. **Decay.** `weight = Σ 0.5^(age_days / 30)`. Store decayed value plus
   `decayed_at`, re-decay lazily on read. No background job, no clock-skew bug.
3. **Score composition.** Match tier from v0.2, multiplied by Frecency weight.
4. **Kind ordering, applied after scoring.** Apps always above documents. Never
   interleaved by raw score. This is a product rule, not a tuning knob.
5. **Stability lock:**
   ```rust
   struct StabilityLock { query: String, top: EntryId, locked_at: Instant }
   ```
   100 ms after last keystroke, current top `EntryId` locks for that exact query
   string. Later results append below, never displace. New keystroke clears lock.
6. **Aliases.** Resolved before matching, from `settings.db`. Alias exact match
   outranks everything.
7. **Recents Source.** Shell recent-items list, no index, cheap. Always below
   apps.

## Traps

**Stability lock is the phase.** Without it a late Source inserts above your
selection in the 20 ms between eye and finger, and you launch the wrong thing.
Unit test it the day it exists. Test case: lock top, deliver a higher-scoring
Entry 50 ms later, assert top unchanged and new Entry appended.

Frecency keyed on an unstable `EntryId` silently resets on every app update. If
`vsc` stops finding VS Code after an update, this is why.

Decay half-life of 30 days is a guess. Tune from real use, not from theory.

Recents come from the shell, so they include files opened by any app. Do not
assume they are yours.

## Exit criteria

After a week of real use, your ten most-used apps each reachable in one or two
keystrokes.

## Manual verification

1. Pick Slack from `s` five days running. `s` puts Slack first.
2. Alias `ps` → Photoshop. `ps` returns Photoshop above everything.
3. Type a query, stop, wait 200 ms. Top row does not move. Confirmed with a
   deliberately slowed Source.
4. Recents appear, always below apps, never above.
