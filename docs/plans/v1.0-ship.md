# v1.0 Ship

Someone who is not you installs it and uses it for a week.

## Read first

ADR-0010 (zero telemetry), ADR-0020 (identity slug), TBC-0002 (the
warm-window bet, now resolvable with real numbers), `docs/brand.md`.

## Tasks, in order

1. **Installer.** NSIS. Must install to a trusted location, because UIAccess
   requires it — `C:\Program Files\Takyon`, the path
   `scripts/dev-sign-uiaccess.ps1` already assumes. That is a per-machine install,
   which is a change from today's per-user default and pulls two things with it:
   the uninstall hook still writes to `HKCU` (the `Run` value is per-user even when
   the app is not), and the install path now contains a space.
1b. **Quote the `Run` value.** The space in `Program Files` is what makes this
   task 1's problem rather than a footnote. `auto-launch` 0.5.0 writes
   `format!("{} {}", app_path, args.join(" "))` with no quotes, so the value
   becomes `C:\Program Files\Takyon\takyon.exe` and starts only by the
   CreateProcess ambiguity heuristic. Rewrite it quoted immediately after every
   successful `enable()` — the Settings switch, the first-run prompt, and
   `tray::self_heal_autostart`, which would otherwise unquote it again at the next
   launch. `is_enabled()` tests only that the value exists, never its contents, so
   quoting is invisible to the plugin. Detail in [`../tbd/v0.1.md`](../tbd/v0.1.md)
   §4.
2. **Code signing.** Already needed at v0.1 for UIAccess, so this is verification
   rather than new work. Confirm the uninstall hook removes **both** values it
   names — `...\Run\com.v3sper.takyon` and
   `...\Explorer\StartupApproved\Run\com.v3sper.takyon`. `auto-launch`'s
   `disable()` clears only the first, so the second is ours to delete or it
   outlives the application.
3. **Updater.** `tauri-plugin-updater`, feed keyed on `com.v3sper.takyon`, not
   on the display name.
4. **First run.** Hotkey introduction, autostart prompt, index roots confirmation.
   Short. A launcher that opens with a wizard has already lost.
5. **Crash logs.** Written locally, settings button opens the folder, nothing is
   ever sent. State that plainly in the README.
6. **Full benchmark pass on a cold machine.** All four budgets plus `!e` p95.
   **Login → hotkey responsive is the one `bun run bench` cannot measure**: it
   launches the binary by hand on an idle desktop, which is not the same machine
   as one where Explorer, OneDrive and every other startup app are competing for
   the disk. v0.1 measured 311.6 ms against a 500 ms budget that way, and
   `docs/verify/v0.1.md` E3 checks the login case only by eye. Get a number:
   timestamp the hotkey registration against the session's logon time, on the VM,
   after a real reboot.
7. **Resolve TBC-0002.** Write the real numbers in, then mark it resolved or
   triggered. If triggered, the verdict section already says what to do.
8. **Redraw the timing chart from real bench output.** The current numbers in
   `docs/brand.md` are budgets, not measurements. Publishing them as measured
   would be a lie.
9. **Licence decision.** Open source or proprietary. It has been open the whole
   project and it constrains dependencies.

## Traps

The `Run` key must not survive uninstall. Test the actual uninstaller, not the
dev path, and check both values (task 2).

Moving from a per-user to a per-machine install is exactly the case
`tray::self_heal_autostart` exists for: a `Run` value left pointing at
`%LOCALAPPDATA%\Takyon` after the binary moved to `Program Files`. It self-heals on
the first launch — but the first launch after the move is the *next login*, which
is the one that fails. Anyone upgrading in place gets one dead login. Decide
whether the installer re-registers, or accept it and say so.

An MSIX identity change forces every user to reinstall and loses their data.
`com.v3sper.takyon` is fixed as of ADR-0020, which took the one rename this slug
will get while no user and no signature depended on it. There is no second one.

SmartScreen reputation accrues per signed binary. Early installs will warn.
Expect it, do not panic and re-sign under a different name.

Shipping telemetry in the same release as the privacy promise would undermine
both. Post-V1, opt-in, and its own ADR (ADR-0010).

## Exit criteria

A person who is not you installs it, uses it for a week, and does not go back to
what they used before.

## Manual verification

1. Clean Windows VM, install, reboot, hotkey works at login. Read the `Run` value
   and confirm it is **quoted** (task 1b).
1b. Upgrade in place from a per-user install with autostart on, reboot twice. The
   first login is the one that can fail; the second must not.
2. Palette appears over an elevated terminal (UIAccess proof).
3. Uninstall. No `Run` key, no leftover data unless the user chose to keep it.
4. Update from the previous version, confirm settings, Frecency and clipboard
   history all survive.
5. Benchmark on the VM, not the dev machine.
