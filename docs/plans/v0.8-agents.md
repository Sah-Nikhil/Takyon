# v0.8 Agents

Ask a question from the hotkey, get an answer in place. Three Agents behind one
Bang: Claude Code, Codex, opencode.

## Read first

ADR-0001 (launcher first, lazy Promotion), ADR-0017 (Agents are driven, never
authenticated), TBC-0012 (why sign-in is delegated), `CONTEXT.md` §Agents for the
vocabulary, `docs/plans/bang-registry.md` for why there is one `!c` and not three
Bangs.

## Decisions taken before the build

The four questions this plan was parked on are answered. So is a fifth the
original plan did not know it had.

**Three Agents, one trait.** T3 Code (`pingdotgg/t3code`, MIT) is the reference
for the surface and the shape. Its `ProviderDriver` SPI — a driver is a plain
value, the thing it makes is a record of captured closures, and one registry
holds them all — comes across as the `AgentDriver` trait with a registry of boxed
drivers. Its vocabulary does not: `CONTEXT.md` already lists "provider" under
*avoid* for two existing terms, so a driver serves an **Agent**.

**Sign-in is the Agent's own business** (ADR-0017). Takyon probes and explains,
exactly as T3 Code does for its five CLI-backed drivers. It never runs a login,
never writes a credential file, never holds a token. The terminal-launching
version of the button is TBC-0012's amendment, not this phase.

**The Agent is a preference, not a Bang.** `!c` means "ask the agent". Which one
answers is a setting, switchable for a single query from `Ctrl+K`. The two
rejected alternatives are written down in `bang-registry.md`.

**One window.** A follow-up continues in the Palette; there is no second window.
The Chat Surface is the Palette *showing a conversation*, which is what
`CONTEXT.md` now defines it as. The tools rule survives the collapse by moving
from the window to the Turn: the first answer has tools off, every follow-up has
them, because a follow-up is an explicit act and the first answer is a reflex.

**The model and effort are locked in Settings.** One pair per Agent, picked from
what that Agent itself reports, and it is the only pair a Turn can use — no
per-query override, and `agent_ask` reads both from `settings.db` rather than
taking them from the frontend (ADR-0017).

**Every Turn runs in the Scratch directory unless the user chose otherwise.**
`%LOCALAPPDATA%\v3sper\launcher\scratch\`, created empty. Settings can name a
default directory. An Agent pointed somewhere the user did not choose must find
nothing there.

**Fresh process per Turn, resumed by session id.** Not one long-lived process per
conversation. All three CLIs persist sessions and all three take a resume flag,
so the resumed process is the cheap path *and* the crash-proof one — a
conversation that survives a killed subprocess is worth more than the startup a
warm process would save, and `--input-format stream-json` exists on only one of
the three anyway. Revisit if measured first-token latency on a resumed Turn exceeds
1.5 s.

## What each Agent actually speaks

Verified against the installed CLIs (`claude` 2.1.261, `opencode` 1.18.27) and
against `openai/codex`'s own `cli.rs`, not against documentation.

| | Sign-in probe | Turn | Resume | Working directory | Tools off |
|---|---|---|---|---|---|
| Claude | `claude auth status --json` | `claude -p <prompt> --output-format stream-json --verbose` | `--resume <id>` | process cwd | `--tools ""` |
| Codex | `codex login status` | `codex exec --json --skip-git-repo-check` | `codex exec resume <id>` | `-C <dir>` | `--sandbox read-only` |
| opencode | `opencode models` | `opencode run --format json` | `-s <id>` | `--dir <dir>` | `--agent plan` |

And the locked pair, which each Agent spells its own way:

| | Model list | Model | Effort | Effort levels |
|---|---|---|---|---|
| Claude | none — `--model` aliases | `--model` | `--effort` | low · medium · high · xhigh · max |
| Codex | `codex debug models --bundled` | `-m` | `-c model_reasoning_effort="…"` | none · minimal · low · medium · high · xhigh · max · ultra |
| opencode | `opencode models` | `-m` | `--variant` | minimal · high · max |

**Claude is the one without a models command.** Its `--model` help documents
aliases — `opus`, `sonnet`, `haiku`, `fable` — and an alias always resolves to the
latest of its family, so the picker offers those rather than a bundled catalogue
that would go stale between releases. **Codex spells effort as a config key**,
not a flag, so it is overridden per run with `-c`. **opencode calls it a
variant**, and its three levels are not Claude's five — which is why the
vocabulary is per Agent rather than one shared enum, and why Settings refuses a
level the chosen Agent does not accept.

**Claude's probe is a gift.** `claude auth status --json` returns
`{loggedIn, authMethod, apiProvider, email, subscriptionType}` in one cheap call.
T3 Code reaches the same three facts by running a query through the Agent SDK and
reading its init result, because the SDK is what it already had. We do not have
the SDK — Takyon is Rust — and we do not need it.

**Codex's probe is an exit code.** `codex login status` writes its answer to
**stderr** and exits 0 or 1: `Logged in using ChatGPT`, `Logged in using an API
key - sk-…`, or `Not logged in`. Read the code, show the line as the label, never
parse the line for meaning.

**opencode has no sign-in to read**, so T3 Code counts connected upstream
providers instead and calls one or more "authenticated". We copy that, from
`opencode models`: the distinct provider ids in its output. Note what this means
— opencode ships free `opencode/*` models that need no credential, so a fresh
install reports one connected provider and answers questions. That is not a bug
in the probe. "Can this Agent answer right now" is the question worth asking.

**Tools-off is not the same word in three CLIs.** Claude has a real switch
(`--tools ""` removes the built-in set). Codex and opencode do not; the closest
each has is a read-only posture. The Scratch directory is what makes the
difference immaterial — a read-only Agent in an empty directory can read an empty
directory. Do not paper over the asymmetry in the code; name it at each driver.

## Tasks, in order

1. **`agents/mod.rs` — the `AgentDriver` trait and the registry.** `AgentKind`
   (`claude`, `codex`, `opencode`), `Snapshot` (installed, version, Sign-in
   state, message), and a registry holding one boxed driver per kind. Nothing
   Agent-specific may exist outside a driver file; that rule is what makes a
   fourth Agent a new file rather than a search-and-replace.
2. **`agents/probe.rs` — spawning, with a timeout that is not optional.** Resolve
   the binary on `PATH` and in the documented install locations, because a
   `bun add -g` binary is not always on a GUI app's inherited `PATH`. Spawn with
   `CREATE_NO_WINDOW`, collect stdout and stderr, kill on timeout. Every driver
   goes through this; no driver spawns its own process.
3. **The three drivers.** `claude.rs`, `codex.rs`, `opencode.rs`, each
   implementing the probe and the Turn against the table above.
4. **`agents/turn.rs` — the streaming Turn.** Spawn, read stdout **line by
   line**, parse each complete line as JSON, map it to a `TurnEvent`, emit to the
   frontend. Buffer until newline; a half-line rendered as text is the classic
   bug in this shape of code and it is in Traps for a reason.
5. **`agents/scratch.rs`.** Create and return the Scratch directory. Empty, and
   asserted empty by a test.
6. **Prefs and IPC.** `agents.default`, `agents.cwd`, `agents.model.<kind>`,
   `agents.effort.<kind>`. The commands: `agent_snapshots`, `agent_models`,
   `agent_ask`, `agent_cancel`. Snapshots are their own command, never a field on
   `QueryResult` — Sign-in state changes on the Agent's schedule, not the
   user's, which is the argument `file_index_status` won at v0.7. `agent_models`
   is its own call again, because it costs a spawn and only Settings needs it.
7. **The `!c` Mode.** `bang::Route::Ask`. An empty query shows which Agent will
   answer and its Sign-in state; a query streams an inline answer into the
   Palette with tools off.
8. **Sign-in surface, copied from T3 Code.** A status dot, a headline built from
   installed + enabled + Sign-in state, and the Agent's own message underneath.
   The strings are T3 Code's, adapted: `Not found`, `Not authenticated`,
   `Authenticated · <label>`, `Needs attention`, `Unavailable`. A signed-out
   Agent gets one line in the Palette and nothing else — no dialog, no retry.
9. **The Chat Surface, in the Palette.** Promotion on the first follow-up turns
   the answer view into a transcript and turns tools on. No second window: one
   launcher window holds everything, and Escape goes back to the search line.
10. **Settings → Agents page.** One card per Agent: status dot, headline,
    message, version, and — for an Agent that can actually answer — a **model
    picker and an effort picker**, both lists rather than text fields, both
    populated from that Agent. An Agent that is missing or signed out gets no
    pickers, because a model list for a CLI that cannot answer is a control that
    cannot mean anything. No Sign in button (ADR-0017).

## Traps

**Streaming JSON means partial lines.** Buffer until newline. A half-parsed event
rendered as text is the classic bug here, and it is worse than it sounds: the
first thing the user sees is a fragment of JSON where an answer should be.

**A conversation lives as long as the Palette does.** One window means dismissal
ends it, which is the honest consequence of collapsing the two surfaces and is
recorded as such in `docs/tbd/v0.8.md` §3. Escape goes back one step; only a
second Escape, or a focus loss, ends the conversation.

**`claude` startup is not free.** First-token latency on the inline path is what
people will judge. It does not belong to the 50 ms budget, but a Bang that takes
four seconds to say anything has to say *something* in the first hundred
milliseconds.

**Escape must not kill an in-flight Turn.** Over a conversation it goes back one
step, exactly as it does over `!v`. Only `agent_cancel` stops a Turn.

**A spawned console flashes.** Every spawn needs `CREATE_NO_WINDOW`, or a
launcher whose whole promise is "appears in tens of milliseconds" blinks a black
box on every probe.

**Probing three Agents costs three process spawns.** Probe lazily — on the first
`!c` and on Settings mount — never on the login path. The 500 ms login budget has
nothing to spare and none of this is needed before the first question.

**`PATH` in a GUI process is not `PATH` in a shell.** A binary installed by
`bun add -g` or `npm i -g` after login can be invisible to an already-running
Takyon. "Not found" must be recoverable by re-probing rather than by restarting.

## Exit criteria

A question answers inline in the Palette. A follow-up promotes into a Chat
Surface in the same window, with tools on. Escape goes back one step rather than
destroying a conversation. All three Agents report an accurate Sign-in state, a
signed-out one says what to run, and an authenticated one offers a model and an
effort level that lock for every Turn.
