# v0.4 Calculator and converter

Second reflex after launching. Small phase.

## Read first

v0.3 done. ADR-0002 (Bangless never touches network). That ADR constrains
currency conversion specifically.

## Tasks, in order

1. **`sources/calc.rs`.** Inline expression evaluation. Arithmetic, parens,
   percent, exponent. Pick a Rust expression crate rather than hand-rolling a
   parser.
2. **Detection.** Input that parses as an expression yields a Calc Entry at rank
   top. Input that does not parse yields nothing, silently. No error rows in a
   launcher.
3. **Enter copies the result** to clipboard, Palette dismisses.
4. **Unit conversion.** Length, mass, temperature, data, time. Static tables,
   fully offline.
5. **Currency.** Needs live rates, so it leaves the machine. Bang-gated or
   explicitly opt-in with a default-off setting. Never on the Bangless path.

## Traps

**Currency is the ADR-0002 trap of this phase.** `100 usd to inr` on the Bangless
path is a network request, which breaks the product's central promise. Either put
it behind a Bang or behind an off-by-default setting. Not both, and never
neither.

Expression detection must be conservative. `1password` is not arithmetic. A
greedy parser turns app searches into calculator results.

Cache currency rates with a visible timestamp. A stale rate presented as current
is worse than no rate.

## Exit criteria

You stop opening a calculator app. `12*1.18` and `40 kg to lb` both answer
inline, both offline.

## Manual verification

1. `12*1.18` → 14.16, Enter copies it.
2. `40 kg to lb` → 88.18 lb, no network request (verify with a network monitor).
3. `1password` → the app, not a calculation.
4. Currency with the setting off → no result and no request.
