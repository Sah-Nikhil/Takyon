# v0.16 Focus

A Focus session blocks the apps and websites you name for as long as you say,
modelled on Raycast Focus and built without elevation, a service, a browser
extension or a network request.

**Driver: asked for by name.** The user wants Raycast Focus on Windows: a goal, a
duration, and a Block list of apps, websites and Focus categories, with snooze,
pause, early completion and a floating bar that keeps the goal in view. This
plan is the outcome of the 2026-10-06 design session. Every decision below was
made by the user in that session, and the ones that outlive this phase are
recorded in ADR-0035 and ADR-0036.

Comes after v0.15 and does not depend on it. It touches none of the Agent, macOS
or index seams, so it could move earlier without rework. It is not a v1.0
blocker.

**Windows only.** macOS refuses Focus in words, like the other unported rows,
until the port reaches it. § macOS records what the port will need.

## Design

### Surfaces

**Palette Entries.** A new Source, `sources/focus.rs`, answers Bangless queries
with Entries: Start Focus Session, and while one runs, Complete, Pause or Resume,
and Edit. It reads only local state, so it obeys ADR-0002 trivially.

**The start form.** Enter on Start Focus Session opens a form view inside the
Palette, in the same way the Ask view replaces the list. Fields: Goal, Duration,
Block list, Strict. The Block list field is a chip picker. Typing searches Focus
categories and installed applications (through the existing apps Source) and
always offers a last row, "Block website: <text>". `Ctrl+Enter` starts. Before
starting, the form lists anything it cannot block, with the reason in words:
"Can't block Process Hacker: runs as administrator", "Can't block sites in Opera
GX: browser not supported".

**`!f`.** An optional Bang, off by default, switched on in Settings → Focus.
`!f write report 45m` or `!f write report until 4:30pm` starts a session with the
last Block list. The duration is parsed from the end of the line; whatever is
left is the goal. With no duration, Enter opens the start form pre-filled.

**The floating bar.** A small always-on-top window that never takes focus. It
sits top centre, can be dragged, and remembers where it was left. It shows the
goal and the time left; Pause and Complete appear on hover. When something gets
blocked it pulses in `accent` and shows "Discord blocked · Snooze 3m" for five
seconds. It is created when a session starts and destroyed when it ends, never
left hidden between sessions. A setting collapses it into the tray instead: the
tray icon then flashes on a block, and its tooltip carries the countdown and the
last block line.

**Settings → Focus.** The page holds Snooze duration, Restore Terminated Apps,
the bar or tray choice, the `!f` switch, the two Strict hurdles, and the Focus
category editor: duplicate a built-in category, create, edit and delete custom
ones, import and export them as JSON. It also holds two **Coming soon** rows,
Scheduled sessions and Locked strictness, as static text.

**Settings → Focus / Stats.** A sub-view of the Focus page, opened from its
top row and titled with a breadcrumb (t3code's "Usage / All environments"),
not a sidebar page of its own. Laid out like t3code's usage page:
- a headline total of focused time with a per-Focus-category split;
- a daily focused-minutes line over a gradient area (monotone cubic, so it
  never dips below a zero day);
- a totals strip: sessions, completed, blocks, snoozes, Strict sessions;
- a breakdown table switching between most-blocked targets and by-day;
- 24 h / 7 d / 30 d / 90 d ranges.

The chart is hand-built SVG, like `Mark.tsx` and `Select.tsx`. No chart library,
and every colour comes from a theme role so `check:colours` stays green.

`pages.ts` currently says a page for an unbuilt feature is absent and that a
disabled row would be a dead control. The Coming soon rows are a deliberate,
user-chosen exception, and the rule is amended rather than broken: **a static,
non-interactive Coming soon line inside a page that otherwise works is
allowed; a disabled control is still not.** The `pages.ts` comment is updated in
the same change.

### Identity: what "an app" is

Custom picks are stored as the app's **`EntryId`**, the same string Frecency keys
on, so choosing an app in the form and blocking it agree by construction.
Built-in Focus categories cannot use `EntryId`s, because paths differ per
machine, so an item in Focus categories is one of:

| Key | Matches a running process when |
|---|---|
| `entry:<EntryId>` | Exe: the image path equals the path half of the id (arguments ignored). Aumid: `GetApplicationUserModelId` on the process returns it. Game: the image lies under the game's install directory |
| `exe:<name>` | The image file name equals it, case-insensitively (`discord.exe`) |
| `package:<family>` | The process's package family name equals it (Store apps such as WhatsApp) |
| `site:<domain>` | Not a process. Matches a URL whose host is the domain or a subdomain of it |

A game's install directory comes from its Game launcher's library data: Steam's
`appmanifest_*.acf` `installdir`, Epic's manifest `InstallLocation`.

**Never blocked, whatever the list says:** Takyon itself and its helper,
`explorer.exe`, `ShellExperienceHost`, `StartMenuExperienceHost`,
`TextInputHost`, `ctfmon.exe`, `dwm.exe`, `csrss.exe`, `winlogon.exe`, every
process in session 0, and `taskmgr.exe`. The list lives in one place,
`focus/protected.rs`, and the Allow list will reuse it.

### Blocking apps

**As built:** polled rather than hooked (foreground every 250 ms, process table
every 2 s), and tab restore after an early Complete runs on the browser's next
visit. `docs/tbd/v0.16.md` §3 and §4 say why.

All in the Rust host, on a dedicated `focus` thread with its own message loop.
None of it depends on the Palette being shown.

1. **At start**, a Toolhelp snapshot quits everything on the Block list that is
   already running.
2. **On foreground change**, `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`. A
   blocked app coming to the front is quit before it can be used.
3. **Every 2 s**, another snapshot, for apps that never come to the front: tray
   residents like Discord, and anything launched minimised.

**Quitting** sends `WM_CLOSE` to every top-level window the process owns, waits
2 s, and then calls `TerminateProcess` if it is still alive. `WM_CLOSE` first so
an editor can save. If `OpenProcess(PROCESS_TERMINATE)` fails with
`ERROR_ACCESS_DENIED`, the process is elevated or protected. It goes on the
"can't block" list in words and is not retried every two seconds.

**Restore Terminated Apps**, when on, relaunches at session end every app that
Focus quit, through its own `LaunchTarget`, once each, in the order they were
quit.

### Blocking websites

ADR-0035 in full. In short:

- **Supported browsers**, by image name: Chrome, Edge, Brave, Vivaldi, Opera,
  Arc (Chromium) and Firefox, Zen, LibreWolf, Waterfox (Gecko). Any other browser
  whose sites are on the Block list gets "can't block sites in <browser>" on the
  start form.
- **Reading.** While a session with sites runs and a supported browser is in
  front, poll that window's address bar through UI Automation every 500 ms. Read
  its `ValuePattern`, normalise the scheme-less display form to a host, and match
  it against `site:` items. Only the active tab is read. A blocked background tab
  is caught the moment it is activated, because activation changes the address
  bar.
- **Blocking.** Set the address bar's value to the block page and send Enter.
  The block page is
  `file:///<data>/focus/blocked.html?u=<original>&end=<unix-ms>&g=<goal>`, a
  local file that makes no request. Its title is always `Blocked · Takyon`.
  The source is `src-tauri/focus/blocked.html`, designed at the spike: the goal
  as the heading, the blocked host, a countdown, the mark, and the cone at room
  scale behind it. At session start Takyon writes a copy into the data
  directory with its `<style id="takyon-theme">` block replaced by the live
  family's half (plate, fg, accent), so the page matches the theme the user
  chose. The goal travels in the URL, so it lands in the browser's history;
  the start form says so in one line.
- **Restoring.** At session end, walk each supported browser's tab strip through
  UI Automation for tab items named `Blocked · Takyon`. Select each one, read its
  address bar, parse `u`, and navigate back. As a fallback for anything the walk
  misses, the page's own timer navigates to `u` once `end` has passed. When a
  session is completed early, the walk is the only route, and the page says "If
  this session has ended, reload" under the timer.

**Fallbacks**, in the order they would be tried if UI Automation stops working.
ADR-0035 has the reasoning:

| Fallback | Elevation | Cost |
|---|---|---|
| Browser extension + native messaging | none | Per-browser install, store review, a second codebase |
| `hosts` file entries | admin | Needs an elevated helper (amends ADR-0007); browser DNS caches delay it; some secure-DNS configurations may bypass it |
| Per-user proxy or PAC (HKCU) | none | A crashed Takyon leaves the user offline; collides with ADR-0019's use of the user's own proxy |
| WFP filter or DNS sinkhole | admin or service | Same as Locked (ADR-0036) |

### Strictness

ADR-0036 in full. Two levels in this phase, chosen per session on the form:

| | Soft | Strict |
|---|---|---|
| Snooze | allowed, 1/3/5/10 min or none, default 3 | none |
| Pause | free, 5/10/15/30 min | after friction |
| Complete early | free | after friction |
| Quit Takyon from the tray | ends blocking until relaunch | asks to confirm |
| After relaunch or reboot | the session resumes from `focus.db` | the session resumes from `focus.db` |
| Shutdown hurdle | off by default | on by default |
| Idle-sleep hurdle | off by default | on by default |

**Friction** means retyping the goal exactly and then waiting through a 30 s
countdown that resets if the Palette is dismissed.

**Snooze** covers one blocked target and leaves the session clock running. When
it expires, the app is quit the next time it loses the foreground, never while
it is being typed into. **Pause** covers the whole session and stops the clock.
When the break ends, the bar nudges and blocking resumes.

**The hurdles**, both switchable in Settings → Focus:

- **Shutdown, restart, sign-out.** `ShutdownBlockReasonCreate` on a window Takyon
  owns, and `FALSE` from `WM_QUERYENDSESSION`. Windows shows its full-screen
  "Takyon is preventing shutdown" with our reason, "Focus: write report, 23 min
  left", and its own Shut down anyway button. That button always wins; this is a
  hurdle, not a lock.
- **Idle sleep.** `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`
  from the `focus` thread for the length of the session, cleared at the end.
- **User-initiated sleep cannot be held.** Since Vista no application can veto
  it (`PBT_APMQUERYSUSPEND` is gone). Settings says so under the switches.

### Sleep and the clock

`WM_POWERBROADCAST`: `PBT_APMSUSPEND` pauses the session, and
`PBT_APMRESUMEAUTOMATIC` resumes it with the time left intact. A session's end
is therefore not a wall-clock instant. It is the planned length plus every pause.

### Storage

`focus.db`, WAL mode, alongside the others. Settings keys go in `settings.db`
through `prefs.rs`, like every other preference.

```sql
-- focus.db
CREATE TABLE categories (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  icon        TEXT NOT NULL,
  copied_from TEXT            -- built-in id it was duplicated from, or NULL
);
CREATE TABLE category_items (
  category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
  key         TEXT    NOT NULL,   -- entry:/exe:/package:/site:
  label       TEXT    NOT NULL,
  PRIMARY KEY (category_id, key)
);
CREATE TABLE sessions (
  id          INTEGER PRIMARY KEY,
  goal        TEXT    NOT NULL,
  strictness  TEXT    NOT NULL,   -- soft | strict (locked later, ADR-0036)
  block_list  TEXT    NOT NULL,   -- JSON: category ids, built-in ids, item keys
  started_at  INTEGER NOT NULL,
  planned_ms  INTEGER NOT NULL,
  paused_ms   INTEGER NOT NULL,   -- accumulated, sleep included
  paused_at   INTEGER,            -- set while paused
  ended_at    INTEGER,
  outcome     TEXT                -- completed | ended-early | expired
);
CREATE TABLE session_events (
  session_id  INTEGER NOT NULL REFERENCES sessions(id),
  at          INTEGER NOT NULL,
  kind        TEXT    NOT NULL,   -- blocked | snoozed | paused | resumed | refused
  target      TEXT                -- item key, NULL for pause/resume
);
-- settings.db keys: focus.snooze_minutes, focus.restore_apps, focus.surface
-- (bar|tray), focus.bar_position, focus.bang, focus.hurdle_shutdown,
-- focus.hurdle_idle_sleep, focus.last_block_list
```

**A running session is the row with `ended_at IS NULL`.** At most one. Deferred
init reads it right after the hotkey registers and resumes enforcement. That is
the whole crash-and-reboot story, and the reason Strict means anything.

**History is kept forever.** A session costs a few hundred bytes. Settings →
Focus has Clear Focus history, which deletes `sessions` and `session_events` and
runs `wal_checkpoint(TRUNCATE)`. Nothing here is sensitive in the clipboard's
sense, so no `secure_delete`. Goals are the user's own words and never leave the
machine (ADR-0010).

### Focus categories

**Built-in**, embedded with `include_str!` from
`src-tauri/src/focus/categories.json`, so there is no runtime file read and no
install-directory dependency:

| Id | Contents |
|---|---|
| `social` | X, Instagram, Facebook, Reddit, TikTok, Threads, Bluesky, LinkedIn, Pinterest: sites, plus Store and desktop apps where they exist |
| `messaging` | Discord, Slack, WhatsApp, Telegram, Signal, Messenger, Teams (personal): apps and web clients |
| `video` | YouTube, Netflix, Twitch, Prime Video, Disney+, Hulu, Max, Crunchyroll: sites and apps |
| `news` | A short, neutral set of major outlets and aggregators: Google News, BBC, NYT, The Guardian, Reuters, Hacker News |
| `shopping` | Amazon (regional domains), eBay, AliExpress, Flipkart, Etsy, Temu, Myntra |
| `games` | **Resolved at session start, not stored.** Every Entry whose `LaunchTarget` is `Game`, plus the Game launchers themselves: `steam.exe`, `EpicGamesLauncher.exe`, `GalaxyClient.exe`, `Battle.net.exe`, `EADesktop.exe`, `UbisoftConnect.exe`, `RiotClientServices.exe` |

The exact item list is written during the build and reviewed in the PR. It is
data, not design.

**Adding a built-in category is a JSON edit.** No Rust or TypeScript changes. A
unit test validates the file: unique ids, known key prefixes, no duplicate keys
within a category, and a non-empty label for every item. A typo fails CI, not the
app. New built-in categories reach users with releases. Through the v1.0 updater
is the post-v1 route; a remote feed is ruled out because it would be an outbound
request with no Bang behind it.

**Import and export** of custom Focus categories uses the same JSON shape,
through the Settings page's file picker. Importing a category whose name already
exists adds a suffix rather than merging.

**Agent classification** of unknown apps is later work, recorded in
`post-v1.md`. It would send installed app names to an Agent, which is an
outbound request with no Bang, so it needs its own ADR.

### Allow list (designed, not built)

The inverse of a Block list: everything is blocked except what is listed. Recorded
here so the Block list's data shape does not paint it into a corner.

- **Apps.** Every process that is not listed, not in `focus/protected.rs`, and
  owns a visible top-level window gets quit. Background processes with no window
  are left alone, or the allow list kills drivers' tray helpers and audio
  services the user never sees. `protected.rs` grows an "always allowed" tier:
  IMEs, accessibility tools (Narrator, NVDA), password managers' system tray
  processes, and the shell.
- **Websites.** A browser on the allow list with no sites listed allows every
  site, which is Raycast's "Allow all websites". With sites listed, any other
  host goes to the block page.
- **Data.** `sessions.block_list` becomes `sessions.list` with a `kind` of
  `block` or `allow`. That is the only schema change, so the column name is
  chosen now: v0.16 writes `{"kind":"block", ...}` inside the JSON from day one.
- **Why later.** Getting the always-allowed tier wrong logs the user out of their
  own input method. It needs its own verify section on a machine with an IME.

## Traps

- **UI Automation trees change with browser releases.** Chromium's address bar
  is found by `ClassName` `OmniboxViewViews`, not by its localised name or its
  per-build `AutomationId`. Gecko's is `urlbar-input` by `AutomationId`. Both
  were confirmed by the spike (ADR-0035 § Spike result). Both lookups get a live test
  against an installed browser (`--ignored`, as `web_search` does), and CI's
  daily job runs it so a browser update that breaks it is caught in a day.
- **Never act while the address bar has keyboard focus.** A half-typed `youtu`
  is the bar's value while the user types. Skip the tick when
  `HasKeyboardFocus` is true or the value is empty, and re-find the element on
  an empty read, because Gecko's goes stale while focused.
- **The displayed value has four shapes** (scheme, no scheme, host only, bare
  drive path for `file:`). Host extraction and the `u=` parse are unit-tested
  against each, taken verbatim from ADR-0035's table.
- **An image name is not a browser's identity.** Helium installs as
  `chrome.exe`. Detection by image name is still right, because the engine and
  the lookup are the same, but UI copy names the browser from the exe's
  version-info `ProductName`, never from the image name.
- **An elevated browser cannot be read.** UIPI blocks UI Automation into a
  higher-integrity process. The UIAccess helper is not a fix: it only foregrounds.
  It gets the same "can't block sites" line as an unsupported browser.
- **`ES_CONTINUOUS` is per thread.** Call `SetThreadExecutionState` from the
  long-lived `focus` thread, never from a Tauri command thread that exits.
- **`ShutdownBlockReasonCreate` needs a top-level window the process owns** and
  `WM_QUERYENDSESSION` arrives at window procedures. Subclass the floating bar's
  HWND, or a hidden message-only window on the `focus` thread if the bar is
  collapsed to the tray. A message-only window does not receive
  `WM_QUERYENDSESSION`, so in tray mode it has to be a real hidden top-level
  window.
- **The floating bar is a second webview.** It may get its own WebView2 renderer
  process. The 150 MB idle RSS budget is measured with no session running, so it
  does not move, but RSS during a session is measured and written into
  `docs/tbd/v0.16.md` regardless. If it is heavy, the bar becomes a native
  layered window drawing two lines of text, which `docs/tbc/0002` already
  contemplates for the Palette.
- **Create the bar off the main thread.** `WebviewWindowBuilder::build()` from
  the main thread deadlocks with a white rectangle. `settings::open`'s pattern.
- **`WS_EX_NOACTIVATE` is not a Tauri option.** Set it with `SetWindowLongPtrW`
  after creation, and set `focused(false)` on the builder, or the first show
  steals focus from whatever the user is typing into.
- **Sending Enter into a browser.** Only after confirming that the browser is
  still the foreground window and the address bar has focus. Otherwise the
  keystroke lands in whatever replaced it.
- **Matching an `EntryId` with arguments.** `path|args` blocks the path. Two
  shortcuts to one exe with different arguments are one blocked app.
- **UWP processes run under `ApplicationFrameHost.exe` windows.** `WM_CLOSE`
  goes to the frame window. The app's own process is what gets terminated, found
  through its package family name.
- **Never block what started the session.** The Palette, the bar, Settings and
  the UIAccess helper are all in `protected.rs`, and a Block list that names
  Takyon is refused with a message rather than silently filtered.

## macOS

Not built in this phase. What the port will need, so v0.12's hand-off table can
pick it up:

- App blocking: `NSWorkspace` `didActivateApplicationNotification` and
  `didLaunchApplicationNotification`; `NSRunningApplication.terminate()`, then
  `forceTerminate()`. Bundle identifier replaces `exe:` and `package:`.
- Websites: AppleScript for Safari and Chromium browsers (tab URL read and set),
  Accessibility for Firefox. Each browser asks for Automation permission on first
  use, which is a first-run copy problem.
- Idle sleep: `IOPMAssertionCreateWithName(kIOPMAssertionTypePreventUserIdleSystemSleep)`.
- Shutdown hurdle: `applicationShouldTerminate` returning `.terminateLater`
  during a logout, which macOS reports as "Takyon cancelled logout".
- Sleep: `NSWorkspace.willSleepNotification` / `didWakeNotification`.

## Exit criteria

On this machine, with a release build: a Soft session blocks Discord and
youtube.com, Discord is quit at start and on relaunch, youtube.com in Chrome and
in Firefox goes to the block page and comes back to the same URL when the session
completes, Snooze lets Discord back for three minutes, and Pause lets everything
through until the break ends. A Strict session survives killing Takyon in Task
Manager and a reboot, resuming with the right time left, and the shutdown hurdle
shows its reason. Focus stats shows that history. Nothing in any of it makes a
network request.
