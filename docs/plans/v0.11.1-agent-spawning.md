# v0.11.1 Agent spawning

Agents that install as `.cmd` shims, and Agents that die with the Palette.

**Driver: a test laptop.** opencode installed through npm, `!c who directed
titanic`, and the Palette said:

```
Could not start opencode: batch file arguments are invalid
```

Every Agent installed through npm is broken the same way, and this machine never
saw it because all three of its Agents are real executables. Auditing the spawn
path to explain it turned up a second defect that matters more: **cancelling a
Turn does not reliably stop the Agent**, and dismissing the Palette can leave one
running. The product rule this plan enforces is that every process `!c` or `!s`
starts is gone the moment the Palette hides. Nothing survives between summons.

A patch release, following v0.10.1's precedent. It keeps v0.8's shape — a fresh
process per Turn, resumed by session id — and changes how that process is
started, fed and stopped. Streaming for Codex and opencode and a permission UI
need a different transport altogether, and are
[`v0.15-agent-streaming.md`](./v0.15-agent-streaming.md).

## The problem, precisely

### 1. A multi-line argument to a `.cmd` is refused before anything starts

`npm i -g opencode-ai` puts `%APPDATA%\npm\opencode.cmd` on `PATH`: a batch file
that runs `node`, which runs the platform binary. `probe::resolve` accepts `.cmd`
deliberately (`EXTS` in `probe.rs`), because half the installs in the wild have
no `.exe`.

Every driver passes the prompt as the last argument. `styled_prompt` builds it as
`"{ANSWER_STYLE}\n\n{prompt}"`, and `!s`'s `synth::prompt` is roughly 26,000
characters over many lines.

When the program is a `.bat` or `.cmd`, Rust's standard library builds a
`cmd.exe /e:ON /v:OFF /d /c` command line through `make_bat_command_line`
(`library/std/src/sys/args/windows.rs`). That function is the fix for
CVE-2024-24576 ("BatBadBut"), and it refuses any argument containing `\r` or
`\n`, returning `io::ErrorKind::InvalidInput` with the message
`batch file arguments are invalid`. `turn.rs` wraps it as
`Could not start {label}: {e}`, which is the message on the laptop, character for
character.

| Agent via an npm `.cmd` | `!c` first Turn | `!c` follow-up | `!s` |
|---|---|---|---|
| opencode | always fails — the style prefix has `\n\n` | never reached | always fails |
| Codex | always fails — same prefix | never reached | always fails |
| Claude | works for a one-line question; a pasted multi-line one fails | same | always fails |

The Settings card says Ready throughout, because the probes (`--version`,
`models`, `login status`) have no line breaks. That false green is why the report
came from a person rather than the product.

**argv has ceilings as well.** `CreateProcessW` takes at most 32,767 UTF-16 units
and `cmd.exe` 8,191 characters. `!s`'s prompt is past the second and close to the
first once quoting is added. Moving the prompt off the command line fixes both
with the newline rule.

### 2. Cancelling a Turn kills the wrong process

`Turns::cancel` calls `Child::kill`, which is `TerminateProcess` on the process
Takyon created. For a `.cmd` that is `cmd.exe`. Windows does not kill children
with their parent, so `node` and the real Agent carry on — still streaming, still
spending the user's tokens, with nobody reading the pipe. bun's `.exe` shims in
`~/.bun/bin` are launchers too (`opencode.bunx`, `codex.bunx` sit beside them),
so the same may hold on this machine; unverified.

There is no Job Object anywhere in the crate.

### 3. Dismissing the Palette can leave a Turn running

Dismissal reaches a Turn only through React: `Palette.tsx`'s `onHide` clears the
Ask view, `useTurn` unmounts, and its cleanup calls `agentCancel`. Three races get
past that:

- **Hide while `agent_ask` is in flight.** `useTurn` sets `active.current` only
  when the invoke resolves, so the unmount cleanup sees `null` and cancels
  nothing. The Turn starts after the Palette has gone.
- **A `!s` whose Turn starts after hide.** The search thread fetches pages first;
  `web_cancel` stops it between steps, but a hide that lands after the last check
  still starts a Turn.
- **Cancel between spawn and registration.** `Turns::run` spawns, starts the
  stderr thread, and only then inserts the child into `running`
  (`turn.rs:116-140`). A cancel in that window finds nothing.

And if Takyon itself crashes or is killed, every child survives.

### 4. Smaller things found on the way

- **`.ps1` is in `EXTS` and can never be spawned.** `CreateProcessW` refuses a
  script with os error 193, "%1 is not a valid Win32 application". npm and pnpm
  always write a `.cmd` beside it, so the `.ps1` entry is dead at best and a
  misleading "Could not start" at worst.
- **The last-resort directories miss three common installers**: Volta
  (`%LOCALAPPDATA%\Volta\bin`), the Node installer (`%LOCALAPPDATA%\Programs\nodejs`)
  and scoop (`%USERPROFILE%\scoop\shims`).
- **Errors are strings.** A failed spawn is a raw `io::Error`, a failed Turn is
  the last of stderr. A `.cmd` whose `node` is missing exits 9009 with
  "'node' is not recognized as an internal or external command", which reads as
  noise rather than as "reinstall Node".
- **Claude arrives a message at a time.** `parse_line` renders whole `assistant`
  messages; the CLI can send token deltas and is not asked to.

## What t3code does, read from the source

**Every spawn goes through one function.** `resolveSpawnCommand` in
`packages/shared/src/shell.ts` resolves the command against `PATH` × `PATHEXT`
(falling back to `.COM .EXE .BAT .CMD`). If the result is a `.cmd` or `.bat` it
spawns with `shell: true` and escapes every argument the way cross-spawn does;
otherwise it spawns directly.

**No prompt ever goes on the command line.** The one-shot generators write it to
stdin:

- `ClaudeTextGeneration.ts:199-229` — `claude -p --output-format json … --tools ""`
  with `stdin: { stream: Stream.make(prompt) }`
- `CodexTextGeneration.ts:196-229` — `codex exec … -s read-only … -`, prompt on stdin
- opencode is not driven through `run` at all; that is v0.15's subject

**Windows not-found detection.** `processRunner.ts`'s `isWindowsCommandNotFound`
treats exit code 9009, or stderr matching "is not recognized as an internal or
external command" in six languages, as the command being missing.

**Known CLI directories.** `resolveKnownWindowsCliDirs`: `%APPDATA%\npm`,
`%LOCALAPPDATA%\Programs\nodejs`, `%LOCALAPPDATA%\Volta\bin`,
`%LOCALAPPDATA%\pnpm`, `~\.local\bin`, `~\.bun\bin`, `~\scoop\shims`.

**Fixtures.** `apps/server/src/provider/testFixtures/codexCollabMockPeer.cmd` —
a fake Agent written as a `.cmd`, so the shim path is tested rather than assumed.

### What is taken, and what is not

| t3code | Taken? | Why |
|---|---|---|
| Prompt on stdin | **Yes** | It is the fix |
| `PATHEXT`-driven candidates | **Yes** | Drops `.ps1` without special-casing it |
| Known CLI directories | **Yes** | Volta, `Programs\nodejs`, scoop added to `extra_dirs` |
| `isWindowsCommandNotFound` | **Yes** | Becomes the `launcherBroken` failure |
| `.cmd` fake-peer fixtures | **Yes** | The test that would have caught this |
| `escapeWindowsShellArg` + `shell: true` | **No** | A Node workaround: Node refuses to spawn `.cmd` at all since 20.12 (`spawn EINVAL`). Rust's standard library already routes `.cmd` through `cmd.exe` and escapes safely. A hand port would go through `raw_arg` and reopen BatBadBut |
| `ClaudeExecutable.ts` (follow `claude.cmd` to `node_modules/@anthropic-ai/claude-code/bin/claude.exe`) | **No** | t3code needs it because the Agent SDK cannot spawn a shim. With the prompt on stdin and a Job Object, all it would save here is the `cmd.exe` and `node` hop, and it depends on each package's folder layout. Revisit if `bun run bench` ever shows that hop |

## Design

### 1. The prompt travels on stdin

The `AgentDriver` SPI splits in two:

```rust
/// The arguments for one Turn. **Never** the prompt: a `.cmd` refuses a line
/// break in argv, and `!s`'s prompt is past `cmd.exe`'s length limit.
fn turn_args(&self, req: &TurnRequest) -> Vec<String>;

/// What the Turn writes to the Agent's stdin. Default: `styled_prompt(req)`.
fn turn_input(&self, req: &TurnRequest) -> String;
```

Each CLI spells "read the prompt from stdin" differently, checked against the
installed help and opencode's source:

| Agent | Spelling | Source |
|---|---|---|
| Claude | `-p` with no positional prompt | `claude --help`: `--input-format` defaults to `text` |
| Codex | a trailing `-`, for `exec` **and** `exec resume <id>` | `codex exec --help`; `resume` reads stdin **only** with an explicit `-` |
| opencode | no message argument | `run.ts`: `process.stdin.isTTY ? undefined : await Bun.stdin.text()` |

Claude overrides `turn_input` to return the bare prompt, because its style already
travels in `--append-system-prompt`, which is one line.

`turn.rs` gains `pub fn spawn(driver, exe, req) -> io::Result<Spawned>`, which
builds the command through `probe::command`, sets `Stdio::piped()` for stdin, and
starts a writer thread that writes the input as UTF-8 and then **drops the
handle**. `Turns::run` calls it; integration tests call it too, so they exercise
the real spawn path rather than a copy.

`probe.rs` gains `run_with_input(exe, args, input, timeout)`; `run_command` takes
an `Option<String>` and keeps `Stdio::null()` when it is `None`, so probes are
unchanged.

### 2. Agent processes die with the Palette

New module `agents/job.rs`. Every Agent process, Turn or probe, is spawned through
it.

**Windows: one Job Object per spawn.**

1. `CreateJobObjectW`, with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` set and no
   breakaway allowed.
2. Spawn with `CREATE_SUSPENDED | CREATE_NO_WINDOW`.
3. `AssignProcessToJobObject`.
4. Resume the one thread. `std::process::Child` exposes the process handle but
   not the thread handle, so find it with `CreateToolhelp32Snapshot` →
   `Thread32First`/`Next` → `OpenThread` → `ResumeThread`.
   `Win32_System_Diagnostics_ToolHelp` is already a feature.
5. If assignment or resume fails, terminate and report `spawnFailed`. **Never run
   a process outside its job.**

Suspended first, because a process that runs before assignment can start a child
that is never in the job — which is exactly the tree this exists to catch. Every
descendant inherits the job, `node` and the real Agent included, and anything they
start in turn.

Cancel becomes `TerminateJobObject`. `KILL_ON_JOB_CLOSE` covers the crash: when
Takyon dies, Windows closes its handles and kills every job's members without any
code of ours running.

New `windows` feature: `Win32_System_JobObjects`. No new crate.

**Unix: a process group.** `setsid` in `pre_exec` and `kill(-pgid, SIGKILL)`,
the pattern `probe::run_command` already uses for `shellenv`'s probe. There is no
unix equivalent of `KILL_ON_JOB_CLOSE`, so a Takyon crash still orphans children
on macOS; that gap is recorded, not closed, and v0.12 owns it.

**A visibility gate on `Turns`.**

```rust
pub struct Turns {
    running: Mutex<HashMap<u64, Spawned>>,
    /// False while the Palette is hidden. A Turn may only run while it is shown.
    visible: AtomicBool,
}
```

- `window::show` sets it; `window::hide` clears it.
- `start` refuses while it is clear.
- After spawning and registering, `run` checks again and terminates the Turn if a
  hide landed in between. That closes the in-flight `agent_ask` race, the late
  `!s` Turn, and the spawn-to-registration window together.
- `cancel_all()` terminates every registered job.

`window::hide` calls `set_visible(false)` and `cancel_all()` **in Rust, before it
emits `EVENT_HIDE`**. It is the one function all three dismiss routes — hotkey,
Escape, focus loss — go through, so dismissal stops depending on the webview
running a cleanup. It also calls `Searches::cancel_all()`, so a `!s` stops
fetching as well. `TerminateJobObject` does not block; reaping stays on each
Turn's own thread, never on whatever thread called `hide`.

`probe::run_command` spawns inside a job too, so a probe that times out on
Windows takes its whole tree, which today only unix does.

### 3. Failures are facts, and the copy is TypeScript's

The same split `Snapshot` already follows: Rust says what happened, TypeScript
decides how to say it.

```rust
#[serde(rename_all = "camelCase", tag = "reason")]
pub enum TurnFailure {
    NotFound { agent: String, binary: String },
    LauncherBroken { agent: String, binary: String, detail: String },
    SpawnFailed { agent: String, detail: String },
    AgentError { agent: String, message: String },
    Exited { agent: String, code: Option<i32>, detail: String },
    Silent { agent: String },
}
```

| Reason | When |
|---|---|
| `notFound` | `probe::resolve` found nothing |
| `launcherBroken` | exit 9009, or stderr matches t3code's six "is not recognized" patterns |
| `spawnFailed` | `spawn` returned an `io::Error`, or the job could not be set up |
| `agentError` | the driver's parser saw the Agent's own error event — its words, unedited |
| `exited` | non-zero exit; stderr's tail, capped at 2,000 characters |
| `silent` | the process ended having produced no text |

`TurnEvent::Failed { failure }`, and the wire in `packages/shared/src/ipc.ts`
becomes `{ kind: "failed"; reason; agent; binary?; code?; detail?; message? }`.
Cancellation still emits nothing.

`apps/desktop/src/agents/status.ts` gains `turnFailureCopy(failure)`, returning a
headline and an optional detail, beside `agentSummary`. `turnState.ts`,
`search/searchState.ts`'s `reduceTurn`, `AskView.tsx` and `SearchView.tsx` render
it; `api.mock.ts` learns the new shape.

### 4. Resolution

`probe::in_dir` builds its candidate extensions from `PATHEXT`, falling back to
`.COM;.EXE;.BAT;.CMD` as t3code does. `.ps1` stops being a candidate because no
default `PATHEXT` contains it. `extra_dirs` gains Volta, `Programs\nodejs` and
scoop. Order is unchanged: hydrated `PATH`, inherited `PATH`, then these.

### 5. Claude streams token by token

`--include-partial-messages` on every Claude Turn. The stream then carries
`stream_event` lines whose `event` is `content_block_delta` with a `text_delta`,
**and** the whole `assistant` message afterwards. Rendering both doubles the
answer, so:

- a `text_delta` emits `Text` and sets `TurnState.streamed`
- `message_start` clears it
- an `assistant` message emits its text only when nothing streamed since the last
  `message_start`

The fallback keeps a Claude that ignores the flag working. Codex and opencode are
unchanged here: neither `exec` nor `run` can stream tokens, which is v0.15's
reason for existing.

## Traps

- **stdin must be closed, not just written.** Claude and opencode read to EOF
  before they start. A Turn that writes the prompt and keeps the handle hangs
  forever, and looks like a slow model.
- **Write stdin on its own thread.** Writing 26,000 characters while nobody reads
  stdout deadlocks as soon as the child's output fills its pipe. Same rule as the
  stderr drain already has.
- **Never let a process run outside its job.** Resume only after assignment
  succeeds; on any failure, terminate. A best-effort job is no job.
- **`hide` may run on the main thread.** Terminate and return; `wait()` belongs to
  the Turn's thread. Blocking here freezes the Palette's own dismissal.
- **The gate defaults to hidden.** Integration tests that start Turns — including
  any in `tests/ipc.rs` driven through `MockRuntime` — must set it visible first,
  or they will see Turns refused and read it as a regression.
- **Codex `resume` needs the explicit `-`.** `exec` reads stdin when the prompt is
  omitted; `exec resume` does not.
- **Do not port `escapeWindowsShellArg`.** It exists because Node will not spawn a
  `.cmd`; ours will, safely. Porting it means `raw_arg`, and `raw_arg` means owning
  BatBadBut.
- **Partial messages double the text** without the `streamed` rule.
- **`tests/zz_turn_live.rs` breaks under the new SPI.** It builds a Claude command
  from `turn_args` with stdin null, which after this change is `-p` with no
  prompt. It is also not `#[ignore]`d, so it spends Claude tokens on every
  `bun run test`. Mark it ignored and route it through `turn::spawn`; deleting it
  is the user's call.

## Hand-off

**One unit, one agent, one branch.** Hand over this file; it names its own reads.
`CONTEXT.md` as always. Windows first — every task here is verifiable on this
machine — and `bun run check:macos` for the unix arm of `job.rs`.

The gate is `bun run typecheck && bun run lint && bun run test`, plus
`bun run check:macos` and `bun run check:comments` on every touched file. The
ignored live tests are run by hand once, and their output pasted into the PR.

Then drive a real build: `!c` with each Agent first in the order, a follow-up,
`!s`, and a dismissal mid-answer by each of the three routes followed by
`Get-Process claude,codex,opencode,node -ErrorAction SilentlyContinue`. On this
machine `Alt+Space` belongs to Raycast, so summon from the tray. The laptop that
reported it is the only machine with the real npm shape: `where.exe opencode`
there should name a `.cmd`, and the release build goes through the same script.

## Exit criteria

On a machine whose Agents are npm `.cmd` installs, `!c` and `!s` answer with each
of the three, including a multi-line question. Dismissing the Palette mid-answer
— by hotkey, by Escape and by clicking away — leaves no process that Takyon
started, checked in Task Manager or `Get-Process`.

## What shipped differently

- ADRs are **0032** and **0033**: 0031 was taken by the sole-installed-Agent rule.
- `probe::run_with_input` was not built. The live tests need Claude's cwd as the
  process cwd, which no `probe` entry point takes, so they go through
  `turn::spawn` - the real path - and nothing else wanted stdin on a probe.
- `Turns::set_visible(false)` cancels every Turn itself, so `window::hide` has one
  call to make rather than two that must stay in order.
- The manual script is its own file, `docs/verify/v0.11.1.md`, with section C
  driven by `scripts/verify-drive-v0.11.1.ps1`.
- `docs/tbd/v0.11.md` gained sections 8 to 11.
- Driving the real build found a spawn storm that predates this phase: `ask` is a
  new object per keystroke, so every character typed after `!c` started another
  `agent_snapshots` while the first was still running - three process spawns each,
  about 30 `opencode` processes for one sentence. `Palette.tsx` now keeps one
  probe in flight at a time.
- Section C is driven end to end by `scripts/verify-drive-v0.11.1.ps1`, which
  passed all five routes against the release build.
