# v0.7 File search

Largest phase in V1. Unelevated, no service, no raw volume access.

## Read first

ADR-0007 (why not MFT/USN), ADR-0004 (superseded, read for the rejected path),
TBC-0003 (switching costs), TBC-0005 (default roots, weakest call in the design),
`IMPLEMENTATION_PLAN.md` §5.

## Tasks, in order

1. **`FileIndex` trait** (§2). Everything else sits behind it, including the
   Windows Search fallback and any future MFT accelerator.
2. **`index/walker.rs`.** Parallel directory walk over configured roots.
   Filenames and folder names only, no content. Skip excluded patterns during
   the walk, not after.
3. **`index/store.rs`.** On-disk format from §5: header, string arena, entry
   table, trigram postings. Memory-mapped, never parsed. `format_version` bump
   forces rebuild.
4. **Boot path.** `mmap` existing index, serve immediately. Never re-walk at
   startup.
5. **`index/watcher.rs`.** `ReadDirectoryChangesW` per root. Apply deltas to the
   live index.
6. **Overflow handling.** `ERROR_NOTIFY_ENUM_DIR` means events were dropped. On
   that signal: bump generation, mark subtree stale, rescan that subtree only.
7. **`IndexStatus` surfaces in the UI.** `Ready`, `Building { pct }`, `Stale`.
8. **Query path.** Intersect trigram postings, then verify candidates with the
   real matcher from §3. Queries under 3 chars skip postings, scan the recent set.
9. **Windows Search fallback** for locations outside walked roots.
10. **`!e` Mode.** Actions: open, reveal in Explorer, copy path.
11. **Bangless file toggle**, default off. When on, file Entries appear below
    apps, never above.

## Traps

**Never serve a known-stale index silently.** An index that quietly misses files
is worse than no index, because the user learns not to trust the feature and
stops using it. Detection is cheap and certain. Use it.

Watcher overflow is a correctness path, not an edge case. Under a large `git
checkout` or an npm install it fires routinely.

Default roots are a product decision with a settings UI, not a constant.
`C:\Programming` is a personal-workflow assumption that will not generalise. See
TBC-0005.

Exclude during the walk. Walking 400,000 `node_modules` entries and then
discarding them wastes the whole time budget.

Trigram postings on a 2-char query return nearly everything. Handle short queries
separately or the p95 target is unreachable.

## Exit criteria

`!e` p95 under 20 ms. Initial walk under 60 s in background, no competition with
login. Index survives reboot without re-walking. A file created one second ago is
findable.

## Manual verification

1. `!e` a known filename, confirm under 20 ms (instrumented, not felt).
2. Create a file, search for it within 2 s, confirm found.
3. Reboot, confirm no re-walk, first `!e` still fast.
4. Trigger overflow with a large `git checkout`, confirm status shows Stale then
   returns to Ready and results are correct after.
5. Delete the index file, restart, confirm rebuild and a visible Building state.
6. Add and remove a root, confirm the entry count moves.
