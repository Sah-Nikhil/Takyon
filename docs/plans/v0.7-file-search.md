# v0.7 File search

Largest phase in V1. Unelevated, no service, no raw volume access.

## Read first

ADR-0007 (why not MFT/USN), ADR-0004 (superseded, read for the rejected path),
TBC-0003 (switching costs), TBC-0005 (default roots, weakest call in the design,
**amended at v0.7** — read the amendment, it carries the Windows Search
measurement), `IMPLEMENTATION_PLAN.md` §5.

## Decisions taken before the build

Four questions were settled at the start of the phase rather than during it.

**The code root is probed, not hardcoded.** `C:\Programming` ships as one entry in
a candidate list — with `%USERPROFILE%\source\repos`, `~\dev`, `~\code`,
`~\projects`, `~\git`, `~\repos` — and only paths that exist on disk become roots.
TBC-0005's amendment carries the reasoning and the measurement behind it.

**The Windows Search fallback ships in this phase, with a settings toggle, default
off.** It is built rather than deferred, but nothing depends on it and nobody gets
it without asking. Two reasons it cannot be on by default, both measured: its
queries run 10–72 ms against a 20 ms p95 budget, and its coverage of any given
folder is unknowable from outside — the development machine has the whole C: drive
in crawl scope and still returns zero rows for `C:\Programming\SELF`. A fallback
that is on by default returns *some* results, reads as working, and hides the gap.

**Delivered in three slices, each verified before the next.** A walker bug and a
watcher bug arriving together are hard to separate, and slice 1 is testable with
no watcher at all.

**`!e` with an empty query shows the Takyon-owned recents list** (task 12),
filtered to File and Folder kinds. It gives that table a visible purpose in the
same phase that builds it, and answers the bang-registry's "what does a Bang with
no query show" for one Bang without settling it for all.

## Slices

**Slice 1 — the index, offline.** Tasks 1, 2, 3, 4 and 8. Roots and exclusions,
the walk, the on-disk format, mmap at boot, the query path. No watcher, no UI, no
Bang: an index that is built once and queried, which is enough to hold the p95
budget honest.

**Slice 2 — keeping it true.** Tasks 5, 6 and 7. Watchers, overflow handling and
`IndexStatus` surfaced in the UI. This is the correctness half.

**Slice 3 — the surface.** Tasks 9, 10, 11 and 12. Windows Search fallback behind
its toggle, the `!e` Mode and its actions, the Bangless file toggle, the owned
recents list and the Settings control that clears it.

## Tasks, in order

1. **`FileIndex` trait** (§2). Everything else sits behind it, including the
   Windows Search fallback and any future MFT accelerator.
2. **`index/walker.rs`.** Parallel directory walk over configured roots.
   Filenames and folder names only, no content. Skip excluded patterns during
   the walk, not after. **Guard reparse points** — a junction or a redirected
   OneDrive folder makes the walk a cycle, and depth is otherwise unbounded.
3. **`index/store.rs`.** On-disk format from §5: header, string arena, entry
   table, trigram postings. Memory-mapped, never parsed. `format_version` bump
   forces rebuild.
4. **Boot path.** `mmap` existing index, serve immediately. Never re-walk at
   startup.
5. **`index/watcher.rs`.** `ReadDirectoryChangesW` per root. Apply deltas to the
   live index.
6. **Overflow handling.** `ERROR_NOTIFY_ENUM_DIR` means events were dropped. On
   that signal: bump generation, mark subtree stale, rescan that subtree only.
7. **`IndexStatus` surfaces in the UI.** `Ready`, `Building { pct }`, `Stale`.
8. **Query path.** Intersect trigram postings, then verify candidates with the
   real matcher from §3. Queries under 3 chars skip postings, scan the recent set.
9. **Windows Search fallback** for locations outside walked roots. Behind a
   settings toggle, default off, and never on the fast path — results arrive after
   the local index has already painted, and land below the settled set so the
   Stability rule is not broken by a late answer.
10. **`!e` Mode.** Actions: open, reveal in Explorer, copy path. Empty query shows
    the owned recents list from task 12.
11. **Bangless file toggle**, default off. When on, file Entries appear below
    apps, never above.
12. **A recents list Takyon owns** — [TBC-0010](../tbc/0010-takyon-owned-recents.md).
    One `opened` table written from `record_activation`, merged with the shell's
    list and preferred over it. **Belongs here, not in v0.3**: it records what
    the Palette opens, and until task 10 the Palette opens nothing but
    applications, which Frecency already ranks better than a chronological list
    would. Ship the Settings control that clears it in the same phase.

## Traps

**Never serve a known-stale index silently.** An index that quietly misses files
is worse than no index, because the user learns not to trust the feature and
stops using it. Detection is cheap and certain. Use it.

Watcher overflow is a correctness path, not an edge case. Under a large `git
checkout` or an npm install it fires routinely.

Default roots are a product decision with a settings UI, not a constant. See
TBC-0005 and its v0.7 amendment.

Exclude during the walk. Walking 400,000 `node_modules` entries and then
discarding them wastes the whole time budget.

Trigram postings on a 2-char query return nearly everything. Handle short queries
separately or the p95 target is unreachable.

**A junction is a cycle.** The walk has no depth cap by design, so a reparse point
pointing at an ancestor walks forever. Skip `FILE_ATTRIBUTE_REPARSE_POINT` rather
than following it: the targets worth indexing are reachable as their own roots.

## Exit criteria

`!e` p95 under 20 ms. Initial walk under 60 s in background, no competition with
login. Index survives reboot without re-walking. A file created one second ago is
findable.

## Manual verification

1. `!e` a known filename, confirm under 20 ms (instrumented, not felt).
2. Create a file, search for it within 2 s, confirm found.
3. Reboot, confirm no re-walk, first `!e` still fast.
4. Trigger overflow with a large `git checkout`, confirm status shows Stale then
   returns to Ready and results are correct after.
5. Delete the index file, restart, confirm rebuild and a visible Building state.
6. Add and remove a root, confirm the entry count moves.
7. With the Windows Search fallback off, `!e` a file outside every root and
   confirm the empty state says so rather than showing nothing. Turn the fallback
   on, repeat, confirm the file is found and that its Entries arrive below the
   local ones.
