# v0.5 manual verification

Clipboard history. Written as the phase is built, one section per task.

This is the highest-risk phase in V1 and the only one whose failure mode is a
leaked password rather than an awkward list. **Every step that claims something
is absent from the database is checked by opening the file, never by looking at
the Palette.** The Palette is the surface most likely to be lying.

Run [`../../scripts/verify-guard.ps1`](../../scripts/verify-guard.ps1) first,
every time. An installed Takyon swallows every summon through
`tauri-plugin-single-instance` and the build under test never runs, silently.

`Alt+Space` is unavailable on the development machine (Raycast holds it), so
every step below assumes the `TAKYON_HOTKEY` override — `Ctrl+Alt+Shift+F9` is
what the drivers use.

**Sections K, S, V and P4 were driven and confirmed against the release build on
2026-09-02** by [`../../scripts/verify-drive-v0.5.ps1`](../../scripts/verify-drive-v0.5.ps1).
Shots land in `%TEMP%\takyon-verify-v0.5`. The driver runs the build under an
**isolated `LOCALAPPDATA`**, so it never creates or touches the real clipboard
history — it copies things, and a run against the real database would file the
operator's own clipboard into it.

**Read the clipboard, not the pixels**, which is v0.4's lesson and applies twice
as hard here. Window heights say a list has rows; only V2b says the right bytes
came back out. It copies a sentinel, finds a stored clip through `!v`, presses
`Ctrl+Enter`, and compares — capture, encryption, storage, search and decryption
in one assertion no screenshot could fake.

**Build with `bun run build`, never bare `cargo build --release`.** A cargo-only
release binary launches, registers the hotkey and shows a Palette with a
completely dead frontend, which fails in the one way that looks like a Rust bug.

## Reading the database

Steps below refer to these three commands. `clips.db` is at
`%LOCALAPPDATA%\v3sper\launcher\`.

```powershell
# Row count and metadata. Never decrypts anything, so it is safe to paste output.
sqlite3 "$env:LOCALAPPDATA\v3sper\launcher\clips.db" `
  "SELECT id, created_at, source_exe, len FROM clips ORDER BY id DESC LIMIT 10;"

# Does any plaintext survive anywhere in the file, WAL and shm included?
# Prints nothing when the answer is no, which is the passing result.
$needle = "the-string-you-copied"
Get-ChildItem "$env:LOCALAPPDATA\v3sper\launcher\clips.db*" | ForEach-Object {
  $bytes = [IO.File]::ReadAllBytes($_.FullName)
  $text  = [Text.Encoding]::Unicode.GetString($bytes) + [Text.Encoding]::UTF8.GetString($bytes)
  if ($text -match [regex]::Escape($needle)) { "FOUND in $($_.Name)" }
}

# The key. Should be a DPAPI blob, several hundred bytes, and not 32.
Get-Item "$env:LOCALAPPDATA\v3sper\launcher\creds\clip.key.dpapi" | Select Length
```

Search both encodings. `CF_UNICODETEXT` is UTF-16, so a UTF-8-only grep passes
against a file that is leaking.

## B — The Bang as a toggle

**Drive this through Settings now, not through `sqlite3`.** v0.6 built
Clipboard History → "Reach history with `!v`", so the restarts these steps ask
for are no longer part of the feature — they were scaffolding for a setting with
no editor. Editing `clips.bang` by hand still works and still needs the restart,
but it stops being the honest test: what ships is the switch.

**BT2 and BT4 therefore make a second claim as well** — that the change lands on
the next summon with no restart at all. A toggle that only takes effect after a
restart is a defect in the v0.6 window, whatever the Bang does. `v0.6.md` C4 is
the same ground from the settings side; this section is the Palette's half.

## What cannot be checked here

**Whether the encryption is correct**, as opposed to present. The tests in
`tests/clips_disk.rs` assert the ciphertext is absent from the file after a
sweep, which is the property that matters operationally; neither they nor this
script is a cryptographic review of AES-256-GCM usage.

**Whether every password manager sets the exclusion format.** X1 checks the two
that are installed. An application that sets neither format nor gets blocklisted
is captured, by design — that is why the blocklist exists and why it is
user-editable (ADR-0006).
