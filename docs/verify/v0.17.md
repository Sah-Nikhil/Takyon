# v0.17 manual verification

Time zones in the calculator. Plan: [`../plans/v0.17-time-zones.md`](../plans/v0.17-time-zones.md).

**Nothing here has been run.** The Rust unit tests fix the instant and the zone,
and the visual suite draws a fixture card, so neither proves what a real machine
gives: the system zone jiff detects, the Windows 24-hour setting, and a zone
change reaching a running Palette.

Run [`../../scripts/verify-guard.ps1`](../../scripts/verify-guard.ps1) first. An
installed Takyon swallows every summon through `tauri-plugin-single-instance`.
Build with `bun run build`, never bare `cargo build --release`.

Answers depend on today's date and your zone. Check each against the Windows
clock or a second source (time.is) rather than against the numbers below, which
are shapes.

---

## A — Conversions

| # | Step | Expected | Status |
|---|---|---|---|
| A1 | Type `12 pm utc` | A card under **Calculator**. Left: `12:00 PM UTC`, labelled `Coordinated Universal Time · <today>`. Right: your local time with its code, labelled `your time · <zone in words>, UTC±n · <date>` | |
| A2 | Press `Enter`, then paste | The right half only, e.g. `5:30 PM IST`. Palette dismissed | |
| A3 | Type `3:30pm pst to ist` | Right half labelled `Kolkata · India Standard Time, UTC+5:30`. Left reads `PDT` between March and November, `PST` otherwise | |
| A4 | Type `11 pm pst to ist` | Right half starts with a weekday (`Thu …`), because India is already tomorrow | |
| A5 | Type `noon london to new york` | `7:00 AM` with `EDT` or `EST` (`8:00 AM` in the weeks only one side has changed its clocks), labelled `New York · Eastern … Time` | |
| A6 | Type `14:00 utc+5:30 to utc` | `8:30 AM UTC` | |

## B — The time now

| # | Step | Expected | Status |
|---|---|---|---|
| B1 | Type `time in london` | Left: your local time now. Right: London's, with `BST` (summer) or `GMT` (winter) and `British Summer Time` or `Greenwich Mean Time` in its label | |
| B2 | Type `london time`, then `now in london` | Same card as B1 | |
| B3 | Type `time in dubai` | Right half reads `UTC+4`, label `Dubai · UTC+4 · <date>`, and no invented zone name | |
| B4 | Type `time in dublin` | `IST` in summer labelled **Irish** Standard Time, never India | |

## C — What must not answer

| # | Step | Expected | Status |
|---|---|---|---|
| C1 | Type `tokyo` | No Calculator card. Whatever is named Tokyo keeps the top row | |
| C2 | Type `12 pm`, then `9:30` | No card | |
| C3 | Type `screen time` | No card | |
| C4 | Settings → Calculator → `After =`, then type `12 pm utc` | No card. `=12 pm utc` shows it | |

## D — The machine's own settings

| # | Step | Expected | Status |
|---|---|---|---|
| D1 | Windows Settings → Time & language → Date & time: switch the time zone to a different one, with Takyon running | Within **5 minutes** (jiff's cache), `12 pm utc` answers in the new zone. Before that it may still show the old one, which is expected | |
| D2 | Switch it back | Same, within 5 minutes | |
| D3 | Region → Change formats → Short time: pick `HH:mm`, then **restart Takyon** | `12 pm utc to ist` reads `17:30 IST`, no `PM` anywhere on the card. The format is read once per process | |
| D4 | Set it back to `h:mm tt` and restart | `5:30 PM IST` | |

## E — Offline

| # | Step | Expected | Status |
|---|---|---|---|
| E1 | With a network monitor open (Resource Monitor → Network, filtered to `takyon.exe`), type every query in A and B | **No connection** from `takyon.exe`. tzdb is in the binary (ADR-0037) | |
| E2 | Disconnect from the network, repeat A1 and B1 | Identical answers | |
