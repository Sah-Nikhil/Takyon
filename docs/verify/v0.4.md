# v0.4 manual verification

The calculator and the converter. Written as the phase is built, one section per
task, so nothing is improvised at the end.

Run [`../../scripts/verify-guard.ps1`](../../scripts/verify-guard.ps1) first,
every time. An installed Takyon swallows every summon through
`tauri-plugin-single-instance` and the build under test never runs, silently.

`Alt+Space` is unavailable on the development machine (Raycast holds it), so
every step below assumes the `TAKYON_HOTKEY` override — `Ctrl+Alt+Shift+F9` is
what the drivers use.

**Sections C, D, E, F and G were driven and confirmed against the release build
on 2026-09-01** by [`../../scripts/verify-drive-v0.4.ps1`](../../scripts/verify-drive-v0.4.ps1).
Shots land in `%TEMP%\takyon-verify-v0.4`. Only the Settings switch (F3-F8) and
the network-monitor half of E1/E5 still need a person.

**Read the clipboard, not the pixels.** The driver's first revision injected
shifted keys by hand and Shift silently did not take, so `12*1.18` arrived as
`1281.18` — a *valid expression*. The Palette answered 1,281.18 and every
screenshot looked like a pass. The C3 clipboard assertion is what caught it, and
it is the reason that step exists.

**Build with `bun run build`, never bare `cargo build --release`.** A cargo-only
release binary launches, registers the hotkey and shows a Palette with a
completely dead frontend, which fails in the one way that looks like a Rust bug.

## C — Arithmetic and the answer row

| # | Step | Expected | Status |
|---|---|---|---|
| C1 | Type `12*1.18` | One row above everything else: **14.16**, with `12*1.18` as its second line | confirmed |
| C2 | Look at the row's icon | An `=` glyph, not the letter `1`. A calculation has no icon, and the initial of its answer reads as an app icon that failed to load | confirmed |
| C3 | Press `Enter`, then paste somewhere | `14.16` on the clipboard, and the Palette dismissed | confirmed |
| C4 | Type `10+30%` | **13**, not 10. Percent after `+` is a percentage *of the left operand*, which is what a person means and the opposite of what `%` means in every programming language | confirmed |
| C5 | Type `12+30%` | **15.6**. The second reading of the same rule, because 13 alone could be a coincidence | confirmed |
| C6 | Type `200*10%` | **20**, not 220. After `*` and `/` the same sign is the plain fraction | confirmed |
| C7 | Type `2^3^2` then `-2^2` | **512** and **-4**. Right-associative, and binding tighter than unary minus | confirmed |
| C8 | Type `1/0` | No calculator row at all. Not `inf`, not an error row — the Palette has nowhere to put a reason | confirmed |
| C9 | Select the row, press `Ctrl+K` | One item: **Copy answer**, with `Enter` beside it. Nothing to open, elevate or reveal | confirmed |

## D — Detection, which is the phase's real work

Every Source sees every keystroke and `EntryKind::Calc` wins its tier outright,
so a wrong answer does not sit politely at the bottom. It takes the top row and
takes Enter with it. These steps are the ones that matter.

| # | Step | Expected | Status |
|---|---|---|---|
| D1 | Type `1password` | The application, or nothing if it is not installed. **No calculator row** | confirmed |
| D2 | Type `7zip`, `x264`, `3dsmax` | Same: no calculator row for any of them | confirmed |
| D3 | Type `202` | No calculator row. Formatting `202` changes nothing, so there is nothing to say | confirmed |
| D4 | Type `2024` | **2,024**, above the applications. This is the rule working, not failing | confirmed |
| D5 | Type `2022` | **2,022** above **Adobe Photoshop 2022**, and the footer hint on the calc row rather than the app. *This is the known cost of the default Policy* — see `../tbd/v0.4.md` §1. It is expected, not a bug | confirmed |
| D6 | Type `45+` | No calculator row. Raycast answers 45 here; we refuse a half-typed expression | confirmed |
| D7 | Type `log` | No calculator row. A function name is only a function with a `(` after it | confirmed |
| D8 | Type `notion to do` | No calculator row. `do` is not a unit, so the conversion is refused rather than guessed at | covered by unit test, not yet driven |

## E — Unit conversion, all of it offline

Run **at least E1 and E5 with a network monitor open** (Resource Monitor →
Network, filtered to `takyon.exe`, or Fiddler). ADR-0002 makes an outbound
request on the Bangless path a correctness bug, not a slow path.

| # | Step | Expected | Status |
|---|---|---|---|
| E1 | Type `40 kg to lb` | **88.1849 lb**, and **zero network activity from `takyon.exe`** | confirmed |
| E2 | Type `40kg to lb` | The same answer. Attached and spaced units are one code path | covered by unit test, not yet driven |
| E3 | Type `100 c to f` | **212 °F**. Temperature is affine; a factor-only table gets this wrong and gets 0 °C right | confirmed |
| E4 | Type `1 gb to mb` | **1,024 MB**, matching what File Explorer reports under the same label | confirmed |
| E5 | Type `100 usd to inr` | **No row at all**, and **no network request**. Currency is not built — `../tbd/v0.4.md` §2, owned by v0.8 | confirmed |
| E6 | Type `40 kg to cm` | No row. Two units from different dimensions do not convert | confirmed |
| E7 | Type `3 months to days` | No row. Neither months nor years is a unit here; both are ambiguous | confirmed by unit test, not driven |

## What cannot be checked here

The `2022` collision in D5 is a **judgement**, not a pass/fail. It is recorded so
that whoever runs this script sees it deliberately rather than filing it as a
bug. If it turns out to be annoying in daily use, that evidence belongs in
`../tbd/v0.4.md` §1, which owns the decision.
