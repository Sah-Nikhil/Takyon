# v0.2 manual verification

The third testing layer from `IMPLEMENTATION_PLAN.md` §11, for the applications
phase. v0.1's script still applies in full — this one only covers what v0.2 added.

Everything below is here because the Rust unit tests cannot see it and the mocked
visual layer structurally cannot either (TBC-0007): what the shell actually
returns for *this* machine's applications, what the extracted icons look like,
whether the native window is the right shape, and whether pressing Enter really
starts the thing.

Run it against a **release** build. Record the date, the machine, and anything
surprising. A step that "sort of worked" is a failure.

---

## Setup

```powershell
bun run build
# or, without producing an installer:
bunx --bun tauri build --no-bundle --cwd apps/desktop
```

**If another launcher is already running**, expect the hotkey-failure dialog and
the amber banner in the Palette — `Alt+Space` is contested by PowerToys Run, by
Raycast and by the classic window system menu. That is v0.1 behaviour working
correctly, not a v0.2 regression. Steps that need the hotkey can be driven by
launching a second copy of `takyon.exe` instead: `tauri-plugin-single-instance`
turns that into a show through the same code path.

## A. Discovery

| # | Step | Expected |
|---|---|---|
| A1 | Start the release binary from a console and read stderr | One line: `discovered N applications in M ms`. `N` should be in the hundreds to low thousands, `M` comfortably under a second |
| A2 | Open the Palette within a second of launching | Either Entries, or the row **"Indexing applications…"**. Never a silently empty list — that reads as "you have no such app" |
| A3 | Type the name of something installed from the **Start Menu** | It appears, titled as the Start Menu names it rather than as its executable is named |
| A4 | Type the name of a **Store app** (Calculator, Photos, Settings) | It appears, subtitled `Store app` |
| A5 | Type the name of a command-line tool that has no Start Menu shortcut (`node`, `ffmpeg`, `rg`, `bun`) | It appears, subtitled with its full path |
| A6 | Type the name of an **installed Steam game** | It appears, subtitled `Steam` |
| A7 | Type `steamworks` | **Nothing.** Redistributables and Proton runtimes are not games and must not be offered |
| A8 | Uninstall something, restart Takyon, search for it | Gone. There is no cache to go stale (`sources/apps.rs`) |

> **A6 and A7 could not be run on the development machine.** Its Steam library
> contains exactly one manifest, `appmanifest_228980` — Steamworks Common
> Redistributables — so there is no game to launch and the only thing the filter
> could act on is the thing it is meant to hide. The parser is covered by
> fixtures in `steam.rs` taken verbatim from that machine's real
> `libraryfolders.vdf`, but **the Steam path has never been seen end to end** and
> this step stays open until someone runs it against a library with a game in it.

## B. Matching

The tier ladder itself is unit-tested in `rank.rs`. These check it against real
application names rather than chosen ones.

| # | Step | Expected |
|---|---|---|
| B1 | `phot` | Photoshop (or Photos) is the top Entry |
| B2 | `vsc` | Visual Studio Code, by acronym |
| B3 | `code` | Visual Studio Code |
| B4 | Type a full app name exactly | That app is top, above anything merely prefixed by it |
| B5 | Type two letters and watch the list while typing the third | The list changes, and never shows results for a *shorter* prefix than what is in the box — that is the `seq` rule (§3) |

## C. Icons

| # | Step | Expected |
|---|---|---|
| C1 | Search for several apps on a cold profile (delete `%LOCALAPPDATA%\v3sper\launcher\icons.bin` first) | Rows appear **immediately** with lettered placeholders; icons fill in behind them. Rows never wait for icons |
| C2 | Look at a Store app's row | Its real package icon, not a generic one |
| C3 | Look at a `.lnk`-derived row whose shortcut has custom branding | The shortcut's icon, not the target stub's |
| C4 | Dismiss, re-summon, repeat the same query | Icons are there instantly. The second showing costs nothing — WebView2 caches by URL and the key contains the file's mtime |
| C5 | Restart Takyon and repeat | Still instant. `icons.bin` survived |

## D. The window

The one area where the browser-based visual tests are blind: they have no native
window to be clipped by, and this is where three separate bugs were found.

| # | Step | Expected |
|---|---|---|
| D1 | Open the Palette with an empty query | One input row. No empty shadowed box hanging below it |
| D2 | Type something matching one app | The window snaps to exactly one row. No animation |
| D3 | Type something matching many apps | The window stops growing at **8 rows**; the rest scroll inside the list |
| D4 | Count the rows against the window | No row is clipped, and **no scrollbar appears on a list that fits** |
| D5 | Press `Ctrl+K` on a one-row result | The window grows to hold the menu. All four actions are visible; none is cut off at the bottom edge |
| D6 | With the hotkey **unregistered** (run another launcher first), repeat D2–D5 | The amber banner is fully readable, and still nothing above it is clipped. Its height is measured at runtime, not assumed |
| D7 | Repeat D2–D6 on a monitor at **150% scaling** | Identical. This is where a hardcoded banner height came up 16px short and ate a row |
| D8 | Dismiss with a full list showing, then re-summon | It opens as one empty input row, not as a tall empty box that then snaps shut |

## E. Launching

| # | Step | Expected |
|---|---|---|
| E1 | Select an app, press Enter | **The Palette disappears before the app's window paints.** Not after |
| E2 | Launch a Store app | It starts. UWP has no path to `CreateProcess`; this goes through `shell:AppsFolder` |
| E3 | Launch a Steam game | Steam takes over and starts it — with playtime and cloud saves, i.e. through `rungameid` (**blocked, see A6**) |
| E4 | Launch a `PATH`-only tool such as `node` | A console appears and stays. It is not holding one of Takyon's pipes |
| E5 | `Ctrl+K` → Run as administrator | UAC prompts. Accept: it starts elevated. Cancel: nothing happens and nothing is reported as an error |
| E6 | `Ctrl+K` → Open file location | Explorer opens with the file **selected**, not just its folder. Try one whose path contains a space |
| E7 | `Ctrl+K` → Copy path, then paste somewhere | The full path, exactly |
| E8 | Select a Store app, press `Ctrl+K` | Only **Open**. No reveal, no elevate, no copy path — a packaged app has no file, and a menu item that can only fail teaches the user the menu lies |

## F. Keyboard only

Do the whole of section E again **without touching the mouse**. If any step needs
one, that is the finding.

| # | Step | Expected |
|---|---|---|
| F1 | Summon, type, arrow down twice, Enter | The third Entry launches |
| F2 | Summon, type, `Ctrl+Enter` | Run as administrator, without opening the menu |
| F3 | Summon, type, `Ctrl+Shift+Enter` | Open file location, without opening the menu |
| F4 | Open the action menu, press Escape once | The **menu** closes. The Palette stays, with the query still in it |
| F5 | Press Escape again | The Palette hides |
| F6 | Open the action menu and type to filter it | Typing `admin` reaches "Run as administrator" |

reach for the Start menu once.** Note every time you do reach for it, and why —
that list is the v0.3 backlog.
