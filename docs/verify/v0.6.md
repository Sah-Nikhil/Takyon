# v0.6 manual verification

Settings. Written as the phase is built, one section per slice.

**All three slices.** Sections S and A cover the window and autostart (slice 1);
K, L, C and A2 the hotkey, Launcher, clipboard and aliases (slice 2); P2 the
appearance and interface size (slice 3).

Run [`../../scripts/verify-guard.ps1`](../../scripts/verify-guard.ps1) first,
every time. An installed Takyon swallows every summon through
`tauri-plugin-single-instance` and the build under test never runs, silently.

`Alt+Space` is unavailable on the development machine (Raycast holds it), so
every step below assumes the `TAKYON_HOTKEY` override — `Ctrl+Alt+Shift+F9` is
what the drivers use.

**Build with `bun run build`, never bare `cargo build --release`.** A cargo-only
release binary launches, registers the hotkey and shows a Palette with a
completely dead frontend, which fails in the one way that looks like a Rust bug.

## Why any of this is manual

Almost all of slice 1 is already covered automatically and should not be re-checked
by hand:

| Claim | Where it is tested |
|---|---|
| Tier one keeps declared order, tier two is alphabetical | `nav.test.ts` |
| A new Source adds a page without touching navigation | `nav.test.ts` |
| Search finds a control by keyword, and names its page | `nav.test.ts`, `settings.spec.ts` |
| The snapshot's wire shape matches `ipc.ts` | `tests/ipc.rs` |
| Migration seeds an empty install and never speaks again | `tests/ipc.rs`, `prefs.rs` |
| A stored calculator Policy is what startup reads | `settings.rs` |
| A refused autostart write shows its error and refetches | `settings.spec.ts` |

What is left is the part with no window in it: the real Tauri window, the real
registry, and the process lifetime.

## S — the window itself

**S1 also samples pixels**, which is not fussiness. The bug this section found —
a window built on the main thread, whose webview therefore never loads — passes
every structural check: the window exists, has the right label and the right size.
Only the pixels say it is empty.

**S1, S3 and S5 are driven** by
[`../../scripts/verify-drive-v0.6.ps1`](../../scripts/verify-drive-v0.6.ps1),
which launches the release build, opens Settings with `Ctrl+,`, closes it and
checks the process is still alive and the hotkey still answers. Shots land in
`%TEMP%\takyon-verify-v0.6`. S2 and S4 still need a person — the tray menu and a
resize.

**S1.** With the Palette open, press `Ctrl+,`. The Settings window opens.

**S2.** Close it. Right-click the tray icon → **Settings**. The same window
opens, on the same page it always opens on (General).

**S3.** Open Settings twice — `Ctrl+,`, then the tray item. There is exactly one
Settings window, and the second request focuses the existing one rather than
building a second.

**S4.** Resize the window as small as it will go. Both the sidebar and the
content column are still readable; nothing overlaps and nothing is clipped.

**S5. The one that looks like a crash.** Close the Settings window with its ✕.
**Takyon is still running**: the tray icon is there, and the hotkey still opens
the Palette. This is the failure ADR-0003 exists to prevent and the only place in
the app it can regress, because nothing else has a close button.

## T — the title bar

The Settings window is undecorated since v0.6; `settings/TitleBar.tsx` draws it.
None of this is reachable from the browser build, which has no window to drive.

**T1.** Drag the bar. The window moves. Double-click it: it maximises, and the
middle glyph becomes the restore pair. Double-click again: it restores.

**T2.** Drag the window's edges and corners. It still resizes, and stops at the
680×480 minimum — an undecorated window that cannot be resized is the usual way
this goes wrong.

**T3.** Minimise, then restore from the taskbar. Close with the ✕. **Takyon is
still running** — this is section S5 again, and it now runs through our own
button rather than Windows'.

**T4.** Set appearance to Light. The bar goes light with the rest of the window.
That is the whole reason it is drawn rather than native.

## A — autostart, against the real registry

Re-run [`v0.1.md`](./v0.1.md) section E in full. **None of it is superseded by
v0.6** — the registration itself was not rebuilt, only its home and its error
reporting. What follows is what v0.6 adds on top.

**A0. On by default since v0.6.** On a machine that has never run Takyon, install
and launch it, then check the `Run` key **without touching Settings**:
`com.v3sper.takyon` is there. Through v0.5 this was a modal question; the
Settings window is the off-ramp now, and it works. Delete
`%LOCALAPPDATA%\v3sper\takyon\first-run-complete` to re-test.

**A0b.** Turn it off in Settings, then restart Takyon twice. It stays off — the
marker file is what stops first-run re-enabling a choice you already made.

**A1.** Open Settings on a release build. The switch reads whatever
`Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'` says
about `com.v3sper.takyon`, not what it said last time the window was open.

**A2.** Leave Settings open. In Task Manager → Startup apps, disable Takyon.
Close and reopen the Settings window. The switch reads off. (It is read on mount,
never cached — ADR-0015. It is *not* expected to update live in an open window.)

**A3.** Run a debug build. The switch is disabled and its description names
`target\debug\`. It is the only control in the window disabled by build profile.

**A4. Force the write to fail.** Deny your own account write access to the `Run`
key, or set the policy `DisableCurrentUserRun`:

```powershell
# Break it. Run elevated; note the value before you change anything.
$k = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer'
New-ItemProperty -Path $k -Name 'DisableCurrentUserRun' -Value 1 -PropertyType DWord -Force
```

Toggle the switch. **An error string appears beside the control**, and the switch
settles on what the registry says rather than on what was clicked. Before v0.6
this failure was silent: the rejection vanished into a floating promise and the
switch simply refused to move (tbd v0.1 §3).

```powershell
# Put it back. Do this before anything else, including before reading further.
Remove-ItemProperty -Path $k -Name 'DisableCurrentUserRun'
```

**A5.** With the policy removed, toggle again. It works, and the stale error from
A4 is gone rather than sitting under a control that just succeeded.

## M — the migration off `localStorage`

Slice 1 moves the motion switch and the calculator Policy into `settings.db`
(task 8b). The interesting case is an install that already has the v0.1 keys.

**M1.** Seed the legacy state. With Takyon running, open the Palette's devtools
and set the old key, then quit Takyon completely:

```js
localStorage.setItem("com.v3sper.launcher.reduce-motion", "true");
```

**M2.** Start Takyon and open Settings. **Turn off animations reads on.** The
value was carried across rather than reset — this is the step that catches
somebody's setting silently flipping back.

**M3.** Confirm it landed in the database and the legacy key is gone:

```powershell
sqlite3 "$env:LOCALAPPDATA\v3sper\takyon\settings.db" `
  "SELECT key, value FROM settings ORDER BY key;"
```

`ui.reduce-motion` is `1`. In devtools,
`localStorage.getItem("com.v3sper.launcher.reduce-motion")` is `null`.

**M4.** Turn the switch off in Settings. Re-run M3: the row reads `0`. Now put
the legacy key back with `"true"` and restart. The switch still reads **off** —
migration never overwrites a choice made after it.

## P — the preferences actually take effect

**Run [`v0.4.md`](./v0.4.md) section F alongside this.** F3 through F8 have sat at `pending` since v0.4 because they ask for a switch that had nowhere to live; this window is that place, and P2 below is F7 seen from the Rust side.

**P1.** With animations on, summon the Palette and leave it empty. The mark
breathes. Open Settings, turn animations off, summon the Palette again. The mark
is still. The Palette re-reads on every show; it is not expected to change while
already open.

**P2.** Set the calculator to **After =** in Settings. Quit Takyon completely and
restart it. Summon the Palette and type `12*1.18` — **no Calc Entry appears**,
because the stored Policy was read at startup. Through v0.5 this silently
reverted to Automatic until a window had mounted and pushed the value.

**P3.** Type `=12*1.18`. The Calc Entry appears.

## K — the hotkey, against the real shortcut manager

The pinned list, the precedence and the restore-on-failure are unit-tested.
What is not is whether Windows actually hands the chord over.

**K1.** Keyboard → pick `Ctrl+Space`. The chip moves and "Applied" appears.
Press `Ctrl+Space` anywhere: the Palette opens.

**K2. The old binding must be gone.** Press the previous chord. **Nothing
happens.** A hotkey that was not released leaves two chords opening the Palette,
and the one you abandoned still answering is the failure nobody notices until it
collides with something else.

**K3.** Quit Takyon and restart it. `Ctrl+Space` still opens the Palette — the
binding is read from `settings.db` before registration, not after a window mounts.

**K4. A refused chord keeps the old one.** With PowerToys Run (or Raycast)
holding `Alt+Space`, pick `Alt+Space`. An error appears beside the control, the
chips stay on what is actually live, and the previous chord still works. The app
must never end up with nothing bound.

**K5.** Press Reset. The binding returns to `Alt+Space` if it is free, and K4's
error is gone rather than sitting under a control that just succeeded.

## L — Launcher

**L1.** Set placement to **Primary screen**. Move the cursor to a second monitor
and summon. The Palette opens on the primary. Set it back to **Where the cursor
is** and repeat: it follows the cursor. (Single-monitor machines cannot check
this — say so rather than ticking it.)

**L2.** Turn the tray icon off. It disappears; the hotkey still works. Turn it
back on from the Settings window, which is still open.

**L3. The refusal.** Run with the hotkey unregistered (hold `Alt+Space` with
another app, or `TAKYON_HOTKEY` set to something taken), open Settings from the
tray, and try to hide the tray icon. **It refuses**, naming why. This is the one
that would otherwise strand you in Task Manager.

**L4.** Turn off **Include recent files**. Summon and type a word that matched a
document before: no recent rows. Applications still match exactly as before.

## C — Clipboard History

**C3 and C4 have a Palette-side half** in [`v0.5.md`](./v0.5.md) section B and X4/X5. Both were written to be driven with `sqlite3` and a restart because the controls did not exist yet. Drive them from here instead — that the change needs no restart is the part worth checking.

**C1.** Copy several things. Settings → Clipboard History → set retention to
**1 day**. The dialog names an exact count, not "some items". Cancel: the chips
stay where they were and `clips.db` is unchanged.

**C2.** Do it again and confirm. The named number of rows is gone from
`clips.db`, and `PRAGMA wal_checkpoint(TRUNCATE)` has run — re-run the v0.5
plaintext scan to confirm nothing survives in free pages or the WAL.

**C3.** Add an executable to the blocklist. **Without restarting**, copy from
that application. Nothing is captured. Remove it, copy again, and it is.

**C4.** Turn off **Reach history with !v**. `!v` no longer opens history; the
**Clipboard History** command still does.

## A2 — Applications

**A2a.** Create an alias from the Palette's `Ctrl+K` menu, then open Settings →
Applications. It is listed against the right title, and it works on the next
keystroke without a restart.

**A2b.** Uninstall (or rename) the target. The alias still lists, marked
**no longer installed**, and Remove deletes it.

## P2 — Appearance

**P2a.** Set Windows to light. With appearance on **System**, both windows follow.

**P2b.** Set appearance to **Dark** while Windows is light. Both windows stay
dark — the override has to win in that direction too, which is the one a
`prefers-color-scheme` rule alone gets wrong.

**P2c.** Set appearance to **Light** while Windows is dark. Check the **Palette**
specifically: it is a transparent window drawing its own panel, so the rounded
corners must survive and there must be no hard square behind it.

**P2d.** Set interface size to **Large**. The Palette scales *and its window
grows with it* — the last row is not clipped, and the eighth row is still fully
visible with a long query. Repeat at **Small**. This is the one place a
CSS-versus-Rust mismatch shows, and it shows as exactly the zoom.

## D — Advanced

**D1.** Advanced → Open folder. Explorer opens `…\v3sper\takyon\logs`. Nothing
is uploaded; there is no network call on this path at all.

**D2.** Force a panic in a debug build. `panic.log` gains a line with a
timestamp, and the file never exceeds its cap after repeated panics.
