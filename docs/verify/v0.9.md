# v0.9 — manual verification

Agents landed: the `AgentDriver` trait and three drivers, Sign-in probes, the
`!c` Mode, the inline answer, Promotion into a conversation in the same window,
the Agent order and per-Agent switch, the locked model and effort, and the
Settings page.

Run this against a **release build** (`bun run build`, then the installed
binary), never `cargo build --release` — see CLAUDE.md's first gotcha. The
Palette resizes itself for every state below, and window sizing is the half no
browser harness can see.

## What automation already covers

Do not re-do these by hand:

- The three line parsers, the account labels, the delta cursor, and every string
  the cards can say: `cargo test --lib agents`.
- Whether each CLI is found, answers, and reports a coherent Sign-in state on
  *this* machine: `cargo test --test agents_cli`.
- **Two real Turns per signed-in Agent, end to end**:
  `cargo test --test agents_cli -- --ignored --nocapture`. Costs tokens and needs
  a network, which is why it is not in `bun run test`. Run it whenever a CLI
  updates — it is what catches a flag being renamed under us. It sends the
  **locked model and effort**, so the three spellings of effort are exercised
  rather than assumed, and it asks a tools-off Agent to write a file and asserts
  the directory stays empty (§5 below, automated).
- **Sections 1 to 4**: `scripts\verify-drive-v0.9.ps1` against a release build.
  Window heights, that the answer view opens, that a follow-up stays in the same
  window, and pixel samples proving both surfaces painted.
- Every surface drawing: `bun run test:visual`, with the IPC layer mocked.

What is left below is the native-window half and the things with a person in
them.

## 1. The `!c` row is one row, and the window is that tall

1. Press the hotkey, type `!c`.
2. The Palette shows exactly one line: the Agent's name and its Sign-in state.
3. **The window is one row tall, not empty-height.** A clipped line here means
   `ask_result` stopped reserving its row.
4. Type a question. The line becomes `Ask <Agent> — press Enter`.

## 2. An answer streams, and the window grows once

1. With a question typed, press Enter.
2. The window grows to the full surface height **once**, not per token.
3. Text appears progressively. **Watch the first thing that appears**: a `{` or a
   fragment of JSON means the newline buffering broke.
4. The question stays visible above the answer throughout.

## 3. Escape never destroys a conversation

1. Ask something. While it is still answering, press Escape.
2. The Palette goes back to the search line. It does **not** dismiss.
3. Press Escape again. The Palette dismisses.
4. Open Task Manager. The Agent's process is gone — dismissal unmounts the view,
   and `useTurn` cancels on unmount.

## 4. Promotion continues in the same window

1. Ask something, wait for the answer.
2. Type a follow-up in the bar at the bottom and press Enter.
3. **No second window appears.** The conversation continues where it is.
4. The first question, the first answer and the follow-up are all still on
   screen, in that order, and the follow-up is already being answered.
5. Ask another follow-up. It is answered in the same conversation — the Agent
   remembers turn one, which is the session id surviving.
6. Scroll up. The whole exchange is still there.

## 5. Tools are off on the first answer and on afterwards

**The first half is automated.** `v0_9_a_tools_off_turn_writes_nothing` asks each
signed-in Agent, in its own empty directory, to write a file with tools off, and
asserts nothing appeared. That is the claim ADR-0017 rests on and it no longer
needs a person. Only the second half does:

1. Ask something, then ask a follow-up that would write a file.
2. Behaviour differs from the first answer: the Agent has tools now. Whether the
   write is permitted depends on the Agent and on `docs/tbd/v0.9.md` §1, and
   either outcome passes — what must not happen is the **first** answer writing
   anything, which the test already holds.

## 5b. The locked model and effort are the only ones used

1. Settings → Agents. For the signed-in Agent, pick a model and an effort level.
   Both are dropdowns; **neither accepts typing**.
2. Ask `!c which model are you` from the Palette. The answer names the model you
   picked, or its family.
3. Change the model, ask again, confirm it changed.
4. An Agent that is not installed or is signed out shows **no pickers at all** —
   just `Sign in to choose a model`.
5. There is no way to override either from the Palette. If a future surface adds
   one, ADR-0017 was broken rather than amended.

## 5c. The Agent order is a preference, not a choice

1. Settings → Agents. Rank an Agent you are **not** signed in to first, and one
   you are signed in to second. Leave both switched on.
2. Type `!c` in the Palette. The row names the **second** Agent, and says the
   first one is unavailable. Press Enter: that second Agent answers.
3. Sign back in to the first, `Check again`, and type `!c` again. It is now the
   one named — no restart, and nothing to change back in Settings.
4. Move the third Agent to the top with `↑`. The rows reorder, so the page reads
   in the order `!c` will use. Both buttons are reachable by Tab.

## 5d. The switch decides, and it decides instantly

The switch is not a second Sign-in state. It exists so `!c` can name an Agent on
the first keystroke, which is what the "Checking which agent can answer" row used
to prevent.

1. Switch off whichever Agent leads the order. Its row dims, reads `Off` and
   loses its model and effort pickers.
2. `!c` in the Palette. It names the next switched-on Agent **immediately** — no
   pause, and no row saying it is still checking.
3. **Kill Takyon and restart it**, so no Agent has been probed since launch.
   Type `!c question` and press Enter within a second. The Turn starts. This is
   the case section 2 could not pass before: Enter used to do nothing until three
   process spawns had finished.
4. Switch every Agent off. `!c` says `No agent is switched on` in amber and
   Enter does nothing, which is the one state with nothing to try.
5. Switch one back on. `!c` reaches it again with no restart.

## 6. Every Sign-in state says something true

For each Agent in Settings → Agents, with `Check again` after each change:

1. **Not installed.** Rename the binary out of `PATH`. Card reads `Not found` and
   names the command.
2. **Signed out.** Run the Agent's own logout (`claude auth logout`,
   `codex logout`, `opencode providers logout`). Card reads `Not authenticated`
   and carries the command to sign back in. `!c` refuses in one amber line.
3. **Signed in.** Log back in through the CLI. Card reads
   `Authenticated · <plan>` with the account under it, without restarting Takyon.
4. **There is no Sign in button anywhere** (ADR-0017). If one appeared, TBC-0012
   was built without its decision being made.

## 7. Nothing flashes and nothing runs at login

1. Log out and back in. Time to hotkey-responsive is unchanged — **no Agent is
   probed on the login path**.
2. Open Settings → Agents and watch the screen edges. **No console window
   flashes**, on this or any `Check again`.
3. Same while typing `!c`: the first probe is three process spawns and must be
   invisible.

## 8. A missing binary is recoverable without a restart

1. With Takyon running, `bun add -g opencode` (or rename a binary back).
2. Open Settings → Agents, press `Check again`.
3. The card moves from `Not found` to installed. A restart must not be needed —
   `PATH` in a GUI process is the one from login, which is why `probe::resolve`
   also looks in the install directories.

## 9. The working directory is what Settings says

1. Leave `Run agents in` blank. Ask `!c what directory are you in`.
2. The answer names the Scratch directory.
3. Set it to a project folder, ask again. The answer names that folder.
4. Set it to a path that does not exist. The control refuses with a message and
   the previous value stands.
