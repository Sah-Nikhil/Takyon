# v0.9 — manual verification

`!s` against the real web, on a real machine. Run against an installed build, not
`bun run dev`: the network path, the shell hand-off and the DPAPI key are all
things the dev server either fakes or cannot reach.

**A Brave key is required.** Settings → Web search → paste, or steps 2 onwards
cannot run. The free tier covers this whole script several times over.

## What automation already covers

Do not re-do these by hand:

- Bang routing, the provider's response shape, HTML extraction, the prompt budget,
  the key's DPAPI round trip and every sentence a failure can carry:
  `cargo test --lib search`.
- **The real network**: `cargo test --test web_search -- --ignored --nocapture`.
  Fetches a live page over HTTPS, reads three in parallel with one host that does
  not resolve, and — if a key is stored — runs one real Brave query and checks
  every Hit it returns. Run it whenever the provider or Windows changes under us.
- Every surface drawing, in both key states: `bun run test:visual`, with the
  provider and the summariser mocked.

What is left below needs a person, a network, or the shell.

## 1. Typing `!s` sends nothing

1. Open a network monitor that shows per-process connections — Resource Monitor's
   Network tab, filtered to `takyon.exe`, is enough.
2. Press the hotkey. Type `!s ferrari in f1` slowly, letter by letter. **Do not
   press Enter.**
3. **No connection appears.** Not one, for any letter. This is ADR-0002 and the
   whole reason the Bang exists.
4. Type a Bangless query — `chrome`, `2+2`, a filename — and watch again. Still
   nothing.

## 2. The row says what will happen before it happens

1. Type `!s` alone. One row: `Brave Search · your question leaves this machine`.
2. The window is one row tall, not empty-height, and not a list.
3. Add a question. The row becomes `Search the web with Brave Search — press
   Enter`, and the footer offers **Search**.
4. Both rows are warm, not the ordinary foreground colour. That is the outbound
   state (`docs/brand.md`), and it is the only warm thing in the Palette.

## 3. An answer arrives, with sources, streaming

1. Ask something current: `!s who won the last f1 race`. Press Enter.
2. The window grows to the full surface **once**, not per token.
3. The header reads `Left this machine · Brave Search`, warm, with a dot.
4. The status on the right moves through *Searching the web…*, *Reading
   sources…*, then names the Agent writing the answer.
5. **The sources appear before the answer finishes** and stay on screen while it
   is written.
6. The answer cites `[1]`, `[2]`. Every number has a row in the list beneath it.
7. Text appears progressively. **Watch the first thing that appears**: a `{` or a
   raw JSON fragment means a line reached the surface unparsed.

## 4. The sources are real and reachable

1. With an answer on screen, press Enter or click on source `[1]`.
2. It opens in the default browser, at that URL, and the page exists.
3. Read the answer against the page. It should be supported by it — a claim that
   is nowhere on any listed source is the failure this phase can actually have.
4. Go back to the Palette. The conversation is still there.

## 5. Escape goes back, and stops what it started

1. Ask something. While it is still answering, press Escape.
2. The Palette goes back to the search line. It does **not** dismiss.
3. Press Escape again. The Palette dismisses.
4. Open Task Manager. No `claude`, `codex` or `opencode` process is left running.

## 6. Enter opens the browser when there is no answer to wait for

1. Type `!s` and a question, then press Enter **from the source list** — or, with
   no key stored, press Enter on the row.
2. Confirm: the default browser opens, on **its own** default search engine, with
   the query intact. Not Brave's page unless Brave is what the browser uses.
3. Repeat with a query containing `&` and a non-ASCII character (`café & co`).
   The query arrives whole rather than truncated at the `&`.

## 7. No key is a state, not a failure

1. Settings → Web search → **Remove**. Confirm the row now offers no hint.
2. Type `!s something`. The row reads `No Brave Search key. Add one in Settings →
   Web search.`, in amber, and Enter does nothing.
3. Paste the key back. Type `!s` again — the row is normal immediately, with no
   restart.

## 8. The key is not readable from anywhere but DPAPI

1. Settings → Web search. The field is a password field: the key is dots while
   typing and the box is empty after saving.
2. Only `…` plus four characters is shown back.
3. Open `%LOCALAPPDATA%\v3sper\launcher\creds\brave.key.dpapi` in a text editor.
   **The key is not in it.**
4. Optional, if a second Windows account is available: copy that file to the other
   account's directory and confirm `!s` there reports no key rather than working.

## 9. The network failing is visible, not a hang

1. Start a search, then disconnect the network before the answer arrives.
2. Within a few seconds a sentence appears saying what failed. No spinner that
   never ends, and no empty answer presented as complete.
3. Reconnect. Ask again. It works with no restart.

## 10. A wrong key says so

1. Settings → Web search. Paste `not-a-real-key`. Save.
2. `!s anything`, Enter. The answer surface says
   `Brave Search refused the key. Check it in Settings → Web search.`
3. That is a different sentence from step 7's. Both name the page that fixes them.
